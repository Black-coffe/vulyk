# Anomaly telemetry (plan)

**Tier:** 3 · **Spec slug:** `anomaly-telemetry` · **Brief:** [brief.md](brief.md)
**Governed by:** ADR-005 (install.sh OWNED set, marked blocks, `shippable()`), ADR-007 (model ladder), `.claude/commands/vulyk-ship.md:11` ("print the command, then stop; never wait" - no agent sends or pushes), `docs/token-economy.md` (hooks fail-open and quiet), `scripts/lib.sh` `is_paperwork_path()` anchoring (memory/map/scripts.md Gotchas).
**Depends on:** v0.13.3 (`7fdb6f1`, installer copies bytes from a source checkout); recon `recon/hooks-and-stats.md`, `recon/weekly-and-publish.md`, and the scout answers of 2026-09-14 folded into A7, A10-A13 below.

## Goal
Every hive running VULYK keeps a committed, append-only anomaly log (`memory/stats/anomalies.jsonl`) fed by five detectors over records that already exist plus one new fail-open hook. One shell script, `scripts/telemetry.sh`, owns all of it: recording, scanning, bundling a week into an anonymized file of codes and numbers only, validating that file, reading consent, and printing (never running) the command that carries the bundle into the VULYK repository - a local commit when the repo is on this machine, a `gh pr create` recipe otherwise. `/vulyk-evolve` gains the weekly step; the constitution gains a `Telemetry` Profile row that is `off` by default. `install.sh` - fresh install and `--upgrade` alike - explains telemetry in the terminal and asks one yes/no question that sets the row, silently defaulting to `off` when no one can answer; `/vulyk-bootstrap` shows the value. The public repo documents what is collected, what never is, how to send, and that the inbox is distilled and cleared weekly. A CI job validates incoming bundles against the schema.

## Assumptions
- **A1 - local VULYK repo detection.** `telemetry.sh publish` treats a checkout as "the VULYK repo on this machine" in this order: `VULYK_LOCAL` env (explicit path, must be a git worktree containing `telemetry/inbox/`); else the hive itself when its `origin` URL contains the origin slug (`VULYK_REPO` env, else `.claude/vulyk-origin`, else `Black-coffe/vulyk`). `~/.vulyk/src` is deliberately NOT a copy target: it is `vulyk-update.sh`'s pull-only release cache, usually detached at a tag, so a commit there goes nowhere. If neither matches, the PR recipe is printed.
- **A2 - thresholds are v1 calibration**, one env var each, defaults baked into `telemetry.sh` and written into every row so `/vulyk-evolve` can recalibrate from data: `VULYK_ANOMALY_CONTEXT_PCT=70` (percent of the resolved window; `VULYK_ANOMALY_CONTEXT_TOKENS=140000` absolute when the window is unknown), `VULYK_ANOMALY_AGENT_PREFIX_TOKENS=50000` (first-turn `input + cache_creation` of a subagent = what the dispatch handed it), `VULYK_ANOMALY_COUNCIL_ROUNDS=3` (max round per spec at or above this), `VULYK_ANOMALY_STAGE_HOURS=24` (gap between consecutive `journal.md` lines). Workers legitimately carry large prefixes; the `agent` token (A12) is what makes the row readable.
- **A3 - version source.** Bundle rows read `.claude/vulyk-version` (written by `install.sh`), falling back to `0.0.0`. In VULYK's own tree that file may not exist; `0.0.0` is acceptable for dogfooding rows.
- **A4 - hive hash input** is `git rev-parse --show-toplevel` as printed (on Windows Git Bash `/e/Projects/hive`). It only needs to be stable per machine, not portable.
- **A5 - `.vulyk/` is already gitignored** (court and report dirs live there); the weekly bundle is written to `.vulyk/telemetry/<week>-<hive>.jsonl` and needs no new ignore entry.
- **A6 - Profile-block exception.** `install.sh --upgrade` today never touches a filled marked Profile block (ci.yml:313). This plan carves exactly one exception: the `| Telemetry |` row - appended when missing, its value replaced when the installer's question was answered. A hand-written Profile without markers is warned, never rewritten (ADR-005 D4.9 stays). Story 10 amends ADR-005 to record it (round-1 review finding 11).
- **A7 - python entry point (resolved by scout).** `handoff.py` `main()` (line 875) dispatches `sys.argv[1]` against `HOOK_MODES` (line 872) in an if/elif chain, and `handoff.sh:10` forwards argv verbatim. `measure` joins that chain as a read-only mode on `handoff.py`; no sibling file.
- **A8 - driver refusal/relaunch** are event-recorded at the two command surfaces that know about them (`/vulyk-build` refusing the fallback, `/vulyk-resume` relaunching), not mined from transcripts. `vulyk-cycle.js` is not touched.
- **A9 - `stage_long` covers closed stages only** (consecutive journal lines). The still-open last stage is not measured in v1 - it would re-fire on every scan until the stage closes.
- **A10 - installer question rule (ask 6; terminal access resolved by scout).** Precedence, first match wins: (1) `--check` never asks and never writes the row; (2) `--telemetry on|off` flag, else `VULYK_TELEMETRY=on|off` env, sets the row without asking; (3) `--telemetry ask` / `VULYK_TELEMETRY=ask` asks even when the row already holds an explicit value; (4) on upgrade, a row already `on` or `off` is left as is, no question; (5) the row is missing (fresh install, or an old hive): when a terminal is reachable the explanation and one `Enable telemetry? [y/N]` question are printed, empty/EOF/anything but `y`/`yes` = `off`; when no terminal is reachable (CI, pipes, non-interactive `vulyk-update.sh`) no prompt, row = `off`. **Terminal access:** `install.sh` never reads stdin today - its only `read` calls are pipeline loops over `find`/`ls` output (lines 70, 256, 503, 520) - so the prompt reads from `/dev/tty`, guarded by `[ -t 0 ] || [ -r /dev/tty ]`, never from a stdin those pipelines consume. `vulyk-update.sh:76` runs `install.sh --upgrade` as a plain foreground call with inherited stdin, so it needs no stdin plumbing - only the `--telemetry` flag / env passed through. Bootstrap shows the value and how to change it (`install.sh --telemetry ask`), asking nothing.
- **A11 - `telemetry/` never ships to hives (resolved by scout).** `copy_tree` (install.sh:491) runs only over `.claude memory bootstrap templates scripts docs/wiki docs/specs docs/adr`; a top-level `telemetry/` is never copied. That is the desired behaviour - the inbox lives in the VULYK repo only - so story 05 adds no exclusion for it. `memory/stats/anomalies.jsonl` IS under a copied tree and needs the runtime exclusion in `shippable()`.
- **A12 - agent token in rows (resolved by scout; source of the set superseded by A20).** A subagent's `.meta.json` carries `agentType` and `name` (e.g. `worker-01-core`), plus `model`, `taskKind`, `spawnDepth`, `teamName`, `description`, `color`, `planModeRequired`, `permissionMode`. Rows for `agent_prefix_high` / `agent_empty` carry an `agent` token = `agentType` when it is one of the framework's agent names, else `other`; every other code carries `""`. A free-form `name` never enters a row. "The framework's agent names" was implemented as the basenames of the hive's own `.claude/agents/*.md` - which includes owner-added agents (round-5 opus seat); A20 fixes the list in the script.
- **A13 - hook wiring on upgrade (resolved by scout).** `install.sh` `wire_session_hook` (:279-356) knows only the `SessionStart` group; nothing wires Stop or SessionEnd into an existing hive's `settings.json`. Story 05 generalises it (`wire_hook <event> <script>`, idempotent) and wires `anomaly-scan.sh` on Stop and SessionEnd; story 02 edits VULYK's own `settings.json` only.
- **A14 - PR recipe shape (round-1 fix, needs owner nod).** The cross-machine path assumes the sender has no push right on the public repo, so the recipe starts with `gh repo fork <slug> --clone` into a fixed relative directory and opens the PR from the fork with `gh pr create --repo <slug> --head <branch>`. Rejected: `git clone` of the upstream + push - fails for everyone but maintainers. The worker confirms the `gh` flags with `gh repo fork --help` locally; if `--clone` cannot take a directory, a `git clone` of the fork URL follows it.
- **A15 - default week (round-1 fix, needs owner nod).** `bundle`/`publish` without `--week` process the previous ISO week and the current one, one file and one inbox path each, skipping a week with no rows. Rationale: `/vulyk-evolve` counts a rolling 7 days, so a Monday run bundling only the current week silently dropped six days (opus seat, UNASKED 1). Rejected: a "last published" marker file - a ledger with no precedent on the stats shelf; a re-sent week lands on the same `<week>/<hive>.jsonl` path, so idempotence comes from the layout. `bundle --out` without `--week` writes both weeks into the one file (round-2 finding 9): documented, not changed - `publish` writes per-week files itself and `--out` is a hand tool where `--week` selects one.
- **A16 - inbox distil-and-clear is a staged changeset, not a hand step (round-2 fix, needs owner nod).** The public docs promise `/vulyk-evolve` distils and clears `telemetry/inbox/` weekly; nothing implemented it (opus seat, round 2; review finding 4). Story 07 implements the promise as written rather than rewording it: a `telemetry.sh inbox [--clear]` verb distils every inbox bundle into per-week, per-code counts and `--clear` stages the emptied week directories with `git rm`; evolve runs it only where `telemetry/inbox/` exists (the VULYK repo, never a hive - A11) and the counts plus the staged deletions ride in evolve's normal reviewable changeset with its CHANGELOG entry. The script still never commits or pushes. Story 07 also folds two review conditions that sit on the same lines it must edit (finding 2, the evolve count's leading-quote bug; finding 3, `docs/telemetry.md` naming env vars the script does not read) - the round-2 reviewer named leaving finding 3 unassigned in a story that owned the file as a plan defect. Strip those two bullets if the owner wants a pure one-ask story.
- **A17 - bounded scan and finished-only `agent_empty` (round-3 fix, needs owner nod).** The Stop-hook scan is bounded by scope, not by a ledger: `scan` reads subagents only under the passed transcript's own session directory (`<dirname>/<sid>/subagents/**`, recon §6), skips a subagent file whose `agent:<basename>` ref is already in the log before starting python, and runs each stats-file detector as one `jq`/`awk` pass (round-1 measured 31 s of per-row spawns with no transcript at all). `agent_empty` is recorded only when the hook fires on `SessionEnd`: the hook reads `hook_event_name` from its stdin payload and passes `--final`; on `Stop` the detector skips that code (a worker mid-turn is the normal state, review finding 6). `scope_breach` dedupes per story (`ref` = `scope:<story>`), because `scope.jsonl` holds one row per scope-check run and the hook-written log itself inflated `out_of_scope` on stories 05 and 06 (finding 11) - story 09 also stops `scope-check` counting the two hook-written stats files. Rejected: a per-machine "last scanned" marker (a new gitignored ledger with no precedent, and it does not fix the wrong path) and an mtime-age guard for `agent_empty` (a worker waiting on a long tool looks idle; the event name is exact). Rejected for finding 7: `ship-check` ignoring every paperwork path (hides a worker's plan.md edit) - only `memory/stats/*` paths that pass `is_paperwork_path` are passed through, and every `cycle.sh --commit` verb stages the log so it reaches git through the one writer ADR-001 allows. **Superseded in part by A18 (round-3 review Critical 1):** the log-ref check alone never bounds an under-threshold subagent; the "no ledger" rejection is revisited below.
- **A18 - per-session seen-list, not a log tombstone (round-4 fix, owner reopen after round 3).** A subagent is measured once per lifetime: `detect_agents` keeps `.vulyk/telemetry/seen/<sid>` (one file per session, gitignored via `.vulyk/` - A5; `.vulyk/telemetry/` already holds the bundles), one line per subagent file `<basename>\t<bytes>\t<measure json>`, and skips python for any file whose byte size is unchanged, feeding the cached JSON to the same detectors (so `--final` evaluates `agent_empty` from the cache too). Byte size is exact and content-derived, not an age guard. Why not a "measured, no anomaly" row in the log (the review's other option): the log is committed and shared across worktrees and machines, while the subagent transcripts it would describe exist on one machine only; ~70 non-anomaly rows per session would dwarf the anomalies, need a new enum code, a `check` exception and a `bundle` filter, and skew `/vulyk-evolve`'s counts. A17's objection to a ledger ("no precedent, does not fix the path") no longer holds: the path is fixed by story 08 and `.vulyk/telemetry/` is the precedent. **Also decided:** `memory/stats/skills.json` is NOT cycle-owned - only `memory/stats/anomalies.jsonl` is exempt from `scope-check` and passed through `ship-check` stage 03 (owner: "skills.json back under the scope gate"); its ship-gate consequence is in `## Descoped`.
- **A19 - the bundle never comes from a whitespace-IFS split of the local row (round-5 fix, ask 3; recorded as built after the round-5 review's Major 1).** `bundle_emit` read each local row through `while IFS=$'\t' read -r ...`; tab is IFS whitespace, so adjacent tabs collapsed and an empty `model` shifted `agent` out of its slot (round-4 opus seat, ASK 3). `detect_agents` never sets `--model`, so every real `agent_prefix_high` / `agent_empty` row bundled as `"agent":""`. Story 13 was allowed either a one-`jq`-pass map or an uncollapsible separator and **built the separator**: one `jq` pass per log file emits the row's fields US-separated (0x1f, stripped from every value first), and the shell loop reads them with `IFS=$(printf '\037')` - not IFS whitespace, so an empty field keeps its slot - then runs the set checks, `week_of` and `printf` as before. The jq-map variant (week via `strftime("%G-W%V")`, which the reviewer found working on this hive's jq 1.8.2) is not built; it would also remove the per-row `date` spawn that makes `bundle` over the 156-row log take ~15 s (round-5 review Minor 4) - a next spec's economy, not a repair. An empty `model` stays legal and empty; schema, key order, enum, token set and `check` are unchanged.
- **A20 - the agent token set is a fixed list in the script, never read from disk (round-6 fix, ask 3; needs owner nod).** Round-5 opus seat: `telemetry.sh agents` resolved the set from the hive's own `.claude/agents/*.md`, and ADR-005:57-58 names that directory as exactly where owners add their own agents - so an owner-chosen filename (`worker-frontend`, `worker-acme-billing`) passed hive-side `check` and left the machine in the bundle, while repo-side `check` rejected the same file (CI job fails, `telemetry.sh inbox` aborts the whole week's distil on one such bundle). Story 14 bakes the framework's 13 agent basenames into `telemetry.sh` beside the enum; `record` and `bundle` both map anything outside the list to `other` (the second mapping cleans rows a hive already logged with a custom name), and `check` rejects anything outside on both sides. A suite case run from the VULYK repo asserts the baked list equals the repo's `.claude/agents/*.md` basenames, so adding a framework agent is a list edit that a red case demands. A hive older than the repo reports a newer agent as `other` - correct for that version. Rejected: keeping runtime resolution and filtering at `bundle` against the repo's list - a hive has no copy of it. Rejected: hashing the custom name - still a per-owner value in the bundle, and unreadable by `/vulyk-evolve`.

## Contracts

### Anomaly code enum (v1, fixed - `telemetry.sh enum` prints it one per line)
| code | detector | value | threshold |
|---|---|---|---|
| `context_high` | main-thread context size (`context_tokens()`) above threshold | tokens | tokens |
| `agent_prefix_high` | a subagent's first-turn `input + cache_creation_input_tokens` above threshold | tokens | tokens |
| `agent_empty` | a subagent transcript whose last assistant entry has no text block (cap death / empty return); recorded only by `scan --final` (SessionEnd) - A17 | assistant entries | 0 |
| `council_rounds_high` | max `round` per spec in `council.jsonl` at or above threshold | rounds | rounds |
| `stage_long` | gap between two consecutive `journal.md` lines above threshold | hours (integer) | hours |
| `driver_refused` | `/vulyk-build` refused (no `Workflow`, no `--fallback`; by-name call threw) | 1 | 0 |
| `driver_relaunched` | `/vulyk-resume` relaunched the driver fresh | 1 | 0 |
| `scope_breach` | a `scope.jsonl` row with non-empty `out_of_scope`; one row per story (A17) | out-of-scope path count | 0 |

### Agent token set (A12, source fixed by A20 / story 14) - `telemetry.sh agents` prints it
A fixed list baked into `scripts/telemetry.sh` beside the enum, identical on every machine and never read from disk: `council-haiku council-opus council-sonnet cycle-clerk drone-coverage drone-docs drone-scout lead-architect lead-review librarian queen-planner worker-code worker-test`, plus `other`, plus the empty string for rows that are not about an agent. `record --agent <x>` and `bundle` both map any `<x>` outside the list to `other`; `check` rejects any `agent` outside it, in a hive and in the VULYK repo alike. The list is kept equal to the basenames of the VULYK repo's `.claude/agents/*.md` by a suite case that runs in the repo; a hive's own `.claude/agents/` (where owners add agents, ADR-005) is never consulted. **Before story 14** the set was resolved at runtime from the hive's `.claude/agents/` - the round-5 defect.

### Local row - `memory/stats/anomalies.jsonl`, one JSON object per line, exactly these 12 keys, this order (`jq -c`)
`{"v":1,"ts":"<UTC ISO-8601>","code":"<enum>","value":<number>,"threshold":<number>,"vulyk":"<semver>","tier":<0-4>,"model":"<fable|opus|sonnet|haiku|"">","agent":"<agent token|other|"">","spec":"<slug|"">","story":"<slug-NN|"">","ref":"<opaque dedupe id|"">"}`
No `note`, no free text. `ref` is the idempotency key: `record` appends nothing when a row with the same `code` and a non-empty equal `ref` already exists. Refs: `session:<transcript basename>`, `agent:<jsonl basename>`, `council:<spec>`, `stage:<spec>:<journal line no>`, `scope:<story>` (story 08; was `scope:<ts>:<story>`). `spec` in `council:`/`stage:` refs is used as a path segment only when it matches `^[A-Za-z0-9._-]+$` (story 08). **The log holds anomalies only (A18): no "measured, no anomaly" rows, no new code for them.**

### Bundle row - `telemetry/inbox/<ISO week>/<hive>.jsonl`, exactly these 10 keys, this order
`{"v":1,"code":"<enum>","value":<number>,"threshold":<number>,"vulyk":"<semver>","tier":<0-4>,"model":"<fable|opus|sonnet|haiku|"">","agent":"<agent token|other|"">","week":"<YYYY-Www>","hive":"<12 hex>"}`
`week` = ISO week of `ts` (`date -u +%G-W%V`); `hive` = first 12 hex of sha256 of the repo toplevel path. `ts`, `spec`, `story`, `ref` are dropped. **Positional fidelity (story 13, A19):** every bundle key is taken from the local key of the same name; any subset of the string fields (`model`, `agent`, `vulyk`) may be empty and every other field still lands in its own key - the bundle is never produced by a whitespace-IFS split of the local row. **Agent (story 14, A20):** a local `agent` outside the fixed token set is emitted as `other`. `check` rejects: a non-object line, a key set other than these 10, a `code` outside the enum, non-numeric `value`/`threshold`, `tier` outside 0-4, `model` outside the set, `agent` outside the fixed agent token set, `week` not `^\d{4}-W\d{2}$`, `hive` not `^[0-9a-f]{12}$`, `vulyk` not `^\d+\.\d+\.\d+$` (anchored both ends, story 08), and any string value containing `/`, `\`, `@` or whitespace.

### Seen-list - `.vulyk/telemetry/seen/<sid>` (story 11, A18)
Per-machine, per-session, gitignored (A5); `<sid>` = the main transcript's basename without `.jsonl`. TSV, one line per subagent file measured: `<basename of agent-*.jsonl>\t<byte size when measured>\t<measure JSON as printed>`. `detect_agents` loads it once per scan; a subagent whose basename is present with its current byte size is not passed to `measure` and its cached JSON drives `agent_prefix_high` and (under `--final`) `agent_empty` exactly as a fresh measure would; otherwise the file is measured and its line written or replaced. `scan` with no `--transcript` reads and writes no seen-list. Nothing under `.vulyk/` is ever staged. Steady state on a session whose subagents are all finished: at most one python start per scan (the main transcript's own measure), on `Stop` and `SessionEnd` alike.

### `scripts/telemetry.sh` verbs (bash, `set -u`, sources `lib.sh`; repo root = `VULYK_HIVE` env else `git rev-parse --show-toplevel`)
- `enum` - prints the codes. `agents` - prints the fixed agent token set (A20). `consent` - prints `on` or `off` from the root `CLAUDE.md` Profile row `| Telemetry | <on|off>... |` (backticks tolerated, first token wins, missing row = `off`).
- `record <code> <value> <threshold> [--spec s] [--story id] [--ref r] [--model alias] [--tier n] [--agent token]` - appends a local row (`mkdir -p memory/stats`), dedupes on (code, ref), maps an `--agent` outside the fixed set to `other`, unknown code = exit 1 on stderr, otherwise exit 0 and silent.
- `scan [--transcript <path>] [--final]` - runs every detector, calls `record`; exit 0 always, silent; `VULYK_TELEMETRY_SCAN=0` makes it a no-op. **Subagents (story 08):** read only under `$(dirname <path>)/$(basename <path> .jsonl)/subagents/` recursively (`agent-*.jsonl`, workflow subdirs included); with no `--transcript`, no subagent file is read. A file whose `agent:<basename>` ref is already recorded under both agent codes is skipped before `measure` runs. **Bound (story 11, A18):** a file present in the session's seen-list with an unchanged byte size is never passed to `measure`; the cached JSON is used instead. `agent_empty` is evaluated only with `--final`; the stats-file detectors make one `jq`/`awk` pass per file.
- `bundle [--week YYYY-Www] [--out <file>]` - bundle rows of that week to stdout or `<file>`; **default (A15, story 06): the previous and the current ISO week**, each week emitted separately on stdout; with `--out` and no `--week` both weeks land in the one file (A15, documented by story 10); empty output when no rows; exit 0. **Emitter as built (story 13, A19):** one `jq` pass per log file prints each local row's fields US-separated (0x1f); a shell loop with `IFS=$(printf '\037')` applies the set checks, `week_of` and the `agent` mapping (A20) and prints the bundle object; `publish` uses the same emitter, so `publish --dry-run` and `bundle --out` on one log print identical rows. Cost on the record: one `date` spawn per local row per week (~15 s over 156 rows on the maintainer's hive; round-5 review Minor 4).
- `check <file>...` - exit 0 when every line of every file passes; exit 1 with `<file>:<line>: <reason>` per failure on stderr; the prefix survives `#`, `&` and spaces in `<file>` (story 06).
- `publish [--week YYYY-Www] [--dry-run]` - consent `off`: prints `telemetry: off (Profile row Telemetry) - nothing to send`, exit 0. Consent `on`: for each week in scope (A15) writes the bundle to `.vulyk/telemetry/<week>-<hive>.jsonl`, runs `check` on it, then (A1) copies it to `<repo>/telemetry/inbox/<week>/<hive>.jsonl` and prints the commit command, or prints the PR recipe. **PR recipe (A14, story 06, reshaped by story 08), eleven lines for one week in one fenced block:** `gh repo fork <slug> --clone -- <dir>` · `cd <dir>` · `base="$(git rev-parse --abbrev-ref HEAD)"` · `git switch "$base"` · `git switch -c telemetry/<week>-<hive>` · `mkdir -p telemetry/inbox/<week>` · `cp '<bundle>' telemetry/inbox/<week>/<hive>.jsonl` · `git add telemetry/inbox/<week>/<hive>.jsonl` · `git commit -m "telemetry(<week>): <hive>"` · `git push -u origin telemetry/<week>-<hive>` · `gh pr create --repo <slug> --head telemetry/<week>-<hive> --title "telemetry(<week>): <hive>" --body "<one sentence, no paths>"`. **Two weeks (story 08):** fork, `cd` and the `base=` line are printed once; each week's block begins with `git switch "$base"` before its `git switch -c`, so each PR holds exactly one week (the fork's default branch is not knowable from a hive and the script may run nothing to find out). `docs/telemetry.md` shows this block and count verbatim (story 12). Every path in either recipe is quoted. The script never executes `git push`, `git commit`, `git clone`, `gh repo fork` or `gh pr create`. `--dry-run` prints without copying.
- `inbox [--clear]` (A16, story 07) - repo-side only. Root without `telemetry/inbox/`: prints `telemetry: no inbox at <root> - nothing to distil`, exit 0. Otherwise runs `check` over every `telemetry/inbox/*/*.jsonl` first; any failure = `check`'s stderr lines, exit 1, nothing deleted. On pass prints one TSV line per (week, code) present - `<week>\t<code>\t<rows>\t<hives>`, sorted by week then code, `hives` = distinct `hive` values - and nothing when the inbox holds no rows; exit 0. `--clear` then runs `git rm -r -q -- telemetry/inbox/<week>` for every week directory that held files: staged, never committed; `telemetry/inbox/README.md` survives; no rows = no-op. The never-executed list (`git commit`, `git push`, `git clone`, `gh repo fork`, `gh pr create`) is unchanged.

### `/vulyk-evolve` telemetry block, repo-side half (story 07)
When `telemetry/inbox/` exists at the root (the VULYK repo; a hive never has it - A11): run `telemetry.sh inbox`, show the table beside the local 7-day per-code counts as diagnosis input, and write the same table into the changeset's CHANGELOG entry; on the full path run `telemetry.sh inbox --clear` so the staged deletions travel in that same reviewable changeset; under `--dry-run` distil only. A non-zero `inbox` exit stops the block with the reason and clears nothing. The block never commits or pushes; the owner reviews and commits the changeset as with every evolve run.

### `handoff.py measure` (A7) - `python .claude/hooks/handoff.py measure <transcript.jsonl> [--sidechain]`
A new entry in `HOOK_MODES` and the `main()` chain; reads only. Prints one JSON object: `{"tokens":<newest context size>,"model":"<model id>","first_prefix":<first assistant input+cache_creation>,"assistant_turns":<n>,"last_has_text":<bool>,"agent_type":"<agentType from the sibling .meta.json or "">"}`. `--sidechain` counts entries with `isSidechain: true` (subagent files carry it on every entry). Exit 0; on an unreadable file prints `{}` and exit 0. **Never reads stdin (story 08, finding 16):** dispatched before the hook-payload read, so a terminal call returns. `agent_type` is the raw `agentType`; the mapping to the fixed token set happens in `record` (A20).

### Hook - `.claude/hooks/anomaly-scan.sh`

### Installer prompt - `install.sh [--telemetry on|off|ask]`, env `VULYK_TELEMETRY=on|off|ask`
Rule A10. Terminal test: `[ -t 0 ] || [ -r /dev/tty ]`; the question is read with `read -r ... < /dev/tty` (fallback to stdin only when stdin itself is the terminal), never from a stdin a pipeline may be consuming. The explanation (4-6 lines, plain stdout) states: anomalies are logged locally in `memory/stats/anomalies.jsonl`; a weekly bundle holds only codes from a fixed list (the enum names) and numbers, never paths, slugs, story names, emails or free text; it goes into the VULYK repo by a command `/vulyk-evolve` prints and you run; the default is off; see `docs/telemetry.md`. Then exactly one question: `Enable telemetry? [y/N]`. `vulyk-update.sh` forwards `--telemetry`/`VULYK_TELEMETRY` unchanged and does nothing about stdin (it is already inherited). **Marker-less Profile (story 10, ADR-005 D4.9):** the row is not written and one stderr warning names the row and the value that was not written.

## Tradeoffs
- **Chosen:** one script with verbs + a step inside `/vulyk-evolve` + a committed log. The log follows the five existing stats files exactly (writer, whitelist, history in git), the weekly cadence is the cadence `/vulyk-evolve` already has, and the print-never-send rule is the ship rule reused. **Rejected:** a separate `/vulyk-telemetry` command - a second weekly ritual the owner would forget, and evolve already reads the same stats shelf for its diagnosis.
- **Rejected:** a gitignored per-machine log - needs new `shippable()` and `ensure_gitignore()` entries with no precedent, loses the anomaly history from the repo, and forces multi-worktree hives to merge logs by hand.
