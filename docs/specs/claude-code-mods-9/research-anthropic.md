## 1. Blast Radius (anthropics/claude-code-playground, `claude-code/mods/blast-radius`)

- **Repo facts:** Apache-2.0 (repo license; file header `// SPDX-License-Identifier: Apache-2.0`), author "Claude Code DevRel", v0.1.0. One commit touching it, 2026-10-01 ("Add three example mods: Blast Radius, Replay Theater, Token Weather"); repo pushed_at 2026-10-14. README: "Shared as-is ... Not an official Anthropic product; no support or maintenance is implied." Files: `hooks/blast-radius.mjs` (22.5 KB, no deps), `hooks/hooks.json` (`modules: ["./blast-radius.mjs"]`), plugin.json.
- **Mechanism:** one hook `on("tool.call", { tool: "Bash" }, ...)` + `on("ui.render", {component:"Pane"})` + `on("ui.render", {component:"AbovePrompt"})`. Not a settings hook, not a permission-prompt change (docs: a mod "can't change what a prompt shows you"; this mod draws its own pane). It parses `e.command`; if risky it holds the call, shows a Pane with buttons **Proceed (key 1) / Cancel (key 2)**; Cancel has focus, so Enter = refuse. Cancel/timeout/interrupt returns `{ deny: "Blast Radius held this command and did not run it: ${why}. It would have: ${summary}. Do not retry it unless the user asks you to." }` (blast-radius.mjs ~l.105): the model reads the refusal reason.
- **Surfaces:** `Pane` (needs terminal ~144+ columns), else `AbovePrompt` band (shared with any other band mod; if another mod owns the band the buttons may not show and the command is refused after 10 min).
- **Hold loop:** hook has a 10 s budget for own code, so it waits by `await $.process.run(["sleep", POLL_SECONDS], {timeoutMs:5000})` in a loop until `onPress` sets a decision (time inside `$` calls does not count). Timeout 10 min -> refuse. One hold at a time (queue).
- **"Dangerous" detection (text parse of the command line, split on `&&|\|\||;|\||\n`, tokenizer, strips env assignments, sudo/prefix words, leading `\`):**
  - `rm` / `*/rm` with recursive (`-r/-R/--recursive`) or force (`-f/--force`) -> lists files (find + `du -k`), count, size, first 10.
  - `git reset --hard` (git status --porcelain + diff --shortstat); `git clean` (runs `git clean -n` with same flags); `git push --force|-f|--force-with-lease|+ref` (commits on remote HEAD lacks, from last fetch); `git checkout|restore` containing `.` (except `--staged` only); follows `cd`, `pushd/popd`, `git -C`, subshell parens.
  - migrations: regex on joined words `alembic upgrade`, `db:migrate`, `prisma migrate`, `manage.py migrate`; any other `migrate` -> note "can't list pending". Runs the tool's own status command (loads project code) before the user decides.
  - Read-only set (`ls cat echo printf grep rg find less head tail cd git`) excluded from the bare-"migrate" rule.
- **Does NOT detect (README "Notes/limitations", verbatim list):** `$(...)`, aliases, `eval`, `bash -c "..."`, `xargs rm`, `find -delete`, scripts that call `rm`, wrappers `timeout 5 rm`, `doas rm`, `time -p rm`, `env -i rm`. Also visible in code: **`mv`, `>` overwrite/truncate, `cp` over a file, `git branch -D`, `git stash drop`, `git checkout <file>` (only `.` is matched), `rm` without -r/-f (e.g. `rm file`), PowerShell tool** (hook is bound to `tool: "Bash"` only); "It only watches the Bash tool. File edits and other tools aren't held." Only the first risky segment is measured; Proceed runs the whole line. False positives: commit message containing `; rm -rf`.
- **Bypass:** trivially by any wrapper above; also not a sandbox ("after you press Proceed, the command runs as written"). README itself: "a safety net, not a permission system. Use permission rules for a hard block." Docs: a mod's approval can't pass `ask` rules/PreToolUse hooks under managed settings/Team login (docs overview, "Decide whether to trust a mod"), but without those a mod can approve what an `ask` rule would prompt for. A mod is ordered with other hooks: PreToolUse settings hooks still apply independently.
- **Model/token cost:** none. README: "The mod itself doesn't call a model." Zero tokens; the deny text adds a small tool_result to the context.
- **Disk:** none persistent (state in module variables). Runs `bash`, `git`, `find`, `du`, `sleep` subprocesses.
- **Platform:** terminal only for the Pane/band (docs "Where mods run": hooks run in VS Code/Desktop/`-p`, drawing only in terminal/Desktop/VS Code panel >= 2.1.299; in `claude -p`/cloud there is no UI so a held call can only time out/deny after 10 min - inference from the docs table, not tested). Needs `bash`, `git`, `find`, `du` on PATH: **native Windows without Git Bash/WSL is a gap** (uses `["bash","-c",CD_SCRIPT]`, `sleep`, `du -k`); README only says "works on macOS and Linux" (du -k remark). Requires CC >= 2.1.287; built on 2.1.280. Fixes after review were tested against a stand-in, "haven't been re-run in a live session". Force-push and migrations "checked against the classifier only, not run".
- **Telegram claim check:** "before a dangerous action Claude stops, shows which files would disappear, waits for continue/cancel" ✅ for `rm -r/-f`, `git reset --hard`, `git clean`, `git checkout .`; ⚠️ "files" only for rm/reset/clean; push/migrate show commits/migrations; narrow command set; trivially evaded.

## 2. Replay Theater (`claude-code/mods/replay-theater`)

- **Repo facts:** Apache-2.0, v0.1.0, same single commit 2026-10-01, DevRel author, "Shared as-is ... no support". hooks/replay-theater.mjs 10 KB, no deps.
- **Mechanism:** `on("tool.call", ...)` records, never blocks (`EDIT_TOOLS = new Set(["Edit","Write","MultiEdit"])`, always `return next(e)`, recording errors swallowed); `turn.start` (clears pending unless `e.agentId`), `turn.complete` (moves pending -> replay, invalidates UI; skips subagent turns, but subagent edits made inside the main turn are included); `session.start` registers command `/replay`; `command.run` opens pane; `ui.render` on `AbovePrompt` (hint `▶ Replay: 5 edits (press r)  [ Replay ]`) and on `Pane` (id `replay-theater`, one step at a time, Prev/Next/Close, hotkeys n/p/c/Esc, numbered step strip). Fallback to band if no pane can be placed (README: untested).
- **What is stored:** only per-edit `{tool, file, diff}` where diff = LCS line diff of `old_string` vs `new_string` (Edit) or, for Write, the old file read from disk just before the write (`$.fs.read`) vs `e.content`; capped 12 lines/step, 1 line of context; files > 400 lines shown as all-removed/all-added. **Memory only; lost on restart/plugin reload; nothing on disk.** Replay stays until the next turn that has edits.
- **Token cost:** none ("The mod itself doesn't call a model").
- **Weaknesses:** records at call time, so a denied or failed edit still appears (README). **Only Edit/Write/MultiEdit**: edits made through `Bash` (sed, redirects, `mv`, `rm`), NotebookEdit, MCP tools, PowerShell are invisible. No line numbers; whole-file view not available; MultiEdit path untested (CC 2.1.280 has no MultiEdit); cannot undo/rewind - it is review only. Band is shared with other mods. Needs a UI (terminal/Desktop/VS Code panel).
- **Telegram claim check:** "after Claude finishes, a replay button walks through each edit step by step" ✅ (button in band + `/replay`, Prev/Next). "Works on plain text too ... if it edited your article you'll see ..." ⚠️: true only when the article was changed by Edit/Write tool calls (any text file, not just code; it is a line diff, so prose paragraphs show as whole changed lines, no word-level diff). Docs list it as "adds a `/replay` command that steps through the file edits Claude made in the last turn".

## 3. You Should Know (built-in `cc-plugin-you-should-know@builtin`)

Established earlier in `docs/specs/you-should-know/` (brief, 2026-10-04); re-verified now, one new fact below.
- CHANGELOG 2.1.287: "Added You should know, a built-in mod where a side agent watches your back and flags things you or Claude might miss. Turn it on with `/plugin enable cc-plugin-you-should-know@builtin` (for first-party sessions with telemetry on)". Later: 2.1.288ish "notes say we/the main agent/you"; "Fixed writing notes in English regardless of `language`"; newest (top of file) "toasts say 'try again' instead of 'press 2', which only works in the terminal".
- Docs (interactive-mode.md#you-should-know-suggestions): looks for "one thing you should know but might have missed, such as a tradeoff Claude chose without calling it out or a result that may be off"; shows a short note above the prompt (`✦ Heads up · ...  1: Learn more  2: Knew this already  0: Dismiss`). **"a side agent rereads the conversation from time to time as Claude works through a longer task. The side agent is a separate request to the same model and has no tools"** - cannot read files or change what Claude does. Off by default. The main agent does not see a note unless you send it with "Chat in main session".
- **Cost (docs "Cost of checks"):** background requests to the same model as the session, counted against plan limits/API cost; each check sends the whole conversation (read from the session prompt cache "on the same terms as Claude's own next request") plus "the instructions, several thousand tokens of them, and the side agent's reply are billed in full on every check". Debug: `CLAUDE_CODE_YOU_SHOULD_KNOW_DEBUG=1`.
- **Availability:** only direct API connection with claude.ai account or Console API key; not via LLM gateway, Claude apps gateway, `apiKeyHelper`, sessions not fetching feature flags (e.g. `DISABLE_TELEMETRY`), or the first session after install/upgrade. Where unlisted, enable answers `Plugin "..." is not installed in this project`. **Built-in mods are not stopped by `disableAllHooks`, `--bare`, `--safe-mode`** (docs overview).
- **Storage:** `~/.claude/plugins/store/cc-plugin-you-should-know*` (recent notes + topics marked known), deleted after `cleanupPeriodDays` unused.
- **Telegram claim check:** "a second agent reads the reply and surfaces the key point as a note" ⚠️: it is not "the key point of the reply" or a summary - it flags something you might have MISSED (a hidden tradeoff, a doubtful result), periodically during longer tasks, not per reply; no tools, same model, billed on every check. Command text ✅ exact.
- **Cache note (new):** docs prompt-caching.md "Enabling or disabling a plugin": plugin hooks/skills/agents never invalidate the cache, so enabling the mod mid-session does not invalidate it (a mod's content is appended). Side-agent requests share the prefix only when "same terms"; they fall in the "Everything else" TTL bucket? - docs do not state the TTL bucket for the You-should-know check; ❓.

## 5. Points for the VULYK comparison

- Blast Radius guards only `Bash` text by regex and never touches PowerShell; VULYK's host is Windows+PowerShell/Git Bash: a mod would miss the PowerShell tool and `Remove-Item -Recurse`. It is a human-in-the-loop UI, so it does not suit unattended `-p`/workflow agents (a held call there times out after 10 min and denies).
- Replay Theater = review of Edit/Write only, in RAM, no tokens; overlap with `git diff`/`/diff` (built-in `cc-plugin-diff`); of use only to a human at the terminal.
- You Should Know costs several thousand instruction tokens per check, same model; VULYK has already decided about it (docs/specs/you-should-know).
- All three are chrome/UX; none adds a durable artifact or a gate. Everything they read is the same hook event API (`tool.call`, `turn.*`, `ui.render`) documented at https://code.claude.com/docs/en/plugins/mods/reference.md (not read in full this session).
