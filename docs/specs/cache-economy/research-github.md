## Tricks worth testing in VULYK, cache-only

VULYK shape: a main session (Queen) dispatching many subagents and Workflow-driver runs, on Windows. Confirm the billing mode first (subscription within plan usage, usage credits, or API key): TTL defaults differ.

1. **Set `subagentPromptCacheTtl: "1h"` (settings) or `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h`; needs CC >= v2.1.242.** Official default for subagents, workflows, compaction and forks is 5 min even on a subscription. A/B one Tier 3 story and compare 5m vs 1h writes. Risk: 2x write price. Workers that wait on `council.test.sh` (about 10 min per run, past the 5 min TTL) lose their whole cache, so 1h probably wins for workers; it may lose for one-shot scouts and clerks.
2. **Per-agent TTL via subagent frontmatter `experimental: cacheTtl: 1h|5m` (CC >= v2.1.248).** Official precedence: FORCE_PROMPT_CACHING_5M, then the bucket env var, then the bucket setting, then frontmatter, then ENABLE_PROMPT_CACHING_1H, then default. So to keep per-agent control, do NOT set the global subagent setting or env var; use `ENABLE_PROMPT_CACHING_1H=1` (it sits below frontmatter) and pin `5m` on short read-only agents (drone-scout, cycle-clerk, council seats), keep 1h on worker-code, worker-test, lead-review.
3. **Measure first.** Run adampaulwalker `measure.py --days 7` (stdlib, local) and `uvx claude-cache-analyzer` over ~/.claude/projects to get reads and writes by TTL plus "idle rereads" for VULYK's own agents. The cnighswonger README has a jq one-liner (counts each requestId once). Add the cache_read/cache_creation/ephemeral_1h split to `/vulyk-status` spend.
4. **Stable prefix per agent type.** Keep every dispatch of the same agent byte-identical up to the task text: dynamic bits (date, branch, spec slug, story path, round number, stamp) go at the END of the brief. Audit `.claude/agents/*.md` and worker briefs for ids or timestamps near the top. Matches the #74318 "reorder dynamic content" fix (-7.6%, one author).
5. **Fan-out discipline.** Dispatch N same-type workers in one fan-out so the 5 s stagger lets siblings read the first one's cache. Same cwd is required for a shared prefix (official docs: different directories build different prefixes), so per-story and court worktrees cannot share; consider whether same-type seats can share a cwd. Do not set `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0`.
6. **No model or effort switch mid-session in the Queen.** Avoid `opusplan`, skill/command frontmatter `model:` in the main session (each is a full miss), and fast-mode toggles mid-session. Per-agent model routing is fine (separate cache per model anyway).
7. **Keep the Queen's tool set constant.** Do not connect/remove MCP servers, toggle plugins, or add whole-tool deny rules mid-session. Tool-search deferral protects most cases; a custom ANTHROPIC_BASE_URL gateway disables it. Skills, commands, agents and hooks from plugins append as messages (cache-safe) per the docs.
8. **Volatile data via `UserPromptSubmit` hook `additionalContext` (tail), not via CLAUDE.md or SKILL.md edits.** Do framework edits (CLAUDE.md, skills, agents) between sessions or right after `/clear`: a CLAUDE.md edit is invisible until restart, and on some versions editing an existing SKILL.md causes a delayed full rewrite (lllq-123 measurements, single author: UNCONFIRMED).
9. **Avoid long synchronous waits inside a worker's tool call**, or poll in background every few minutes (each poll is a read that refreshes the TTL; single Reddit source: UNCONFIRMED, test on one story). The Queen idling while a Workflow runs is fine on a subscription (main conversation gets 1h), but if usage credits are being drawn the main drops to 5m: set `promptCacheTtl: "1h"`.
10. **Compact/clear only at task boundaries.** `/compact` while warm reads the prefix; after the TTL it reprocesses everything. Prefer a fresh session plus handoff over resuming a session idle for over 1h (VULYK already starts a fresh session at Tier 2).
11. **Monitoring.** Enable statusline `prompt_cache` fields or `/usage` "Prompt cache (main)" line (CC >= v2.1.251; likely-cause text >= v2.1.260); the `claude-statusbar` skill already shows cache age. A hook that scans the last transcript rows and logs collapses (read=0 with huge create, or low read ratio) into `memory/stats/anomalies.jsonl` fits the existing telemetry. Watch the series, not the current value.
12. **Watch known collapse triggers (open issues).** Async/background subagent completion after the parent turn ended (#64901), Agent Teams delivery (#80604), task_reminder nudges (#78660). If the Queen dispatches with `run_in_background`, compare cache_creation spikes against synchronous dispatch.
13. **Do not use:** keepalive pings on a subscription (burns request quota, per the plugin's own README); semantic or response caches (GPTCache, ModelCache, semcache) for code-agent calls (wrong-answer risk; they need an API key and base-URL proxy); third-party cache proxies (cache-fix, CtxGuard) unless step 3 shows a real problem, because they sit in the auth path and rewrite requests. A gateway must forward `cache_control` and the `anthropic-beta` header unchanged per the official docs.
14. **Quick check:** `claude -p "hello" --output-format json` and read `usage.cache_creation.ephemeral_1h_input_tokens` vs `ephemeral_5m_input_tokens` to confirm which TTL the main conversation gets on this machine.
