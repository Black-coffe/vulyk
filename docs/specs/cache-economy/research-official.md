## Q1. Anthropic API prompt caching

Source A: https://platform.claude.com/docs/en/build-with-claude/prompt-caching (docs.claude.com redirects here), fetched 2026-09-30.

- Up to 4 explicit `cache_control` breakpoints per request. [A]
- AUTOMATIC caching exists: one top-level `cache_control: {"type":"ephemeral"}` in the request body; the system puts the breakpoint on the last cacheable block and moves it forward as the conversation grows. [A]
- Minimum cacheable length (below it: silently not cached, both cache fields = 0): 512 tok for Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5, Sonnet 5.5, Fable 5, Mythos 5; 1,024 for Opus 4.8, Sonnet 5, Sonnet 4.6/4.5/4, Opus 4.1/4; 2,048 for Opus 4.7, Mythos Preview, Haiku 3.5; 4,096 for Haiku 4.5, Opus 4.6, Opus 4.5. [A]
- TTL: default 5 min; `ttl:"1h"` optional. Lifetime is measured from the START of the request that wrote/read the entry, not from end of the response. [A]  (Every read refreshes the TTL - standard, but this page states start-of-request; see issue #92090 for long turns outliving the 5 min.)
- Pricing multipliers: 5m write 1.25x; 1h write 2x; READ 0.1x on most models BUT 0.05x on Opus 5.5 and 0.025x on Fable 5.1 / Mythos 5.1. [A]  -> the repo belief "read ~0.1x" is wrong for the newest models.
- Lookback: checks at most 20 blocks per breakpoint looking backward for entries earlier requests wrote; consecutive tool_use blocks (and consecutive tool_result blocks) count as one position. Writes only at the breakpoint. Put the breakpoint on the last block whose prefix is identical across requests. [A]
- Invalidation hierarchy tools -> system -> messages. Tool definition change kills everything; web-search/citations toggle and speed setting kill system+messages; tool_choice and images kill messages only; thinking params and effort setting always kill messages (and are model-specific for tools/system); dropped thinking blocks kill from that block on. Thinking blocks can't be marked directly but are cached as part of prior assistant turns. [A]
- Isolation: per WORKSPACE on Claude API, Claude Platform on AWS, Microsoft Foundry; per ORGANIZATION on Bedrock and Google Cloud. Exact 100% prefix match required. [A]
- Rate limits: cache reads are NOT deducted from ITPM. [A]
- Concurrency: an entry becomes available only after the first response BEGINS; parallel requests must wait for first response start to hit. [A]  (Critical for parallel subagent fan-out.)
- Usage fields: input_tokens (only tokens AFTER last breakpoint), cache_read_input_tokens, cache_creation_input_tokens, cache_creation.ephemeral_5m_input_tokens / ephemeral_1h_input_tokens; total input = sum of the three. [A]
- Pre-warming: `max_tokens: 0` request is a pre-warm; rejected with stream:true, extended thinking, structured outputs, tool_choice tool/any, and inside Message Batches. [A]

## Q2. Claude Code harness (docs fetched 2026-09-30 as raw .md from code.claude.com)

Sources: [P] https://code.claude.com/docs/en/prompt-caching ; [S] .../sub-agents ; [W] .../workflows ; [SET] .../settings-reference ; [ENV] .../env-vars ; [C] .../costs ; [ST] .../statusline ; [SDK] .../agent-sdk/modifying-system-prompts and .../agent-sdk/cost-tracking.
(NB: a WebFetch summary of .../model-config was hallucinated - ignored; raw curl of the .md files used instead.)

Layout / breakpoints
- Request order: system prompt (core instructions + tool definitions) -> project context (CLAUDE.md, auto memory, unscoped rules; loaded at session start, after /clear or /compact) -> conversation. Exact-prefix match; no per-file caching. [P]
- Mid-conversation system context (file-change notices etc.) is appended as a block and marked for caching on every provider unless CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1. Gateways that strip cache_control make the whole history uncached every turn; a gateway 400 on cache_control makes CC move the marker to the last conversation message. [P]
- Skills, commands, plan mode, output style, permission mode: delivered as appended messages -> cache-safe. Plugin skills/commands/agents/hooks never invalidate; plugin MCP servers follow MCP rules. [P]
- CLAUDE.md edits mid-session: no invalidation AND no effect (loaded once). Nested CLAUDE.md / paths: rules load lazily into conversation. [P]
- MCP: with tool-search deferral (default on supported models) the tool list from the first request is frozen for the conversation - connect/disconnect does not bust. Upfront-loaded tools: add/remove = invalidation. Whole-tool deny rule busts only when tool search is unavailable. [P]; [C] also says MCP tool definitions are deferred by default.
- Cache keys broken by: /model switch (incl. opusplan toggles, automatic fallback, skill/command frontmatter `model:`), effort change on most models, first fast-mode turn (header is part of key; later toggles keep cache), MCP/tool-set changes without tool search, image pruning batches, CC upgrade (new system prompt). [P]
- Effort: on Opus 5.5, Sonnet 5.5 and Fable 5.1 (API key or subscription; NOT Bedrock/Vertex/Claude-apps gateway, not with DISABLE_EXPERIMENTAL_BETAS, not HIPAA orgs) an effort change keeps the cache; before v2.1.260 Fable 5.1 also invalidated. [P]  -> repo belief says "except Opus 5.5 and Fable 5.1": INCOMPLETE, Sonnet 5.5 is also exempt (and only on those conditions).
- /rewind keeps the prefix and keeps the entry warm. /recap appends, keeps cache. [P]
- /compact: summarization request reuses same system prompt+tools+history, so a warm cache is read (cheap); after TTL expiry it reprocesses everything. Next turn rebuilds cache only for the short summary. Project context reloaded from disk (hits only if CLAUDE.md/memory unchanged). [P]
- Resume: whole conversation re-sent; reads whatever prefix is unchanged and within TTL; resumed convo keeps its ORIGINAL system prompt by default. [P]

TTL
- Two buckets. Main conversation (interactive, -p, SDK turns + inline helpers) vs "Everything else" (subagents, workflows, in-process teammates, forks, compaction, session titles). [P]
- Defaults: subscription within plan usage: main = 1h, everything else = 5m (except server-controlled helper requests = 1h). Usage credits / API key / cloud provider: 5m for both. Over-limit on subscription drops main to 5m. [P]
- Controls (CC >= 2.1.242): settings `promptCacheTtl` (main) and `subagentPromptCacheTtl` (everything else); env CLAUDE_CODE_PROMPT_CACHE_TTL / CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL; values only `5m`|`1h`. Precedence: FORCE_PROMPT_CACHING_5M=1 > bucket env var > bucket setting > subagent frontmatter `experimental: {cacheTtl: 5m|1h}` (CC>=2.1.248; `1h` ignored while on usage credits) > ENABLE_PROMPT_CACHING_1H=1 (both buckets) > bucket default. [P][SET][ENV][S]
- Correction: `subagentPromptCacheTtl` is a settings.json key (and env var), NOT subagent frontmatter; per-agent frontmatter is `experimental.cacheTtl`. [S][SET]
- "Enterprise 24h TTL" (from a bad WebFetch summary) is NOT in the raw docs -> UNCONFIRMED, ignore.
- Verify TTL actually used: `claude -p "hello" --output-format json`, read usage.cache_creation.ephemeral_1h_input_tokens. [P]
- Gateway: 1h needs anthropic-beta header forwarded; unavailable via Claude apps gateway; Bedrock support varies by model. [P]

Do subagents share cache?
- Non-fork subagent: own system prompt + tool set; first request does NOT read the parent's cache; warms its own. Parent unaffected. [P]; [S] table "Prompt cache: Separate cache".
- FORK: inherits parent's system prompt, tools and history exactly -> first request reads the parent's cache; "cheaper than spawning a fresh subagent for tasks that need the same context". Fork mode ON by default in interactive sessions since v2.1.232; OFF by default in -p and Agent SDK (CLAUDE_CODE_FORK_SUBAGENT=1). Fork = Agent with subagent_type "fork" or /subtask; same model as main; cannot spawn forks. [S][P]
- Non-fork siblings: Workflow docs: agents in one run with same model, effort, agent type, tools, output schema and cwd build the same tools+system prefix, so a later-starting sibling reads the first one's cache. [W]  => repo belief "each subagent writes its own fresh cache" is true only for the FIRST agent of a (type, model, effort, tools, cwd) combination. CLAUDE.md/git status arrive in messages (after the system prefix), so the shared prefix is system+tools only (the [P] layer table and [SDK] say CLAUDE.md is delivered in the conversation, not system prompt).
- Fan-out stagger: Claude Code holds all-but-first same-prefix workflow agents up to CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS (default 5000, CC>=2.1.229; 0 disables; off when DISABLE_PROMPT_CACHING) until the first agent's response begins. Matches the API rule "entry available only after first response begins". [W][ENV][API doc]
- Resumed subagent (SendMessage): first request CAN read the cache the original run warmed (within TTL). [P][S] (Several user reports say it misses - see Q4.)
- Subagent bundle: system prompt (agent body + env details; for custom agents replaces the default CC system prompt entirely), delegation message, CLAUDE.md hierarchy (unless omitClaudeMd: true -> only managed-policy files load; CC>=2.1.271), git status snapshot (Explore/Plan skip; cannot be skipped per agent; global off via includeGitInstructions:false / CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1), preloaded `skills:` content, sibling-roster system reminder (CC>=2.1.206; only if SendMessage in tools and another named agent exists; snapshot at start). [S]  Explore/Plan already omit CLAUDE.md+git status.
- Cache scope: effectively one machine + directory, because the system prompt embeds auto-memory paths and the conversation opens with cwd/platform/shell/OS. Parallel sessions in the same dir share; sequential sessions share only if the startup git-status snapshot matches. [P]
- Agent SDK: `systemPrompt:{type:"preset",preset:"claude_code",excludeDynamicSections:true}` (TS sdk >=0.2.98 / Py >=0.1.58) moves per-user dynamic context into the first user message so identical configs share a system-prompt cache across users/machines. Custom-prompt arrays with SYSTEM_PROMPT_DYNAMIC_BOUNDARY split static/dynamic blocks, each with a breakpoint (TS only; only on direct Claude API / Platform on AWS). ENABLE_PROMPT_CACHING_1H via options.env. [SDK]

Env vars touching caching ([ENV]/[P]): DISABLE_PROMPT_CACHING; DISABLE_PROMPT_CACHING_{HAIKU,SONNET,OPUS,FABLE} (apply to the model an alias resolves to; a pinned other model ID keeps caching; HAIKU covers main convo from 2.1.283); ENABLE_PROMPT_CACHING_1H; FORCE_PROMPT_CACHING_5M; CLAUDE_CODE_PROMPT_CACHE_TTL; CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL; CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS; CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS (kills tool search + effort exemption); CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS; CLAUDE_CODE_DISABLE_AUTO_MEMORY; CLAUDE_CODE_ATTRIBUTION_HEADER (docs: caching unaffected on direct connection); ENABLE_TOOL_SEARCH; CLAUDE_CODE_FORK_SUBAGENT; CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS (default 900000 = 15 min); MCP_DISCOVERY_CACHE*.
- Per-model `DISABLE_PROMPT_CACHING_CLAUDE_OPUS_5_5` / `ENABLE_PROMPT_CACHING_1H_<MODEL>` (seen only in a bad WebFetch summary) are NOT in raw docs -> UNCONFIRMED.

Observability
- /usage Session block `Prompt cache (main)`: requests, % input from cache, misses (>5% AND >=2,000 tokens of readable content re-processed), expected rebuilds, warm/cold + TTL (CC>=2.1.251; likely-cause >=2.1.260). MAIN CONVERSATION ONLY, subagents excluded. [C][ST]
- Statusline JSON `prompt_cache`: warm, ttl, expires_at, hit_ratio, misses, miss_causes, cache_write_tokens, recache_tokens_if_cold; `context_window.current_usage` has creation/read counts. Status line re-runs when expires_at passes. The "cache age" shown by claude-statusbar is derived from these. [ST]

## Q5. Per-agent subagent cache TTL (coordinator question)

YES, a per-agent key exists.
- Key: `experimental:` map in subagent frontmatter, sub-key `cacheTtl`, values `5m` | `1h` (anything else ignored). Must be nested, NOT top level:
  ```
  ---
  name: worker-test
  experimental:
    cacheTtl: 1h
  ---
  ```
  [S https://code.claude.com/docs/en/sub-agents "supported frontmatter fields", fetched 2026-09-30] + CHANGELOG 2.1.248: "Added `experimental.cacheTtl` ("5m" or "1h") to agent frontmatter: a per-agent prompt cache TTL used when no subagent TTL setting is configured" [https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md, fetched 2026-09-30].  Two sources: CONFIRMED.
- Conditions: CC >= 2.1.248 (installed 2.1.285 OK); read only from subagent files (not from --agents JSON? docs say "reads the field only from subagent files"); `1h` is ignored while a subscription is drawing on usage credits. [S]
- Precedence (top wins): FORCE_PROMPT_CACHING_5M=1 > CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL env > `subagentPromptCacheTtl` setting > agent frontmatter `experimental.cacheTtl` > ENABLE_PROMPT_CACHING_1H=1 > default (5m on every plan for non-main). [P https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself]
  => For per-agent control NOTHING global may be set: leave `subagentPromptCacheTtl`, CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL and (for the ones you want at 5m) ENABLE_PROMPT_CACHING_1H unset. Frontmatter `cacheTtl: 5m` would beat ENABLE_PROMPT_CACHING_1H, so it is also a per-agent pin to 5m.
- Global settings history: `promptCacheTtl` + `subagentPromptCacheTtl` added 2.1.243 (CHANGELOG; docs say "requires >= 2.1.242" - a one-version inconsistency between docs and changelog, cosmetic); ENABLE_PROMPT_CACHING_1H added 2.1.108 for API key/Bedrock/Vertex/Foundry (CHANGELOG), FORCE_PROMPT_CACHING_5M same release.
- NOT available: no TTL parameter in the Agent tool call (tools-reference "Agent tool behavior" lists none), none in the Workflow script API docs (grep of workflows.md: the only TTL mention is the global `subagentPromptCacheTtl`). Whether a workflow agent that runs a NAMED agent type honours that type's frontmatter `experimental.cacheTtl` is not stated -> UNCONFIRMED; test with `usage.cache_creation.ephemeral_1h_input_tokens` in a workflow agent's transcript (~/.claude/projects/<p>/<session>/subagents/agent-*.jsonl).
- Evidence supporting the coordinator's local finding (global 1h for subagents = net loss): user-measured #74318 (open, updated 2026-09-29, UR, ~1,800 subagents): blanket 1h for subagents = +8.6% subagent prompt cost because 98% of reuse happens inside ~34 s (median gap 7 s); the parent's cache dying while it is blocked on a child is the real problem (96% of parent "cache deaths" at median ~9 min idle). https://github.com/anthropics/claude-code/issues/74318. Math check with the official multipliers: a 1h write (2x) only pays if it prevents a re-write; break-even is about 1 avoided re-write (1.25x) per ~0.6 writes... i.e. use 1h only where P(gap > 5 min) per write is high.
- Evidence for where 1h DOES pay: #92090 (open, UR): Fable 5.1 background subagents whose single turn runs 5-10 min (thinking + tools) re-wrote 200-430K of context repeatedly on the 5m bucket (10 rewrites, 2.88M tokens in 40 min). Also #89621 (subagent 3.5 h, 65 rewrites >400K, 5m only) and #87215 (woken/parked subagents re-cache). For VULYK this maps to: agents with long single turns (worker-code/worker-test waiting on `tests/*.sh` ~10 min on Windows, council seats) => `experimental.cacheTtl: 1h` per agent; short-turn agents (scout, clerk, drone-*) stay at default 5m.
- Related official caveat: a 5m entry's lifetime is measured from the START of the request that wrote/read it (API doc), so a turn (response streaming + tool execution) longer than 5 min misses even with no idle gap. [API doc A]

## Q6. What sits in a subagent's prompt before the first message, and what breaks the shared prefix

Official (non-fork subagent) [S "What loads at startup", fetched 2026-09-30]: system prompt = agent's own markdown body + environment details appended by Claude Code (NOT the default CC system prompt; a custom agent's body replaces it entirely, as with --system-prompt); task message = the delegation prompt; CLAUDE.md files (user, project, local, rules, managed, AGENTS.md; skipped by Explore/Plan; `omitClaudeMd: true` keeps only managed policy files); git status snapshot (read when the subagent starts; Explore/Plan skip; "You can't change which subagents receive git status"); preloaded `skills:` full content; sibling-roster system reminder (only when SendMessage is among its tools and another named agent exists; snapshot at start).
Ordering is NOT documented by Anthropic. Best evidence = a captured outbound request body in issue #98513 (open, filed 2026-09-30, CLI 2.1.284 / SDK 0.3.284, n=31 per arm, UR but measured at the wire):
  1. `tools` (schemas) + `system` (system prompt, + append) -> breakpoint, cached across sessions.
  2. `messages[0]` (user): project memory (CLAUDE.md, .claude/rules) as a <system-reminder>, THEN the user prompt. For a subagent the user prompt = the delegation/task prompt. No breakpoint between memory and prompt, so memory is read back only when the prompt also matches.
  3. `messages[1]` (role "system", carries the only message-level cache_control): `# Environment` block, deferred-tool name list, MCP "still connecting" notice, agent-type listing, skill listing, date. It FOLLOWS the user prompt -> never shared across sessions/spawns with different prompts.
  Measured: default first turn cache_read=12,185 / cache_creation~=32.5K on Sonnet 5.5; moving memory into the system prompt (append + claudeMdExcludes) -> read 18,052 / write ~16.1K; the residual ~16K written per new session is the post-prompt system message, which no option moves in front of the prompt; `excludeDynamicSections:true` did not change its position. https://github.com/anthropics/claude-code/issues/98513
  => This matches the coordinator's data (same agent type, minutes apart: read ~5k = tools + agent body; write ~12k = CLAUDE.md + env/listings/date after the unique task prompt). WHAT BREAKS THE SHARED PREFIX: the unique task prompt sits in messages[0] right after CLAUDE.md, and the environment/listing block sits after it; only tools+system (before the first breakpoint) is a shared read. Matches the doc rule that the lookback only finds entries previously written AT a breakpoint and never finds stable content behind your breakpoint [A].
  Counter-evidence to keep honest: #74318 measured 85% shared-prefix hits for same-type siblings within 5 min (45% with no recent sibling) on a ~37k cold start where only ~950 tokens are the unique task; consistent with a shared head (tools+system) being large in his setup. Different setups => measure yours.
- Git status: location CONFLICTING. CHANGELOG 2.1.78 (line "Fixed CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS and includeGitInstructions setting not suppressing the git status section in the system prompt") and #87282 (compiled CLI v2.1.226: `--exclude-dynamic-system-prompt-sections` moves cwd/env/memory-paths/git-status out of the system prompt) say git status is part of the SYSTEM prompt -> it would break the shared tools+system prefix whenever the working tree/commits differ between spawns (and in an active build the tree changes constantly). The SDK doc says cwd/platform/shell/OS and CLAUDE.md are in the conversation, not the system prompt, and #98513 shows Environment after the prompt (2.1.284). Treat git-status position as UNCONFIRMED for 2.1.285; it is volatile either way, and after compaction it is refreshed (2.1.269).
- Can volatile parts be turned off for subagents?
  * Git status snapshot (+ built-in commit/PR instructions in the Bash tool description): settings `includeGitInstructions: false` or env CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1 (env wins). Global, all sessions and all subagents; NO per-agent switch; Explore/Plan already skip it. There is no CLAUDE_CODE_DISABLE_GIT_STATUS variable (grep of env-vars.md, settings-reference.md, CHANGELOG: none). [SET][ENV][S]  Tradeoff: also removes the commit/PR guidance text, so agents that commit (worker-code via cycle.sh?) lose it - put the needed git rules in the agent body instead.
  * CLAUDE.md: per-agent `omitClaudeMd: true` (2.1.271). Removes it from messages[0] (less tokens written per spawn; does not make the remainder shareable).
  * Auto memory: not loaded into non-fork subagents at all [S]; main-session: CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 (the auto-memory path is embedded in the main system prompt [P]; issue #96578 shows turn-by-turn rewrite cured by it, UR).
  * Date line: no switch; feature request #87487 (open) says the `Today's date is ...` block is injected unconditionally (v2.1.231) so the prefix changes at midnight. UNCONFIRMED by docs; by #98513 it lives in the post-prompt system message (2.1.284), so it only matters for what sits behind it.
  * Sibling-roster reminder: only appears if SendMessage is in the agent's tools; omit SendMessage from `tools:` of agents that don't need resume to keep it out. [S]
  * Skills/preloaded skills: content of `skills:` is part of the agent's initial context; a changed set = different prefix; keep identical per type. CC 2.1.265 fixed preloaded skills/SubagentStart hook context moving out of the prefix on later turns.
  * Bash tool description embeds a per-session console URL (#87137, open, CC ~2.1.234): tools array differs between sessions -> whole-prefix miss on resume and across sessions; within ONE session all subagents share the same URL so they can still share. UR, not confirmed by docs.
  * For the Agent SDK only: `excludeDynamicSections` (moves auto-memory path/cwd/env/git status from system prompt to first user message) and `--exclude-dynamic-system-prompt-sections` (CLI, -p only since 2.1.98; interactive ignores it per #87282). [SDK][CLI ref https://code.claude.com/docs/en/cli-reference]
- Practical structural lever (derived, evidence = API doc lookback rule + #98513 layout): content you want shared across spawns of a type must live in the agent's markdown BODY (system prompt, before the first breakpoint), not in CLAUDE.md (messages[0]) and not in the delegation prompt. Keep the body byte-identical across spawns (no dates, ids, paths, run numbers); put per-story text only in the delegation prompt. Minimum cacheable length for Sonnet 5.5 / Opus 5.5 is 512 tokens [API doc], tools+system of a custom agent is easily above that.

## Q3. Other cache layers

- File-read dedup: Read tool "deduplicates unchanged re-reads" (CHANGELOG 2.1.x line "Read tool now uses compact line-number format and deduplicates unchanged re-reads, reducing token usage"); stub text "File unchanged since last read"; /rewind used to leave stale tracking causing stubs after external edits (fixed, CHANGELOG ~2.1.2xx). Per agent context (each subagent has its own file-read state). Sources: CHANGELOG (2 hits), no docs page. Treat as CONFIRMED that it exists, exact scope per agent UNCONFIRMED.
- WebFetch: 15-minute per-URL response cache; `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` (CC>=2.1.233) [tools-reference https://code.claude.com/docs/en/tools-reference ; env-vars; CHANGELOG]. CONFIRMED (3 docs). Saves tool-result tokens only when the same URL is refetched; the cached page still re-enters context.
- Tool-result clearing / microcompact: Claude Code clears old tool results from context ("expected rebuild" in /usage; `Prompt cache (main)` counts them) [C, ST]. Issue #94177 (UR, 2026-09-14) measured 4 microcompact events = 3.0M tokens re-written, each clear dropping cache_read to the shared prefix; suggests pruning only when the cache is already cold. 68% of one user's cache writes came from 36 events (1h TTL expiry 19, microcompact 4, resume/model switch ~6). https://github.com/anthropics/claude-code/issues/94177
- Image/PDF pruning in batches changes earlier messages -> rebuild from earliest changed message [P]; issues #90716, #89418 (UR).
- MCP discovery cache (MCP_DISCOVERY_CACHE, TTL 900 s, max stale 4 h; off by default unless rolled out) [ENV]: a startup-time cache of remote MCP tool lists; affects startup and the `cached` status, not API cost directly.
- Plugin/marketplace cache (~/.claude/plugins, CLAUDE_CODE_PLUGIN_CACHE_DIR, PLUGIN_SEED_DIR) [ENV]: local file caches; no token-cost effect except that plugin skills/agents load as appended content (cache-safe) [P].
- Auto-mode permission classifier reuses the conversation's cached prefix (CHANGELOG 2.1.x "Reduced prompt-cache costs for auto-mode permission checks by reusing the cached conversation prefix"). Prompt suggestions likewise [C].
- Message Batches: 50% discount; stacks with prompt caching; cache hits are best-effort because batch requests run asynchronously/concurrently, typical hit rate 30%-98%; use identical cache_control blocks, steady stream, and preferably 1h TTL; `max_tokens:0` pre-warm unsupported in batches [https://platform.claude.com/docs/en/build-with-claude/batch-processing, fetched 2026-09-30; prompt-caching page]. Claude Code itself does not use Batches for subagents.
- Bedrock / Vertex: cache lives in the cloud provider's infra, org-level isolation only (not workspace) [API doc; P]; support, min prefix length and 1h TTL vary by model/region; CC honours ENABLE_PROMPT_CACHING_1H and the TTL vars there; token-count fields still reported so /usage works [P, https://code.claude.com/docs/en/amazon-bedrock]. Effort-change cache exemption and `excludeDynamicSections` blocks split do NOT apply on Bedrock/Vertex/gateways [P, SDK]. Mantle endpoint caches like the Claude API [P].
- Semantic caching: NOT a native Anthropic feature - the API cache is exact-prefix KV reuse only ("exact matching (100% identical prompt segments) required") [API doc]; semantic caches live in third-party gateways (LiteLLM etc.) and are not cited by Anthropic docs -> note only; UNCONFIRMED beyond "not in Anthropic docs".
- KV-cache concepts as they surface to users: prefix match, TTL refreshed on each read, cache write vs read billing, exact-match sensitivity, per-model/per-effort/per-speed keys, workspace isolation, concurrency (entry available only after the first response begins) [API doc, P].
- Cache diagnostics: beta `cache-diagnosis-2026-04-07` returns server-side `cache_miss_reason` (seen used in issue #91707, UR) - official docs page not checked -> UNCONFIRMED as a supported public feature.

## Q4. Known cache-busting bugs / gotchas (gh search, 11 queries: cache, prompt cache, cache miss, cache_read, cache ttl, 1h cache, subagent cache, cache invalidation, cache busting, prompt caching subagent, cache_creation; ~150 distinct issues; all below are open unless noted; UR = user report, not vendor-confirmed)

Directly relevant to a multi-agent framework:

## Levers VULYK could pull, cache-only

(No fewer agents / smaller prompts / cheaper models. "Evidence" = source ids above. All are to be measured with `usage.cache_creation.*` in ~/.claude/projects/<p>/<session>/subagents/agent-*.jsonl, deduped by message.id + requestId [#94177, #74318].)

1. Per-agent 1h TTL only for agents whose single turn or waiting gap exceeds 5 min: add `experimental: {cacheTtl: 1h}` to worker-code, worker-test (long tests.sh on Windows ~10 min), council-opus/lead-review if a round exceeds 5 min. Leave scout/clerk/drones at default 5m. Keep `subagentPromptCacheTtl`, CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL and ENABLE_PROMPT_CACHING_1H UNSET or the global value overrides/ignores frontmatter. Evidence: Q5; #92090 (turns >5 min rewrite full context), #74318 (blanket 1h = +8.6%). Break-even: 1h write 2x vs 5m 1.25x, pays only if it avoids a re-write (1.25x of the context) - i.e. the agent's own mean gap between requests > 5 min.
2. Main session: on a subscription it is already 1h. If VULYK is run with an API key or once on usage credits, set `promptCacheTtl: "1h"` (main only) - the Queen waits for agents/Workflow for long stretches and its context is the largest; a 5m main cache dies while blocked (#74318: 96% of parent cache deaths at ~9 min median idle; #97758). No built-in keepalive exists; UNVERIFIED workaround = none.
3. Make the shared prefix of each agent TYPE actually shared: move every stable rule (what the repo puts in CLAUDE.md that workers need, the cycle.sh protocol, verification commands) into the agent file BODY, because the body is the system prompt (before the first breakpoint, shared across spawns), whereas CLAUDE.md goes into messages[0] after which the unique task prompt makes it unshareable (#98513, API lookback rule). Then set `omitClaudeMd: true` on those agents so the CLAUDE.md copy is not written 12-30K per spawn. Keep the body byte-identical (no dates, slugs, story ids, run numbers, absolute per-run paths). Minimum cacheable is 512 tokens on Sonnet 5.5/Opus 5.5 [API doc].
4. Use Workflow fan-outs for same-type parallel agents and keep the stagger ON (default 5000 ms; raise CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS if the first response takes longer than 5 s to begin, e.g. slow Opus/Fable thinking start) so siblings 2..N read the first agent's tools+system cache instead of each writing it; identical model/effort/agent type/tools/output schema/cwd are required for the match [W]. For ad-hoc Agent-tool spawns from the Queen, dispatch ONE agent of a type first, then the rest after its first response starts (API doc: entry available only after the first response begins) - parallel simultaneous first requests each write.
5. Keep agent config uniform per type: same `model`, same `effort`, same `tools:` list order, same `skills:` list; any difference (or an extra tool like SendMessage that adds the sibling roster reminder) forks the prefix [W][S]. Omit SendMessage from `tools:` where resume is not needed.
6. Stabilise volatile parts that land before/near the prefix: (a) git status snapshot is per-spawn volatile and cannot be disabled per agent; global `includeGitInstructions:false` / CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1 removes it (and the built-in commit/PR text) - test on a worker-heavy spec whether the read tokens rise; its position (system prompt vs message) is CONFLICTING in evidence (Q6). (b) Bash-tool description session URL (#87137) and the `Today's date` line (#87487) have no switch - nothing to pull, but avoid midnight-spanning runs or expect one rewrite. (c) CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 if main-session cache writes recur every turn in this repo (#96578).
7. Hook hygiene (VULYK ships SessionStart/UserPromptSubmit/PreToolUse hooks, e.g. defects-inject.sh, handoff.sh): hook `additionalContext` placed in the prefix region or changing every call causes rebuild misses (#91707, fixed 2.1.259 - installed 2.1.285 is past it; but #89651 says SessionStart additionalContext after the last breakpoint is billed uncached each session start, regressed in 2.1.237, UNVERIFIED on 2.1.285). Make hook output constant or move it to a file the model reads.
8. Check `totalTokensReminder`: default padded-countdown places a `<total_tokens>` role:system message last with the only message-level breakpoint; UR #90018/#96101/#96163 show repeated conversation rewrites, `"totalTokensReminder":"off"` fixed interactive tool loops (#90018). (The Queen session here shows `<total_tokens>` reminders, so the feature is active.) A/B it with the /usage `Prompt cache (main)` misses counter; turning it off is a one-time system-prompt change.
9. Stop self-inflicted prefix breaks in the Queen: no /model or /effort (non-exempt models) mid-task; no MCP/plugin/deny-rule changes mid-session unless tool search is on; `/compact` only at natural breaks and while the cache is warm (summarisation reads the cache; after TTL it reprocesses everything); prefer /rewind over compact to abandon a path; avoid batches of screenshots/PDFs. opusplan toggling = model switch. [P]
10. Use forks instead of fresh subagents when a task needs the Queen's whole context (review of what she just built): fork reads the parent's cache on first request (interactive default since 2.1.232; the Workflow/-p/SDK default is off -> CLAUDE_CODE_FORK_SUBAGENT=1). Caveats: a fork runs the main session's model, so it is not a cheaper-model option; its requests fall in the "everything else" bucket (5m by default) [P]; resuming forks is cache-hostile (#88444, UR). [S][P]
11. Measurement loop: statusline `prompt_cache` (hit_ratio, misses, last_miss_cause, expires_at, recache_tokens_if_cold) and `/usage` line cover the MAIN conversation only; subagents need transcript parsing (dedupe by message.id + requestId; the jsonl writes usage per content block, inflating ~1.7x [#94177]). Set VULYK telemetry to record cache_creation.ephemeral_5m vs 1h per agent type.
12. If anything is ever run through the raw API/SDK (e.g. headless -p fleets): `excludeDynamicSections:true`/`--exclude-dynamic-system-prompt-sections` (-p only), system prompt array with SYSTEM_PROMPT_DYNAMIC_BOUNDARY, top-level automatic `cache_control`, ENABLE_PROMPT_CACHING_1H via env for short sessions with gaps, `max_tokens:0` pre-warm to have the entry ready before a parallel fan-out (not with streaming/thinking/tool_choice any|tool, not in Batches) [SDK, API doc]. Batches: 50% discount stacks with caching; best-effort hit rate 30-98%, prefer 1h TTL [batch doc].
