## 1. Состав следующего минора (0.19)

### 1.1 Библиотека дефектов — механизм фреймворка
- **Шаблон.** Установщик кладёт в хост `docs/defects/README.md` (пустой индекс + правила).
- **Карточка — одна на класс**, не на место:
  - `id`, `класс`, `area:` (маски путей и/или команды);
  - дословные цитаты владельца: дата, материал, место;
  - причина; «нельзя / можно»;
  - `check:` — команда, которая выходит ≠ 0 на этом браке;
  - `status: block | text`. Статуса `warn` в VULYK нет: это «text с инструментом».
- **Условие статуса `block`.** Карточка `block` без `check:` блоком не считается. Кроме того, у `block` в `fixtures:`
  должны быть два негатива:
  - исходный случай;
  - синтетический негатив «та же жалоба в соседней форме».

  Оба обязаны ронять `check:`.
- **Снятие запрета владельцем:** цитата-отмена и `status: revoked` (D13 из гриля остаётся).
- **`scripts/defects-check.sh`** (переносится из YouTube_AI и обобщается). Прогоняет `check:` всех `block`-карточек
  против их фикстур и падает. Падает и на **долге**: у класса ≥ 2 цитат, а статус не `block`, где время цитаты —
  время коммита её строки (`git blame`), а не дата в тексте.
- Проектные проверки (`verify_edit.py` и т. п.) остаются в хосте. VULYK знает только контракт `check:`.

### 1.2 Приём замечания: хук `defect-intake` (UserPromptSubmit)
- Разбирает **только текст человека**. Вырезает `<task-notification>`, `<system-reminder>`,
  `<cross-session-message>`, `<pasted_content …>…</pasted_content>` до поиска.
- Триггер: таймкод **или** словарь RU/UK/EN («опять», «снова», «я же говорил», «не так», «переделай», «обрезал»,
  «again», «I said», «why did you»…).
- Вывод: одна строка в `additionalContext`: «похоже на замечание владельца → найди класс в `docs/defects/`, добавь
  цитату или заведи карточку; если класс ловится кодом — `check:` + две фикстуры в этой же работе».
- Бюджет задержки ≤ 200 мс (в пилоте замерено 163–183 мс на bash + jq под Windows). Без jq — тихий выход 0.

### 1.3 Подкладка `text`-карточек: хук `defects-inject` (PreToolUse)
- Для карточек, которые кодом не проверить (в пилоте 10 из 19).
- Matcher: `Edit|Write|MultiEdit|NotebookEdit|Bash`. Сопоставление с `area:` идёт по `file_path` или по **всей** строке
  команды.
- Кладёт строки «нельзя» этих карточек, ≤ ~1000 токенов, хвост заменяется ссылкой.
- Ключ дедупликации: `session_id + agent_id + card`. Сброс на SessionStart с `source: compact|clear`.
- `block`-карточки не подкладываются: за них говорит `check:`.

### 1.4 Ревью: «ПРОВЕРИТЬ» — это находка
- В `lead-review` и `council-opus`: каждая строка проверки со статусом warn / ПРОВЕРИТЬ / check при коде 0 выносится
  в находки, и её нужно закрыть блоком или явным решением владельца.
- Место совета с **независимым замером** остаётся обязательным с Tier 3: пилот показал, что оно ловит класс
  «проверка есть, но не блокирует».

### 1.5 Конституция (одна строка в Laws)
> An owner's correction joins a defect class in `docs/defects/`. A class that code can check gets a failing `check:` with the original
> case and a neighbour-form negative in the same work; a repeated class without one is debt and fails `defects-check.sh`.
> Inside a Tier 3-4 story that names the file, the check goes into the next repair story.

### 1.6 Хвосты, найденные пилотом
- **Ручной шаг в волне.** В плане истории можно писать `blocked_by: manual:<id>`. Драйвер останавливается на границе
  волны с понятным `stop`, а не диспатчит воркера в NEEDS_CONTEXT. Снятие: `cycle.sh` команда `manual-done <id>`.
- **`VULYK_AUTOLEARN` на SessionEnd.**
  - Сначала проверить в YouTube_AI, пишет ли `project-learnings.sh` хоть что-то после 27.09.
  - Если нет (ожидаемо по docs), `anomaly-scan.sh` называет хост, где в SessionEnd стоит `claude -p`.
  - Дистилляция — дело litopys (SessionStart / PreCompact / команда).
- **Установщик.** `wire_hook` получает matcher (для PreToolUse). Правка `install.sh` — только в бинарном режиме,
  CR не терять. Проектные хуки хоста не трогаются.

### 1.7 litopys (D7a, D10 — не зависит от пилота)
- `session-start-brief.sh` видит litopys в `enabledPlugins`. Если его нет — одна строка модели: «предложи владельцу
  один раз».
- Согласие → `claude plugin marketplace add Black-coffe/litopys --scope project` + `claude plugin install litopys@litopys --scope project`.
- Отказ → строка профиля `Chronicle: none (declined <дата>)`, вопрос больше не задаётся.
- Режим без litopys: всё из 1.1–1.6 работает; теряется только хроника.
- Открытие репо litopys — отдельным шагом после скана истории и явного «да» владельца. До открытия установка работает
  только у тех, у кого есть git-креды к приватному репо.
- ❓ Проверить: проходит ли `claude plugin install … --scope project` из Bash внутри сессии без интерактива.

### 1.8 Тесты
