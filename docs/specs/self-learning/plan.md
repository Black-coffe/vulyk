## 1. Ступень 1 — следующий минор VULYK (0.19)

Цель: урок, который уже записан в `.claude/rules/`, доходит до модели на Edit/Write/Bash и после компакции, но
не раздувает базовый промпт. Проверяемый урок становится гейтом через обычный путь VULYK. Противоречия в
правилах видны.

### 1.1 Хук `rules-inject` (PreToolUse)
- Файл: `.claude/hooks/rules-inject.sh`. Регистрация — PreToolUse, matcher `Edit|Write|MultiEdit|NotebookEdit|Bash`.
- Для каждого `.claude/rules/*.md` читает `paths:` (только это поле; Claude Code читает его так же).
  - Edit/Write: сопоставляет `tool_input.file_path` с масками.
  - Bash: ищет по **всей** строке `tool_input.command` пути или имена файлов, которые подходят под маски
    (`cd … && py -3 pipeline/edit_build.py` тоже ловится). Префиксный `if: Bash(...)` не используется.
- В `additionalContext` кладёт только пункты-запреты этого правила: строки с маркером `✗`. Потолок ~1000 токенов;
  если больше — хвост заменяется ссылкой на файл. Полный текст правила по-прежнему грузит сам Claude Code на Read.
- Дедупликация: ключ `session_id + agent_id + rule-file`, состояние в `.claude/state/` (gitignored). Сброс ключей сессии —
  на SessionStart с `source: compact|clear`, так правило снова приходит после компакции. Воркеры-субагенты получают урок
  сами (свой `agent_id`), расход на hive-прогонах считается в `token-report.py`.
- Без python и jq — тихий выход 0. Бюджет задержки ≤ 150 мс на вызов под Windows; мерить в тесте.

### 1.2 Конвенция запрета в правилах
- Урок-запрет в `.claude/rules/*.md` — одна строка: `- ✗ <что нельзя> — <почему> · src: <файл/коммит/дата>`.
  Позитивная форма («держать запас ≥ X») пишется тоже со `✗` через обратное действие («✗ ставить `out` ближе X к концу слова»).
- Отозванный запрет: `- ~~✗ …~~ revoked <дата>: <слова владельца>`. Хук такие строки не кладёт (решение D13).
- `src:` связывает запрет с кодом: `rules-check.sh` (1.3) пометит запрет устаревшим, если файл из `src:` менялся позже даты
  запрета. Это ответ на «гниение» из рецензии.

### 1.3 `scripts/rules-check.sh` — линтер правил (всегда exit 0, отчёт, как остальные гейты VULYK)
- Размер правила: предупреждение > 8 KB (у `edit.md` в YouTube_AI 29 KB).
- `✗` без `src:`; `✗`, чей `src:`-файл изменён после даты запрета (кандидат на перепроверку).
- Сводка для `/vulyk-gc`: `librarian` получает список «кандидатов на противоречие». Пары правил об одном файле или
  параметре смотрит модель, решение за владельцем. Автоматического удаления нет.

### 1.4 Строка в конституцию (CLAUDE.md VULYK, раздел Laws или Routing)
> A correction that code can check becomes a gate: a Tier 1 story (warn first, then block) with fixtures built from source data,
> not from the model's reading of the lesson. Inside a Tier 3-4 story that names the file, it goes to the next repair story instead.

Это снимает конфликт D2 с Laws 3/5 из рецензии. Фикстуры строятся «по источнику» (звук, файл, вывод команды), а не по
пониманию модели: так гейт не закрепляет ту же ошибку.

### 1.5 Установщик
- `py_wire` в `install.sh` сейчас пишет только событие без matcher. Нужен matcher для PreToolUse: расширить `wire_hook`
  (event, script, [matcher]). Проектные хуки хоста не трогаются (урок `vulyk-update-keeps-project-hooks`).
- Правка `install.sh` — в бинарном режиме, литеральные CR не терять (урок `vulyk-install-sh-literal-cr-bytes`).
  После правки прогнать `tests/telemetry.test.sh`.

### 1.6 Личный уровень (D16, в урезанном виде)
- Тот же `rules-inject.sh` умеет читать `~/.claude/rules/*.md`, если его зарегистрировать в **пользовательском**
  `~/.claude/settings.json`. Тогда личные запреты работают и вне VULYK-проектов (ответ рецензии про D16).
- Установщик только предлагает эту регистрацию командой `--user-hooks` и молча её не делает.
- ❓ Грузит ли Claude Code `~/.claude/rules/` сам (user-level rules) — проверить по docs до реализации.

### 1.7 Тесты (новый `tests/rules-inject.test.sh`)
- Edit по маске → инъекция; Edit мимо маски → пусто.
- Bash `cd pipeline && py -3 edit_build.py x` → инъекция; Bash без путей → пусто.
- Повтор в той же сессии и том же агенте → пусто; другой `agent_id` → инъекция; после `source: compact` → инъекция.
- Только `✗`-строки, без `~~revoked~~`; обрезка по бюджету со ссылкой.
- Задержка: 50 вызовов, медиана ≤ 150 мс.
- `rules-check.sh`: фикстура со старым `src:` → «устарел»; > 8 KB → предупреждение.
- Регресс: `tests/{cycle,driver,e2e,solo}.test.sh`, `tests/council.test.sh --quick`, `tests/telemetry.test.sh`.

### 1.8 Критерий успеха ступени 1 (4 недели, YouTube_AI + katan)
- Повторов уроков с гейтом — 0.
- Инъекции ≤ 1% токенов сессии (`token-report.py`, отдельная строка на `rules-inject`).
- Повторы текстовых запретов считаются тем же способом, что база, чтобы сравнение было честным (замечание рецензии к D15):
  по feedback-файлам auto memory / записям `✗` с «снова», «тот же ляп» — до и после.

## 2. Ступень 2 — только если пилот подтвердит «проблема в доставке»

Условие входа: A0 = резала модель (не код), A1 = правила не было в контексте, и после ступени 1 текстовые запреты
всё ещё повторяются. Если A0 = код, ступень 2 не нужна для этого случая: хватает теста и правки `build_clips()`.

Состав (решения гриля с поправками рецензии):
- regex-детектор поправок на UserPromptSubmit (D4). Ложное срабатывание не ведёт в побочную работу: модель только
  отмечает кандидата, урок пишется при подтверждении. Глобальное MANDATORY-правило владельца сливается с ним,
  чтобы не было двух срабатываний;
- дерево запретов с id, счётчиками и слиянием скриптом (D6, D8, ACE). id берётся из хеша содержимого, а не из
  порядкового номера — так не будет коллизий в параллельных worktree;
- повтор как инцидент носителя (D9). Эскалацию ограничивает бюджет D15, иначе она превращается в «громче» (замечание рецензии);
- litopys: обнаружить → предложить → `--scope project` / отметить отказ, режим без litopys (D7a); публичный после скана истории (D10).
