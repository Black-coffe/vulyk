# Round 2 · Stream C · Prosecutor / skeptic

Date: 2026-09-29. Проверено на диске при `d519f22`.

## 1. Атаки

**A 1.6 `token-report.py --band` (δ = 2·sd по прошлым неделям) умирает.** Разброс weighted tokens на спек в сентябре — от 127k до 34.7M, то есть в 270 раз (`python scripts/token-report.py . --since 2026-09-01`). В неделе 1–5 спек, а сентябрьских недель всего четыре. δ получится больше самой медианы, и каждая строка вечно будет печатать «within noise». Это ~30 строк кода и постоянный вывод, который ничего не различает. Замена — печатать n и диапазон. Строки кода не нужны.

**A 1.12, guards по escaped defects / `scope_breach` / `agent_empty`, умирает, кроме `model_below_floor`.**
- `scope_breach` срабатывает в 127 из 140 историй (`memory/stats/scope.jsonl`). Его недельный счётчик меряет число историй, а не качество, поэтому такой guard блокировал бы changeset по объёму работы.
- `model_below_floor` детерминирован: это факт конфигурации (`docs/telemetry.md:27`). Он выживает.

**A 1.5, три пункта критика в `lead-review`, умирает в этой форме.** Тело `lead-review.md` (4 711 B) грузится при каждом диспатче ревью в каждом улье. `lead-review` — это 34% цены раунда (`docs/specs/token-audit/report.md:112`). Пункты рассчитаны на ветки `vulyk/evolve-*`, а таких веток ни одной не существует (`git branch -a | grep evolve` пуст). Выходит, что мы платим на каждом ревью за случай, который пока не наступал ни разу. Место этим пунктам — в разделе «How a changeset is judged» внутри `/vulyk-evolve`, который грузится только там.

**A 1.10 и B-top-3, prune по срабатываниям, умирают для `block`-проверок.** Ценность guard'а — в его молчании. Карта `block` не тратит ни одного токена на ход: знание ушло из контекста в код (B §2). Значит, давления её удалять нет, а тишина — это не бесполезность. Логирование в `defects-inject.sh` (новый state-файл и запись на каждый PreToolUse, `.claude/settings.json:35`) оправдано только для `text`-карт, которые стоят байтов. «Yield ≤ δ» для строк промпта неизмерим (см. выше): под него попадёт либо всё, либо ничего.

**B §4, бюджет always-on 16 KB, включающий глобальный `~/.claude/CLAUDE.md` (9 205 B) и auto-memory `MEMORY.md`, умирает в этой части.** Этими файлами VULYK не владеет: их нет в репозитории, installer их не пишет. Правило «записывай уроки» из глобального CLAUDE.md владелец объявил MANDATORY. Потолок по чужому файлу горел бы вечно, а подрезать его означало бы спорить с инструкцией владельца. Бюджет должен покрывать только то, что VULYK поставляет.

**B, отчёт о бюджете как «отчёт гейта, а не блок», умирает.** Law 6: «A check that only warns is not a check». Доказательство на диске: цель ADR-013 D7 «under ~7 KB and under 120 lines» (`docs/adr/013-light-vulyk.md:255-256`) была советом, и сейчас `CLAUDE.md` весит 8 652 B. Предупреждение уже проиграло.

**B, SessionStart-отчёт размеров, выживает только как замена ложной строки.** Строка «learnings awaiting GC: 41» (`session-start-brief.sh:8`) считает 37 стабов по 4 непустые строки и README. Замена допустима при нетто ≤ 0 байт на сессию.

**Журнал `evolve.jsonl` (A 1.2, B top-2, мой R1) сливается.** Одна оговорка к B: писатель — сама команда evolve, а не диспатч `librarian` (отдельный агент ради одной JSONL-строки).

## 2. Уступки

**(a)** Принимаю. Реальный дефект не «нет Evaluate()», а «существующий цикл не исполняется»:
- 37 из 41 файлов `memory/learnings/` — стабы;
- `CONSOLIDATED.md` нет;
- веток evolve нет;
- в CHANGELOG `/vulyk-evolve` назван «still unproven» (`CHANGELOG.md:1435`).

Журнал для цикла, который не запускается, — мёртвая бумага. Минимум меняется так:
1. Сначала один реальный прогон `/vulyk-gc` и `/vulyk-evolve` и исправленный счётчик.
2. Если после этого evolve так и не станет запускаться, по Law 2 машину надо резать, а не обвешивать.

**(b)** Да, шум к байтам неприменим: `wc -c` точен, и δ = 0. Байты — не косвенный показатель. Фиксированный пакет, который перечитывается на каждом ходу, — это 23.2% всех взвешенных расходов (`token-audit/report.md:74`). Детерминированный потолок выживает при двух условиях: он падает (exit ≠ 0 в существующем тестовом наборе) и меряет только файлы, поставляемые VULYK. Шумной остаётся сторона выгоды, «стоила ли строка своих байтов», и её судит владелец.

**(c)** Да. Фикстуры ADR-014 — единственный детерминированный воспроизводимый Evaluate(), который есть у VULYK: фиксированный набор, бинарный исход, нулевой шум, и соседняя форма как проверка переобучения (`docs/defects/README.md:59-62`). Это аналог held-out у RRSI. Но деноминировать рост в фикстурах нельзя. Фикстуру пишет тот же агент, что предлагает рост, так что платёж легко изготовить (ровно то, от чего у RRSI существует critic). Валюта — **дословная цитата владельца** в классе дефекта (Law 6). Её агент изготовить не может. И следствие из лестницы B: если класс проверяем кодом, ему место в `check:`, а не в always-on. Always-on оплачивается только непроверяемым.

**(d)** Да, три механизма оживают на байтах:
- **Cost rule** → байтовый потолок относительно релиза, не incumbent'а (храповика нет).
- **Within-band rule** → нейтральная правка принимается, только если она сокращает байты (A 1.8).
- **Prune set** → кандидаты — `text`-карты и строки конституции по байтам, решение за владельцем.

Остальные не оживают: noise floor (δ=0 делает его пустым), отжиг, новизна, разведка.

**Выживший минимум**, по порядку:
1. Гигиена. Один прогон `/vulyk-gc` по 37 стабам и 4 реальным learning, исправленный счётчик `session-start-brief.sh:8`.
2. Падающий тест: поставляемый always-on (`CLAUDE.md` ≤ 7 KB по ADR-013 D7 плюс вывод SessionStart-хуков VULYK). Рост разрешён только за дословную цитату владельца в классе дефекта, который нельзя проверить кодом.
3. `memory/stats/evolve.jsonl`, пишет команда. Evolve читает последние 40 строк и все rejected; печатает n рядом с каждой цифрой.
4. Если после одного реального прогона evolve снова не запускается — удалить его, а не достраивать.
