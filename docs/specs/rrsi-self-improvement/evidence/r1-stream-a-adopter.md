# R1 · Stream A (Adopter / mechanic): механизмы RRSI и их перенос в VULYK

Дата 2026-09-29. `rrsi/` — клон google-research/rrsi в scratchpad сессии (коммит на сегодня: 4 коммита, issue #2 открыт).
Все пути VULYK даны от корня репозитория.

## 0. Две вещи, которые определяют весь перенос

**A. У RRSI есть целевая функция, у `/vulyk-evolve` её нет.** RRSI принимает кандидата только по
измерению: 89 задач × k=2 = 178 прогонов на кандидата, δ=0.017 (`domains/coding/rrsi.json`: `_doc`, `k`,
`delta`). Эволюция VULYK в той же точке опирается на суждение человека (`docs/self-evolution.md:16`). Сам
CHANGELOG это признаёт: «`/vulyk-evolve` is unchanged but still unproven … changing configuration without
feedback is exactly what it exists to prevent» (`CHANGELOG.md:1435-1437`). По факту цикл ни разу не
запускался: `git branch -a | grep evolve` пуст. В `memory/learnings/` 36 из 40 файлов — пустые заготовки
(подсчёт по непустым строкам). `CONSOLIDATED.md`, на который ссылается
`.claude/skills/_meta/insight-harvester/SKILL.md:11`, не существует.

**B. Стенд RRSI не переносится.** RRSI повторяет задачи и сравнивает кандидатов A/B; задачи VULYK не
повторяются (`council.jsonl` — 16 строк, `ship.jsonl` — 7 за всю историю). Брать надо **дисциплину учёта**:
гипотеза, предсказание, вердикт, цена в токенах, выход (yield) для обрезки.

Оговорка: TB2.1 74.2→80.2 — на самом эволюционном сплите (`README.md:129`; `rrsi.json` `_doc`: «evolve set
= whole suite»); held-out — SWE-bench 82.0→83.8 (`README.md:130`). Экономия токенов: «30%» (abstract arxiv
2609.24972) против «−36%» (regularized-rsi.com).

## 1. Механизм за механизмом

### 1.1 Отжигаемый бюджет правок b_t
**Как в коде.** Косинус от b_max к b_min с потолком (`rrsi/schedule.py:43-50`). Бюджет проверяется в
`done()`: превышение возвращается proposer'у (`rrsi/propose.py:338-339`). **Разрыв с paper (issue #2).**
Сопровождающий подтвердил: t бежит по 0..T-1 и округляется вверх, поэтому последний раунд получает b_min+1.
`budget_table(20,1,4)` = [4]*8+[3]*5+[2]*7 — единица не наступает никогда, и все опубликованные прогоны шли
с бюджетом последнего раунда 2. Переключателей для аблаций Table 2 в релизе нет. Значит, вклад отжига как
такового не измерен.
**Аналог в VULYK.** `scripts/scope-check.sh` считает `declared/changed/out_of_scope` (строка 19). Для
evolve лимита нет: в changeset'е «one CHANGELOG line per change», но число изменений не ограничено
(`.claude/commands/vulyk-evolve.md:106`).
**Вердикт: ADAPT (без косинуса).** Фиксированный потолок: не больше 3 независимых изменений в недельном
changeset'е, каждое с отдельной гипотезой. Правка — одна строка в `vulyk-evolve.md` шаг 4. Отжиг
отвергаю: при T≈1 раунд в неделю расписание вырождено, а у авторов оно не работает даже при T=20.

### 1.2 История правок L_t (компонент, гипотеза, ΔS, ΔC, вердикт)
**Как в коде.** Одна JSONL-запись на *правку*; бандл делит одно измерение на всех
(`rrsi/history.py:77-99`). Контекст proposer'а ограничен: `render(n=40)` берёт последние 40 записей, а
неизмеренных (отказ критика, smoke) — не больше 4, потому что «a wall of aborts is a feedback loop, not
evidence» (`history.py:166-185`). Proposer'у прямо сказано: «A rejected mechanism is negative evidence; do
not redraw it unchanged» (`propose.py:266-270`). Отдельно ведётся табло предсказаний: `predicted_affected`
→ `hit_rate` и `unpredicted_regressions` (`rrsi/loop.py:159-178`).
**Аналог.** Частичный: `CHANGELOG.md` (проза без измерения), `memory/stats/*.jsonl` (наблюдения, не
гипотезы). Реестра «пробовали / предсказали / вышло» нет.
**Вердикт: ADOPT.** Новый реестр `memory/stats/evolve.jsonl`, одна строка на изменение: `{ts, component,
file, hypothesis, predicted_signal, baseline, verdict: proposed|merged|rejected|reverted,
context_bytes_delta}`. Шаг 1 `/vulyk-evolve` читает последние 40 строк; отвергнутое повторно без новой
улики не предлагается. Объём: около 15 строк в команде и строка в `docs/self-evolution.md`. Растущего
per-turn контекста нет: файл читается только внутри evolve.

### 1.3 Tried set T_t, флаг стагнации σ_t, резервный слот для неисследованных компонентов
**Как в коде.** σ_t = 1[S_t − S_{t−w} ≤ δ] (`history.py:189-193`). При стагнации один из m кандидатов
*обязан* трогать компонент из U_t = K \ T_t (`history.py:196-211`, `loop.py:294`). Метку компонента
перепроверяют по диффу, чтобы её нельзя было подделать (`rrsi/components.py:82-100`, `loop.py:510-530`).
**Аналог.** У `cycle.sh` есть no-progress: та же ask красная два раунда подряд → ESCALATE
(`scripts/cycle.sh:1120-1141`). Но это остановка и вопрос владельцу, а не принудительная разведка.
**Вердикт: REJECT.** Принудительная разведка тянет к *добавлению* механизмов, против «Deletion-biased»
(`docs/self-evolution.md:19`); у недельного evolve нет w раундов для σ. Проверку метки по диффу уже
покрывает `scope-check.sh`.

### 1.4 Analyst + digester (сырые трассы не попадают в контекст)
**Как в коде.** Digester — read-only субагент на одну трассу с дайджестом не длиннее 6000 символов
(`rrsi/digester.py:46-48`, `185-189`). Analyst сам трасс не читает (`rrsi/analyst.py:59`). Между
раундами переносятся только *имена* прошлых failure modes и success habits, для стабильного именования;
`global_analysis.json` каждый раунд перезаписывается (`loop.py:258-267`). Три линзы, среди них
`success_habits` — «behaviors your change MUST NOT break» (`propose.py:279-282`).
**Аналог.** Уже есть: `drone-scout`, `cycle-clerk` (одна строка), `librarian` (`docs/memory-system.md:38`).
**Вердикт: ADOPT только линзу success habits:** каждое изменение в `insight-harvester` называет привычку,
которую может сломать («preservative» из `propose.py:100-103`). Одна строка.

### 1.5 Критик-скрининг утечек до траты на оценку
**Как в коде.** Два слоя. Сначала детерминированные regex: секреты, пути грейдера, *имена всех задач
бенчмарка* (`rrsi/critic.py:50-52`, `domains/coding/adapter.py:113-141`). Затем LLM-ревью по шести
пунктам: leakage, degenerate (в том числе удаление предохранителя без замены), grader gaming, undeclared
bundling, runtime memory leakage, unbounded work (`critic.py:62-95`). Отклонённое уходит на ≤5 раундов
ремонта (`config.py:77`). Непарсабельный ответ считается reject (`critic.py:145-147`). Критик,
proposer и analyst работают на одной модели (`config.py:82-84`, все `claude-opus-4-8`).
**Аналог.** Сильнее по детерминированной части: карточка дефекта получает `block` только при фикстуре
«соседней формы», а фикстура, которая проходит, красит gate в красный (`docs/defects/README.md:58-63`,
ADR-014 D2). Это прямой аналог теста «would this still help on an unfamiliar task». LLM-часть — это
`lead-review`.
**Вердикт: ADAPT.** Отдельного агента-критика не заводить: дефектная библиотека делает эту работу
детерминированно. В инструкцию `lead-review` для ветки `vulyk/evolve-*` добавить три пункта критика,
которых в VULYK нет: degenerate (удалён предохранитель без замены), unbounded work (цикл без выхода),
«правило выведено из одного спека и вне его не работает». Одинаковую модель у проверяющего и
проверяемого не переносить: это нарушает «the family that builds never judges» (CLAUDE.md, Models).

### 1.6 Порог с поправкой на шум + `calibrate`
**Как в коде.** δ = z·sd(null ΔS) по повторным оценкам *неизменного* базового харнесса или бутстрапу
(`rrsi/calibrate.py:85-108`, z=2). Допустимость: S' ≥ S* − δ, где S* — лучший результат за всё время
(`rrsi/selection.py:107-111`). Это храповик: по ступенькам шума вниз не спуститься.
**Аналог.** Нет. Пороги телеметрии названы «v1 calibration, not measured facts» (`docs/telemetry.md`,
абзац после таблицы кодов). Экономия v0.18 «−40…55%» — «an estimate» (`docs/token-economy.md:118-124`).
**Вердикт: ADAPT.** `/vulyk-evolve` шаг 2 печатает недельные метрики (медиану раундов до green,
weighted tokens на спек, escaped defects) вместе с разбросом по прошлым неделям: δ = 2·sd. Всё, что
внутри δ, помечается «within noise», и заявлять улучшение по этой метрике запрещено. Реализация: около
30 строк в `scripts/token-report.py` (`--band`). Честная оговорка: при 1–5 спеках в неделю δ будет
широким, и именно это полезно знать.

### 1.7 Правило стоимости: токены оплачиваются приростом
**Как в коде.** При ΔS > δ кандидат проходит, только если ΔC ≤ β0 + β1·ΔS. Здесь ΔC относительный:
β0=0.10 означает «10% бесплатно», β1=44.5 для coding (`selection.py:81-89`, `config.py:44-46`,
`rrsi.json`). Экономия проходит всегда.
**Аналог.** Токены измеряются (`scripts/token-report.py`), и есть порядок рычагов
(`docs/token-economy.md:194-205`). Правила «рост контекста надо оплатить» нет. `self-evolution.md:19`
говорит «a line there costs on every turn», но это совет, а не проверка допуска.
**Вердикт: ADOPT (ядро ответа на «контекст не разрастается»).** Каждая строка changeset'а объявляет
`context_bytes_delta` для *всегда загружаемого* набора: CLAUDE.md, тела агентов, описания скиллов,
строки инъекций хуков; считается через `wc -c`. Правило допуска:
- дельта > 0 допустима только с уликой: карточка дефекта с 2+ цитатами (Law 6) или метрика за
  пределами δ из 1.6;
- дельта ≤ 0 допустима всегда.

Объём: шаг в `vulyk-evolve.md` и крошечный скрипт `scripts/context-bytes.sh` (≤40 строк).

### 1.8 Правило внутри шумовой полосы (within-band)
**Как в коде.** Если |ΔS| ≤ δ: w_s·ΔS − w_c·ΔC + w_n·ν > 0 (`selection.py:90-94`); для coding w_s=0, т.е.
проходит только экономия токенов или новый структурный компонент (`domains/coding/SKILL.md:32-37`).
**Вердикт: ADAPT без ν** — частный случай 1.7: нейтральное принимается, только если сокращает контекст.

### 1.9 Бонус новизны ν
**Как в коде.** Засчитывается структурный компонент, которого в инкумбенте ещё не было
(`components.py:103-108`). При w_n=0.5 и w_c=15 одна новинка «покупает» +3.3% токенов без всякого
прироста.
**Вердикт: REJECT.** Это прямой стимул к росту механизмов, противоположный deletion bias VULYK.

### 1.10 Множество на обрезку B_t
**Как в коде.** g_t(l) = max ΔS правок компонента l за последние n_prune=4 раунда, B_t = {g ≤ 0}
(`history.py:143-163`). Слабые места, видимые в коде:
- обрезка **только рекомендация** proposer'у: «Prefer it when…» (`propose.py:122-126`), автоматического
  удаления нет;
- g сравнивается с 0, а не с δ, поэтому компонент с шумовым +0.001 обрезки избегает;
- `accepted_edits()` не знает об уже удалённом: удаление не записывается (`history.py:129-138`).

**Аналог.** `skill-gardener` отправляет в архив по *использованию* («Zero invocations for 3+ weeks»,
`.claude/skills/_meta/skill-gardener/SKILL.md:39`), есть `_graveyard/`. Для правил, строк конституции и
карточек `text` критерия выхода нет.
**Вердикт: ADAPT (с исправлением трёх слабостей).** Выход (yield) = «сработало и поймало»: для карточки
`block` — красный `check:` на реальной работе; для `text` — инъекция без повторной цитаты; для строки
промпта — предсказанный сигнал из 1.2 сдвинулся за δ. Если выход ≤ δ за 4 недели и нет пометки
`keep: severity`, это кандидат в graveyard. Удаление записывается в `evolve.jsonl` как `reverted`.
Решение по-прежнему принимает человек.

### 1.11 Worktree на кандидата, инкумбент — всегда коммит
**Как в коде.** Только fast-forward на коммит победителя (`rrsi/gitops.py:121-126`); расхождение tree hash
с `frontier.json` останавливает прогон (`loop.py:235-237`); `readjudicate` пересуживает без новой оценки
(`loop.py:348-422`).
**Аналог.** Уже есть: ветки `vulyk/<slug>`, court worktree (`scripts/cycle.sh:2004`), `pack` в `council.jsonl`.
**Вердикт: ничего не менять.**

### 1.12 Некомпенсаторные guards
**Как в коде.** Любое нарушение делает кандидата недопустимым, как бы ни выросло S
(`selection.py:116-118`). По умолчанию список пуст (`rrsi/domain.py:78-80`); реально guards заданы только
в `eng` (`domains/eng/adapter.py:221-229`).
**Аналог.** Вердикт совета: любой RED/BLOCK → repair/escalate (`cycle.sh:1133-1146`); block-карточки.
**Вердикт: ADOPT для evolve.** Changeset недопустим, если за окно выросли escaped defects, `scope_breach`,
`agent_empty` или `model_below_floor` (`docs/telemetry.md`); экономия токенов не компенсирует. Две строки.

### 1.13 SKILL.md / PATTERNS.md как «конституция proposer'а»
**Как в коде.** SKILL.md открывается разделом «How your work is judged (… this is your reward)» с floor,
cost rule и band (`domains/coding/SKILL.md:12-51`); PATTERNS.md — «reference, not an allowlist»; оба в
кешируемом префиксе (`propose.py:253-256`).
**Аналог.** `insight-harvester/SKILL.md` задаёт метод, но не правила допуска.
**Вердикт: ADAPT.** Раздел «How a changeset is judged» (1.1, 1.7, 1.12), ~12 строк; per-turn цена нулевая.

## 2. Законы VULYK

Всё — Tier 1–2 правки `/vulyk-evolve`, `_meta`-скиллов, `lead-review` и 1–2 мелких скриптов, через
человеческий gate evolve; грузятся только внутри evolve. Law 6: поправка владельца к evolve-изменению
становится карточкой, а 1.7 делает карточку «валютой» роста контекста. Отвергнуто: косинус (issue #2), ν,
принудительная разведка, m параллельных кандидатов, критик той же семьи.

## 3. Топ-5 (по убыванию)

1. **Правило стоимости контекста (1.7 + 1.8).** `context_bytes_delta` на каждое изменение; рост только за
   улику (карточка 2+ цитат или метрика за δ), нейтральное — только если сокращает. Прямой ответ на
   «качество растёт, контекст не разрастается».
2. **Реестр `memory/stats/evolve.jsonl` (1.2).** Гипотеза, предсказанный сигнал, вердикт, дельта байт;
   evolve читает последние 40 строк; отвергнутое без новой улики не предлагается повторно. Даёт evolve
   память без роста.
3. **Обрезка по выходу, а не по использованию (1.10).** Выход ≤ δ за 4 недели без `keep: severity` →
   graveyard. Удаление фиксируется в реестре. Исправлены три слабости RRSI: только рекомендация, сравнение
   с 0 вместо δ, удаление не пишется.
4. **Шумовая полоса для недельных метрик (1.6).** `token-report.py --band`: δ = 2·sd по прошлым неделям,
   «within noise» запрещает заявлять улучшение. Заодно проверяет оценки вроде «−40…55%» из ADR-013.
5. **Guards + «How a changeset is judged» (1.12 + 1.13 + 1.5).** Рост escaped defects, `scope_breach`,
   `agent_empty` или `model_below_floor` блокирует changeset. Правила допуска записаны в
   `insight-harvester`. Три пункта критика (degenerate, unbounded, one-spec rule) — в `lead-review` для
   `vulyk/evolve-*`.
