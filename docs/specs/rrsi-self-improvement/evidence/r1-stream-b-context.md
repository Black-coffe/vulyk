# Stream B — Context keeper (round 1)

Date: 2026-09-29. Lens: how RRSI keeps its knowledge bounded while quality rises, what VULYK does today, and the smallest "golden middle" for VULYK.
RRSI paths are relative to the local clone `scratchpad/rrsi/`. Byte sizes measured with `wc -c` / `find … | wc -c` on 2026-09-29.

## 0. Коротко

В RRSI контекст не разрастается не из-за умной памяти, а из-за **цены**: каждая добавленная строка харнесса оплачивается токенами политики на каждом прогоне, и правило отбора пропускает рост только под измеренный прирост (`rrsi/selection.py:81-95`). Удаление — это обычная правка, которая проходит тот же отбор. В VULYK цены нет: знания копятся в always-on слое, пока человек раз в месяц не вырежет их вручную (ADR-013), механизмы сжатия (gc, evolve) описаны, но ни разу не запускались, и ничего никогда не удалялось потому, что было *измерено* как бесполезное.

## 1. RRSI: что видит каждая роль

| Роль | Видит | Ограничения (file:line) |
|---|---|---|
| Digester (один трейс) | один отрендеренный трейс, read-only инструменты, вопросы аналитика (≤5) | 15 ходов, вывод инструмента ≤25 000 симв., дайджест ≤6 000 симв. — превышение отбивается (`digester.py:257-259, 395-400`) |
| Analyst | таблица задач, **имена** прошлых failure modes и success habits, дайджесты; сырых трейсов не читает | 30 ходов, ≤8 дайджестов за вызов (`analyst.py:22, 139`); трейсы: 22–60 худших + 6 лучших (`config.py:79-80`, `domains/*/rrsi.json`); prior names — **только из прошлого раунда**, файл перезаписывается (`loop.py:258-267`) |
| Proposer | стабильный префикс SKILL.md + PATTERNS.md (кэшируется), затем L_t, scoreboard, E_t, B_t, отчёт F_t, дайджесты, полный исходник харнесса, бюджет b_t | `propose.py:253-304`; префикс 16–24 KB на домен (coding 13.2+3.2 KB, eng 16.8+7.7 KB); read_trace ≤60 000 (`propose.py:58`); результаты чтения в транскрипте ≤150 000, прочие ≤4 000 (`propose.py:407-409`); 40 ходов; дамп исходника без лимита (`propose.py:189-194`) |
| Critic | только diff (≤120 000), объявленные правки (≤20 000), state-файлы (≤20 000); **историю не видит**; сначала regex-precheck | `critic.py:116-129` |

**Как ограничена история.** `history.jsonl` на диске — append-only, одна запись на правку: component, hypothesis, ΔS, ΔC, accepted, outcome; `detail` обрезан до 600 симв. (`history.py:70-99`). Diff хранится, но **в промпт не идёт** — `render()` берёт только ключи без diff (`history.py:181-183`). Proposer видит последние **40 записей**, из них не более **4 неизмеренных** (отказы гейтов): «стена абортов — это петля обратной связи, а не доказательство» (`history.py:166-185`). Scoreboard предсказаний — последние 20 строк (`loop.py:152-157`). Итого: диск растёт линейно, промпт — константа.

**Как удаляются компоненты.** `g_t(l)` = лучший ΔS компонента за последние `n_prune` раундов (4–5, `rrsi.json`); `B_t = {l : g_t(l) ≤ 0}` вместе со списком принятых правок, которые надо вынуть (`history.py:143-163`). Prune — не автоматика, а **рекомендация proposer'у**: правка «prune: …» законна и предпочтительна (`propose.py:122-125`), но проходит тот же отбор: внутри шумовой полосы δ кандидат принимается, если `w_s·ΔS − w_c·ΔC + w_n·ν > 0` (`selection.py:90-95`). Удаление, которое экономит токены и не теряет больше δ, проходит. В coding `w_s = 0` — внутри полосы выживает только экономия токенов или новая структура (`domains/coding/rrsi.json`).

**Регулятор роста.** Рост стоимости при реальном выигрыше: `ΔC ≤ β0 + β1·ΔS` (`selection.py:84-89`; β0 = 0.10–0.15). Бюджет правок отжигается 4→1 (`schedule.py:43-50`), поздние раунды атрибутируемы. Конституция (SKILL.md, PATTERNS.md) — человеческая и **не эволюционирует**.

**Что дала регуляризация** (paper, Table 2, §4.3, arxiv.org/html/2609.24972, прочитано 2026-09-29): без регуляризаторов 92.8 evolve / 40.3 OOD / 3.80M токенов; полный RRSI 90.5 / 43.6 / 2.42M. То есть регуляризация **снижает** in-sample, поднимает перенос и режет токены на 36%. Для VULYK урок: «качество растёт» надо мерить не тем, на чём настраивали.

**Слабые места RRSI в моей оптике.** (a) Окно 40 записей при m = 2 и b ≤ 4 — это ~5–10 раундов из 20–40: отвергнутая гипотеза старше окна **невидима**, и запрет «do not redraw it unchanged» (`propose.py:267-269`) действует только внутри окна. (b) Аналитик помнит имена мод только одного прошлого раунда. (c) Статистика pruning в статье не приводится (§C.2 описывает механизм, цифр нет) — неизвестно, как часто prune-правки вообще принимались.

## 3. Диагноз

1. **Только добавляется:** always-on слой (CLAUDE.md растёт сразу после среза), ADR, handoff, stats, CHANGELOG. Сжатие always-on случилось один раз и было ручным (ADR-013).
2. **Забывается:** реальные learnings лежат в буфере, который никто не читает (evolve не запускался: нет ни одной ветки `vulyk/evolve-*`); handoff старше 12 ч выпадает из авто-восстановления; auto-memory и `memory/` дублируют друг друга, и знание, записанное в одну, не видно из другой.
3. **Сигналы сломаны:** `session-start-brief.sh:8` считает `*.md` кроме `CONSOLIDATED.md` — т.е. README и 36 стабов, которые хук перестал писать в 0.18.0 (ADR-013 D7), но gc так и не удалил. Цифра «41» каждый день учит владельца её игнорировать.
4. **Ничего не удаляется по измерению.** Retire-кандидаты evolve — по неиспользуемости 3+ недели (`vulyk-evolve.md:57`), learnings — «newest evidence wins» (`librarian.md:17-18`), т.е. по свежести. Нет ни одного счётчика срабатываний правил: `defects-inject.sh` не пишет в stats, какую карту и когда показал.
5. **Нет истории отвергнутых гипотез эволюции.** Отклонённый владельцем changeset evolve нигде не оставляет следа; только скиллы имеют graveyard + `RETIRED.md`.

**Честная граница переноса.** У VULYK нет бенчмарка и k прогонов: `council.jsonl` — 16 строк за всё время. Шумовая полоса δ при такой выборке шире любого эффекта, поэтому статистическое «принять/выкинуть» RRSI не переносится. Переносится **форма**: бюджет, цена роста, окно, журнал гипотез, prune-список — с владельцем вместо статистического гейта.

## 4. Золотая середина для VULYK

Три яруса, у каждого своя валюта:

- **Always-on** (платится каждым ходом): бюджет в байтах. Глобальный + проектный CLAUDE.md + MEMORY.md + вывод хуков ≤ **~16 KB** суммарно (проект ≤7 KB по ADR-013; MEMORY.md ≤25 строк; хуки ≤1 KB). Рост здесь — аналог `ΔC`: changeset evolve, увеличивающий ярус, либо удаляет столько же, либо несёт доказательство (ссылку на defect-класс или повторную ошибку). Это прямой перенос правила `ΔC ≤ β0 + β1·ΔS`.
- **On-touch** (платится при касании пути): карты defect `text`, `.claude/rules/`, срезы map. Бюджет на единицу (≤5 строк `## Never`, срез ≤~80 строк), не на сумму.
- **Cold** (ADR, specs, chronicle, handoff, stats): без бюджета, доступ по указателю или окном. Размер не страшен, важна находимость.

**Лестница вниз, не вверх.** learning (буфер) → правило on-touch по пути → `check:` в коде с фикстурами (`block`, ноль токенов). ADR-014 это уже делает для дефектов; обобщить на learnings: evolve продвигает знание **только вниз**, always-on не бывает пунктом назначения. Знание не забывается — оно уходит из контекста в код или в холодный слой с указателем.

**«Правило живёт, пока зарабатывает место»** (аналог `B_t`): логировать срабатывания — `defects-inject.sh` пишет `{ts, card}` в `memory/stats/`; скиллы уже считаются (`skills.json`). Evolve строит prune-список: правила/карты/строки конституции без срабатываний и ссылок за `n_prune = 4` недели и без пометки `severity` → предложение переместить в graveyard с `RETIRED.md` (обратимо). Решает владелец — это наш гейт отбора вместо δ.

**Журнал гипотез эволюции** (аналог `L_t`): `memory/stats/evolve.jsonl`, одна строка на предложенное изменение — `{date, component, hypothesis, evidence, verdict: accepted|rejected|reverted, reason}`, `component` из закрытого словаря (constitution, rule, agent, command, hook, skill, defect, memory). Evolve показывает себе последние 40 строк **плюс однострочники всех rejected/reverted** — исправляя окно-забывание самого RRSI. Писатель один — librarian.

Совместимость с Laws: ничего не применяется само (Law 1, human gate evolve), нет новых агентов, это отчёт + одна строка лога + один jsonl (Law 2); бюджеты — отчёт гейта, как `scope-check.sh`, а не блок.

## 5. Top-5 (по убыванию ценности)

1. **Бюджет always-on с правилом цены роста**: скрипт-отчёт размеров ярусов в SessionStart вместо ложного «41»; changeset evolve, раздувающий always-on (≤~16 KB суммарно, CLAUDE.md ≤7 KB), обязан удалить столько же или предъявить доказательство — перенос `ΔC ≤ β0 + β1·ΔS` (`selection.py:84-89`).
2. **`memory/stats/evolve.jsonl` — журнал гипотез** с вердиктом владельца; evolve видит окно 40 + все отвергнутые однострочником, чтобы не перерисовывать их (лучше, чем окно RRSI `history.py:166`).
3. **Логи срабатываний + prune-список в evolve**: `defects-inject.sh` пишет показ карты; без срабатываний 4 недели и без `severity` → в graveyard через changeset (аналог `B_t`, `history.py:152-163`).
4. **Лестница только вниз**: learning → on-touch правило → `check:` в коде (обобщение ADR-014); always-on никогда не цель продвижения; wiki/rules — промежуточные пункты.
5. **Гигиена сегодня (Tier 0-1)**: один прогон `/vulyk-gc` (36 стабов, 4 реальных learning → CONSOLIDATED), счётчик без README и стабов (`session-start-brief.sh:8`), MEMORY.md отдать под правила владельца с потолком, проектное состояние — в `docs/specs`; handoff по направлению без 12-часового обрыва для явного запроса темы.
