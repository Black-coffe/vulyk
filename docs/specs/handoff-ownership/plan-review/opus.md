# Ревью плана handoff-ownership - Opus 5.5

## 1. Вердикт
**СОГЛАСЕН С ПРАВКАМИ.** Диагноз и фикс через `${CLAUDE_PROJECT_DIR}` верны: я проверил их по бинарю, транскрипту и своей пробе. Главная правка: история 01 закрывает баг, который владелец ловит сегодня в каждом улье, и не делит ни одного файла с `constitution-merge`. Держать её до 0.28.0 незачем, её надо выпустить отдельно сейчас. Вторая по весу: после отключения `/handoff` глобальный хук продолжает звать `/handoff`. План обязан сказать это владельцу вслух.

## 2. По пунктам

**П1. Диагноз: согласен.** Бинарь: `nye()` выполняет инъекцию через сам Bash-инструмент (`await y.call({command:be},Ae)`), поэтому она идёт в текущем cwd оболочки. `Ior()`: `h=oVn(); if(h||r!==s&&!Kg(r,n))`, то есть сброс бывает только при выходе за проект. Транскрипт cf1d2449, строка 1256: `"cwd":"E:\\Projects\\AI\\docs\\specs\\<client>\\<chat>\\files\\<folder>"`. Других `!`-инъекций в `.claude/commands` нет (grep).

**П2. `${CLAUDE_PROJECT_DIR}`: согласен.** В бинаре тело команды проходит `ro.replace(/\$\{CLAUDE_PROJECT_DIR\}/g,()=>bx(Zr()??cr()))` до `nye()`, `allowed-tools` подставляется отдельно (`Zr()??RS()`). Моя проба 2 (haiku, проект по пути с пробелом `.../review-opus/p q`): ``!`bash "${CLAUDE_PROJECT_DIR}/s.sh" "${CLAUDE_SESSION_ID}"` `` отработала, скрипт получил ровно один аргумент. Отвергнутые варианты отвергнуты правильно. `${CLAUDE_SKILL_DIR}` у команд пуст: в бинаре стоит «the skill has no folder of its own».

**П3. Поиск транскрипта: правка.** Корень по месту файла хука я принимаю: при вызове из команды он по построению равен `${CLAUDE_PROJECT_DIR}`. А вот «самый свежий транскрипт по слагу» стоит заменить точным:
- в том же блоке бинаря стоит `ro=ro.replace(/\$\{CLAUDE_SESSION_ID\}/g,K())`, а транскрипт пишется как `Gu(){return i(HW(),`${K()}.jsonl`)}`;
- проба 2: напечатанный sid `4f442da1-…` совпал с `session_id` из init, файл называется `4f442da1-….jsonl`;
- при выборе по mtime может попасться транскрипт параллельной сессии, и тогда механические секции смешают две сессии. Кроме того, Claude Code обрезает слаг длиннее 200 символов и дописывает хеш (`Ppe=200`, `OO()`), а `slugify_cwd` этого не делает.

Что поменять в 01:
- критерий 1: `bash "${CLAUDE_PROJECT_DIR}/.claude/hooks/handoff.sh" dump "${CLAUDE_SESSION_ID}"`;
- критерий 2: если id передан, берётся `~/.claude/projects/*/<id>.jsonl`; без id (ручной запуск) остаётся поиск самого свежего по слагу улья;
- тест: положить в каталог слага два транскрипта, более старый назван по id, и проверить, что собран именно он;
- тест задаёт `HOME` **и** `USERPROFILE`, как в `tests/handoff-window.test.py:75`: Python на Windows игнорирует `HOME`, и без этого тест читал бы настоящий `~/.claude`.

**П4. `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR`: согласен оставить вне плана.** В `Ior` при заданной переменной cwd сбрасывается после *каждой* команды и молча: сообщение и телеметрия стоят под `if(!h)`. Фреймворку не стоит менять семантику Bash во всех ульях. Лично владельцу это разумная опция в `~/.claude/settings.json`, вне этой спеки: его глобальный CLAUDE.md и так запрещает `cd`, а у `context_guard.py` тот же класс дрейфа (комментарий на строках 357-366).

**П5. Карточка дефекта: правка.** В её нынешнем виде её проверка может ослепнуть двумя путями:
- у Claude Code две формы инъекции: `vVn=/```!\s*\n?([\s\S]*?)\n?```/g` и `` TVn=/(?<=^|\s)!`([^`]+)`/gm ``. Соседней фикстурой должна стать fenced-форма ```` ```! ```` с `bash scripts/state.sh`, иначе построчный grep её не увидит;
- по настоящим командам `check:` никто не запускает. Block-карточки не инжектятся (`defects-inject.sh`, `injected_as`), `lead-review` гоняет только аудит фикстур (`lead-review.md:23`), а `defects-check.sh <arg>` в VULYK никто не вызывает. Критерий 4 так остаётся разовой проверкой.

Что поменять:
- добавить критерий в 01: `tests/maintenance.test.sh` прогоняет `check:` карточки по каждому `.claude/commands/*.md` и ждёт 0. Это CI (`ci.yml:156`). Заодно проверка, которая не смогла запуститься, станет красной здесь, а не «упадёт» на фикстурах впустую;
- в Files добавить `docs/defects/README.md`: таблицу `## Cards` не заполняет ни один инструмент;
- в `paths:` добавить `.claude/skills/**/SKILL.md`.

**П6. Очерёдность: правка.** Файлы 01 (`vulyk-handoff.md`, `handoff.py`, `maintenance.test.sh`, `docs/defects/command-injection-*`) не пересекаются со списками историй `constitution-merge`. Предлагаю вынести 01 в отдельную спеку `handoff-cwd` (Tier 1, патч 0.26.1 сразу). `handoff-ownership` оставить с одной 02: Tier 2 после `constitution-merge`, версия 0.28.0. Tier 2 для 02 верен.

**П7. `skillOverrides` вместо затенения: согласен.** Осторожность с плагинами теперь подтверждена бинарём: в `LC(e)` стоит `if(e.type!=="prompt"||e.source==="plugin")return"on"`, в `Wkn` стоит `if(e.source==="plugin")return;`. Значит, плагинный навык через `skillOverrides` не отключить. Допустимые значения: `on|name-only|user-invocable-only|off`. Ответ «disabled» на набранный `/handoff` приемлем. `user-invocable-only` оставил бы глобальный `/handoff` рабочим, а это нарушает ask 2.

**П8. Сканирование плагинов: правка (Закон 2), убрать.** На этой машине единственное попадание: `plugins/cache/claude-for-legal/corporate-legal/1.0.2/skills/ai-tool-handoff`. Это юридический навык, ложное срабатывание. В кеше к тому же лежат старые версии (litopys 0.2.1/0.3.0/0.4.0). Чтобы найти активные версии, нужно читать `installed_plugins.json` и `enabledPlugins` по трём слоям. Это код ради нуля реальных случаев, причём результат всё равно не исполнить. Что поменять: убрать строку `plugin <name>` из Contracts и пункт про плагин из критерия 2 истории 02. В Assumptions записать: «плагинные навыки не сканируются: `skillOverrides` на них не действует (бинарь)».

**П9. Ответ «keep» нигде не запоминается: правка.** Образец, на который ссылается план, это телеметрия: «One question, asked once» (`install.sh:458`), ветка «A10 (4): already answered». С `--keep writes nothing` вопрос будет повторяться на каждом `--upgrade` и каждом `/vulyk-update`. Хуже всего в AI, где keep стоит по умолчанию. Что поменять: `--keep <name>` пишет `"<name>": "on"`. Значение допустимо по схеме, а «Absent = on», так что поведение не меняется. Листинг показывает `kept <name>`, установщик молчит, если все находки `off` или `kept`.

**П10. Отдельный `handoff-owner.sh`: согласен.** Вызывающих трое. Слияние JSON надо брать из готового образца `py_wire` в `install.sh`: бэкап, нечитаемый файл не трогается. Читать с `utf-8-sig` (BOM), писать с `newline='\n'`.

## 3. Чего не хватает (по убыванию веса)

1. **После `--own handoff` второй хендофф теряет только ручной вход, остальное в нём продолжает работать.** Баннер stop говорит «Набери `/handoff`» (`context_guard.py:691`). Хук prompt велит модели «предложи… выполнить `/handoff`» (`:780`). Precompact и sessionend продолжают класть скелеты с «выполни `/handoff`» (`:650`), sessionstart подсовывает свой хендофф. Итог: «работает только один» не достигнут, а пользователю советуют команду, которая отвечает «disabled». Не нарушая решения 1 владельца:
   - (а) Goal, Assumptions и текст вопроса установщика говорят об этом прямо;
   - (б) в Next circle: `context_guard.py` владельца читает `skillOverrides.handoff` проекта и молчит там, где стоит `off`. Это его инструмент, строк пять, вне VULYK.
2. **Оба инструмента пишут в `<улей>/.claude/handoff/` файлы с одинаковым шаблоном имени `%Y%m%d-%H%M%S-<sid8>.md`** (`handoff.py:713`, `context_guard.py:653`). На `/clear` два хука sessionend могут попасть в одну секунду, и один файл затрёт другой. Что пишут оба, видно в `E:/Projects/AI/.claude/handoff/`: `20261013-161936-41bdfaaa.md` (`scope:`, `## Сводка`) лежит рядом с файлами VULYK (`## Summary`). Это задача следующей спеки.
3. **Non-goal «`state.sh` находит свой путь (`:23`)» неточен:** там `git rev-parse --show-toplevel` от cwd. Для обычной подпапки это работает. Но `cd` в `.claude/worktrees/<x>` остаётся внутри проекта и сохраняется, и тогда снимок состояния снимается с ворктри. Вес малый: поправить формулировку или считать корень от `$(dirname "$0")/..`.
4. **Совпадение `allowed-tools` с кавычками вне bypass не проверил никто.** Включить в ручную проверку владельца (`**Checked:**`): улей в режиме default, `cd docs`, затем `/vulyk-handoff`. Тем же шагом закрывается непроверенный интерактивный сценарий.
5. Не проверял: наследует ли субагент (например `cycle-clerk` с его `bash scripts/cycle.sh`) уехавший cwd Королевы.
