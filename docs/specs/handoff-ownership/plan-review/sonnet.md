# Ревью плана handoff-ownership - Sonnet 5.5

## 1. Вердикт
**СОГЛАСЕН С ПРАВКАМИ.** Диагноз и фикс 01 верны; в 02 главная дыра - после отключения `/handoff` глобальный хук владельца всё равно рассылает напоминания «набери `/handoff`», и они ведут в отключённую команду (см. п. 5).

## 2. По пунктам

**П1. Диагноз (cwd ушёл в подпапку, относительные `!`-инъекции падают). - СОГЛАСЕН.**
Подтверждено в бинарнике 2.1.296: `function Ior(e,n){...h=oVn(); if(h||r!==s&&!Kg(r,n)){reset...}}`, `oVn()` читает `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR`; `cd` внутри проекта сохраняется. Единственные `!`-инъекции в `.claude/commands` и `.claude/skills` - в `vulyk-handoff.md` (grep по `.claude`). `state.sh:23` и `handoff.sh:8` сами находят корень - их трогать не надо, как и сказано в Non-goals. Остальные `bash scripts/...` в командах (например `vulyk-status.md:41`) - вызовы модели, а не инъекции; не трогать верно.

**П2. `${CLAUDE_PROJECT_DIR}` в команде. - СОГЛАСЕН.**
В бинарнике есть `replaceAll("${CLAUDE_PROJECT_DIR}", ...)` и для тела, и для `allowed-tools`. Пути с пробелами: кавычки в плане уже есть. Не проверено вне bypass: совпадёт ли правило `Bash(bash "C:/.../state.sh":*)` с текстом инъекции. Подстановка делается одним и тем же `replaceAll`, текст идентичен, риск мал. **Правка:** в тест 01 добавить проверку, что строка в `allowed-tools` - дословный префикс соответствующей инъекции (иначе правка одного без другого молча ломает права).

**П3. `handoff.py`: корень = hive, где лежит файл хука. - СОГЛАСЕН.**
`main()` (`handoff.py` ~995-1003) для `dump`/`status` берёт `os.getcwd()`; хуки получают `CLAUDE_PROJECT_DIR`, их не менять - верно. Slug транскрипта от корня hive правилен, если сессия запущена в корне. Параллельные сессии: берётся самый свежий по mtime; сессия, которая гонит команду, пишет транскрипт прямо сейчас, так что почти всегда она и самая свежая - риск малый. **Опционально (требует пробы):** в бинарнике есть подстановка `${CLAUDE_SESSION_ID}` в теле скилла; если она работает и для команд, `handoff.sh dump "${CLAUDE_SESSION_ID}"` убирает угадывание по mtime. Не включать без пробы - Law 2.
Граница, которую план уже называет: сессия, запущенная в подпапке, всё равно не найдёт `scripts/state.sh` через `${CLAUDE_PROJECT_DIR}`. Это не регресс.

**П4. `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` в план не добавлять. - СОГЛАСЕН с планом.**
Env есть в списке разрешённых в settings, но `h=oVn()` делает сброс cwd при каждом Bash-вызове и глушит сообщение `Shell cwd was reset` (`if(!h) i(...)`). Это меняет поведение всех сессий на машине ради одной команды; корень - потребитель, он починен. Проверить интерактивно нельзя.

**П5. Story 02 и `skillOverrides`. - СОГЛАСЕН С ПРАВКАМИ.**
- Механизм рабочий: в бинарнике `cmd_skill_override_off` и текст `" is disabled via skillOverrides...`, `skillOverrides` - ключ `settings`, значение `on|name-only|user-invocable-only|off`.
- **Дыра (главная).** `~/.claude/hooks/context_guard.py:691-695,780-781` на Stop/prompt пишет «Набери `/handoff`...». Хук глобальный и по ответу 1 не отключается. После `--own handoff` в этом проекте будут два напоминания (VULYK: `handoff.py:736`, и guard), одно из них отправит в команду, которая отвечает `is disabled`. Это ловушка для самого владельца. **Правка в 02:** строка `hook <path>` в выводе и вопрос установщика/`/vulyk-update` должны прямо говорить: «этот хук продолжит напоминать про `/handoff`; после отключения команда ответит "disabled" - используйте `/vulyk-handoff`». Это только текст, код хука не трогаем (ответ 1 сохраняется). Владельцу стоит знать об этом до одобрения: возможно, он захочет «keep» и в других проектах.
- Детект по имени `handoff`: слишком широко (`handoff-lint`, `handoffs-…`) не страшно, потому что отключается только по «да» и по списку. Слишком узко: глобальный скилл с другим именем, но с триггером «запусти handoff» не найдётся. Принять как известный предел, записать в ADR-амендмент. **Правка:** вопрос должен позволять выбрать из списка, а не «все или никто»; AC 02 это не требует.
- Плагины только в отчёт - верно: в бинарнике `Wkn(e){if(e.source==="plugin")return;...}` отдельная ветка ключей для плагинов, не проверена.
- Слияние в `settings.local.json`: Claude Code переписывает этот файл сам (права). **Правка в AC 02:** читать с `utf-8-sig` (BOM), писать LF без BOM, во временный файл + rename, ключи сохранять; нечитаемый - exit 1 (в контракте уже есть). Добавить тест на файл с BOM и CRLF - это Windows-хост.
- `handoff-owner.sh` отдельным скриптом - оправдан тремя вызывающими (установщик с tty, `/vulyk-update` без tty, ручной). Не оверинжиниринг, но 7 файлов и шаг CI - потолок для Tier 2; ADR-амендмент и `command-reference.md` не растить.
- «Должен работать только один»: `/handoff` отвечает `disabled` - приемлемо, это точно то, что просил владелец (вырезать на проекте).

**П6. Последовательность и Tier. - СОГЛАСЕН С ПРАВКОЙ.**
Tier 2 верен. История 01 не трогает файлы `constitution-merge` (`install.sh`, `vulyk-update*`, `telemetry.test.sh`), а ошибка бьёт владельца сейчас. **Правка:** выпустить 01 отдельным патчем (0.26.1) не дожидаясь constitution-merge; 02 как 0.28.0. Plan.md сейчас пишет «Ships as 0.28.0 after constitution-merge» для всей спеки.

**П7. Карта дефектов (Law 6). - СОГЛАСЕН С ПРАВКАМИ.**
- `defects-check.sh`: без аргумента это audit - `check` запускается только на fixtures; на реальные команды он идёт лишь в режиме `<arg>` (`mode == 'gate'`, строка ~260). Поэтому AC 4 «чек проходит на всех остальных командах» никто не проверяет автоматически. **Правка:** в `tests/maintenance.test.sh` цикл, который прогоняет check по всем `.claude/commands/*.md` и `.claude/skills/*/SKILL.md`.
- Слепое пятно: Claude Code поддерживает и блочную форму инъекции (три обратные кавычки + `!`). Чек, ищущий только `` !` ``, её не увидит. **Правка:** второй neighbour-fixture с блочной формой, и `paths:` расширить на `.claude/skills/**/SKILL.md`.
- Fixtures рядом с карточкой (`docs/defects/*.fixture`), а не в `docs/defects/fixtures/` - допустимо, `defects-check.sh` читает любой путь из `fixtures:` и карточками считает только `*.md`.

## 3. Чего не хватает (по убыванию важности)
1. Напоминания глобального хука в отключённый `/handoff` (п. 5) - предупреждение в выводе и в ADR.
2. Проверка контракта `allowed-tools` ≡ текст инъекции (п. 2) и цикл по всем командам для Law 6 (п. 7).
3. Релиз 01 отдельным патчем сразу (п. 6).
4. Тесты слияния `settings.local.json` с BOM/CRLF (п. 5).
5. Блочная форма инъекции и скиллы в карточке (п. 7).
