# Ревью плана handoff-ownership — Fable 5.1

## 1. Вердикт

**СОГЛАСЕН С ПРАВКАМИ.** Диагноз верен и подтверждён бинарником и транскриптом, оба лекарства правильные; главная правка — историю 01 (починка `cd`-дрейфа) вынести в отдельную спеку и выпустить сейчас патчем 0.26.1, потому что `scripts/ship-check.sh:145-156` отказывает выпуску при открытой истории, а история 02 ждёт три несобранные истории `constitution-merge` (`constitution-merge-01..03.md:4` — все `status: todo`). В одной спеке живая ошибка владельца ждёт чужую работу.

## 2. По пунктам

**2.1 Диагноз — согласен.** `.claude/commands/vulyk-handoff.md:9,13` — единственные `!`-инъекции во всех командах (grep по `.claude/commands/` и `.claude/skills/`), обе с относительным путём. В бинарнике 2.1.296: `function Ior(e,n){let r=bo(e).cwd,s=we(),h=oVn();if(h||r!==s&&!Kg(r,n)){...op(s,e)...}}` — сброс только когда cwd ушёл из разрешённых каталогов (`n` = `unlayeredPermissions()`), иначе `cd` внутри проекта остаётся. Транскрипт `cf1d2449`: 16 строк `Shell cwd was reset`, а `"cwd"` записан как `<hive>\docs\specs\<client>\...` в 199 записях. Второй, скрытый баг тоже реальный: `handoff.py:84-91` (`project_root`: env → payload → `os.getcwd()`), `:1000-1003` (`payload["cwd"] = os.getcwd()` и транскрипт по слагу этого cwd), `:634-637` (`cwd = payload.get("cwd") or root`, транскрипт по `cwd`, не по `root`). Каталог `~/.claude/projects/<hive-slug>-docs-specs-<client>-...` не существует → транскрипт `None` → пустой скелет.

**2.2 `${CLAUDE_PROJECT_DIR}` — согласен, и аргумент сильнее, чем в плане.** Команда `/vulyk-handoff` видна только когда сессия запущена в каталоге, где лежит `.claude/commands/vulyk-handoff.md`, т.е. `${CLAUDE_PROJECT_DIR}` по построению равен улью. Значит «сессия, запущенная в подпапке» не «вне скоупа», а невозможна для этой команды — стоит так и записать в Assumptions. `${CLAUDE_SKILL_DIR}` не подходит: бинарник сбрасывает такие гранты для команд без своей папки (`skill_load_no_skill_dir_grants_dropped`). Подстановку в `allowed-tools` бинарник подтверждает (`w.map(Kn=>Kn.replaceAll(fAr,()=>bx(Wn)))` рядом с `skill_load_no_project_dir_grants_dropped`); подстановку в теле беру на веру по пробе планировщика.

**2.3 `handoff.py` «корень = улей, где лежит хук» — согласен.** Для `dump`/`status` это совпадает с `${CLAUDE_PROJECT_DIR}` (см. 2.2) и со слагом каталога транскриптов (`E--Projects-AI` есть в `~/.claude/projects/`). Хук-режимы не трогать — верно: там `CLAUDE_PROJECT_DIR` в env и `transcript_path` в payload. Прецедент у самого владельца: `~/.claude/hooks/context_guard.py:357-396` решает тот же дрейф якорем, не зависящим от cwd. **Правка (история 01, Implementation notes):** назвать строки `handoff.py:1000-1003` и `:635-637` — в `dump` и `payload["cwd"]`, и поиск транскрипта должны идти от корня, иначе AC 2 выполняется наполовину (файл ляжет в улей, транскрипта не будет).

**2.4 Тест в `tests/maintenance.test.sh` — правка.** `handoff.py:53-54`: `HOME = os.path.expanduser("~")`. На Windows Python ≥3.8 `expanduser` игнорирует `HOME` и берёт `USERPROFILE`, поэтому тест, который подкладывает транскрипт в временный `~/.claude/projects/<slug>/`, должен выставлять **и `HOME`, и `USERPROFILE`** на `$T`, иначе он либо лезет в настоящий `~/.claude`, либо тихо проходит без транскрипта. Добавить в AC 2.

**2.5 `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` — согласен, что не в плане.** В `Ior` при установленной переменной сброс идёт после каждого вызова и **без** сообщения (`if(!h)return i("tengu_bash_tool_reset_to_original_dir"...)` — телеметрия и сообщение только без неё). Включать это во все ульи для всех пользователей ради одной команды — Law 2; к тому же модель теряет подсказку «cwd сброшен». Чинить потребителя достаточно.

**2.6 Карточка дефекта — правки.** (а) Шлюз гонит `check:` каждой `block`-карточки на любой `<arg>` независимо от `paths:` (`defects-check.sh:262`: `if mode == 'gate' and status == 'block' and check`), а `paths:` читает только `defects-inject.sh`. Значит проверка обязана выходить 0 на любом не-командном файле и считать инъекцией только строку, начинающуюся с `` !` ``. (б) Соседняя фикстура: самая вероятная слепая зона grep по `bash ` — инъекция **без интерпретатора** (`` !`scripts/state.sh` `` или `` !`./x.sh` ``); требовать именно её, а не «другой интерпретатор». Проверка должна снимать кавычки (`"${CLAUDE_PROJECT_DIR}/..."`) и пропускать флаги (`bash -e`). (в) Фикстуры не `.md`: `load_cards` в обоих скриптах парсит все `*.md` каталога — `.fixture` в истории правильно, зафиксировать как требование. (г) `paths:` расширить до `.claude/commands/*.md, .claude/skills/**/SKILL.md` — скиллы тоже OWNED и несут инъекции. (д) Если однострочник потребует `grep -P`, разрешить `scripts/injection-check.sh <arg>` и внести его в Files сейчас, чтобы не ломать Law 3 посреди сборки.

**2.7 `skillOverrides` — согласен, с сильным подтверждением.** Бинарник: `"off" hides it from both`; и главное — `<hive>/.claude/settings.local.json` **уже** содержит `skillOverrides` с `statusbar*: "off"` для глобальных команд владельца. План повторяет практику самого владельца. Файл там LF без BOM, с ключами `model`, `enabledPlugins`, `skillOverrides` — контракт «все ключи сохранить» нужен и достаточен. «`/handoff` отвечает disabled» — приемлемо: явно, обратимо одним ключом, «работает только один» выполнено для команд и триггеров.

**2.8 Обнаружение по имени — согласен.** На этой машине единственное попадание — `~/.claude/commands/handoff.md`; в `~/.claude/skills/` хендоффа нет; `skill_router.py` слова handoff не знает. Шире (по `description:`) — спекуляция, Law 2. **Правка контракта:** «`HOME` решает» → `${CLAUDE_CONFIG_DIR:-$HOME/.claude}`: бинарник читает `process.env.CLAUDE_CONFIG_DIR` для пользовательского каталога.

**2.9 Хуки «только сообщать» — согласен (решение владельца), но правка формулировки.** Настоящий «двойной хендофф» — именно хуки: `~/.claude/settings.json` вешает `context_guard.py` на Stop/UserPromptSubmit/PreCompact/SessionEnd/SessionStart, VULYK — `handoff.sh` на те же события; оба пишут в `<улей>/.claude/handoff/` и оба на SessionStart восстанавливают. `skillOverrides` закрывает только вход через команду. AC 5 истории 02 должен требовать, чтобы `/vulyk-update` сказал владельцу прямо: «после own глобальный хук продолжит писать и восстанавливать хендоффы в этом улье» — иначе два баннера на старте выглядят как провал переключения.

**2.10 `handoff-owner.sh` отдельным скриптом — согласен.** Функцию внутри `install.sh` не вызовет `/vulyk-update` после апгрейда и не покроет тест; шаблон `telemetry_tty`/`telemetry_decide` (`install.sh:496-519`) переносится один в один.

**2.11 Последовательность — ГЛАВНАЯ ПРАВКА.** История 02 правит `install.sh` и `.claude/commands/vulyk-update.md`, которыми владеют `constitution-merge-02/-03` (todo) — ждать верно. Но `ship-check.sh:156` (`fail 03 ... still open - the build is not closed`) не выпустит спеку с открытой 02. Итог: 2-файловая починка живой ошибки ждёт 3 + 1 несобранные истории. **Предлагаю:** `docs/specs/handoff-cwd/` с историей 01 как есть (Tier 1–2, ничего общего с constitution-merge), выпуск 0.26.1 сразу; `handoff-ownership` остаётся спекой истории 02 → 0.28.0. Обходной путь владельца сегодня — глобальный `/handoff`, то есть ровно тот конфликт, который он просит убрать.

## 3. Чего не хватает

1. **Split по 2.11** — самое важное по влиянию на владельца.
2. **`USERPROFILE` в тесте (2.4)** — без этого AC 2 либо не проверяется, либо трогает настоящий `~/.claude`.
3. **Слепые зоны проверки (2.6 б)** — без фикстуры «без интерпретатора» карточка переобучена на оригинал.
4. Параллельные сессии в одном улье: `newest_transcript_for_cwd` (`handoff.py:420-431`) берёт самый свежий `.jsonl` по mtime — `/vulyk-handoff` может прочитать чужую сессию. Не этого плана, но в карточку/Next circle одну строку.
