## Request (verbatim)

> Короче, смотри, есть такая идея, например, в сам Wolek интегрировать такой функционал, чтобы он ввёл древовидную структуру, в которой будет одно направление — это разрешения markdown-файлов, другое направление — это запреты markdown-файлов, и третье направление — это правила. Как оно работает? Запреты — это строго-настрого то, что нельзя делать. И уже не раз мы проходили это, и оно стало как правило запреща ющее. То есть конкретно в таком виде, в таком элементе, неважно, что это: программа, логика, какие-то действия агента, они как запрет. Разрешение — это наоборот, то, что агент думал делать-не делать, но мы сказали: «Вот это 100% делать можно». И правило — это если в каких-то действиях, решениях, программе, чем угодно, что-то непонятно было, как делать, агент чуть-чуть неправильно делал, мы создали правило, как это нужно делать. Эти файлы могут быть по 1000, по 10 тыс. строк, поэтому нужно делать так, чтобы они были древовидные, хорошо индексировались и были максимально понятны для агента откашливается и были как Wiki-структура, чтобы очень быстро можно было понавигаться и найти. То есть нужно сделать обвязку, некий быстрый поиск внутри этих файлов, некое такое мини-ядро и наполнение самих этих файлов. Файлы должны попадать автоматически в разрешения, запреты, исходя из диалога, и также пополняться прямым текстом, когда пользователь говорит: «Вот это внеси в запрет, вот это внеси в правило, вот это внеси в разрешение». Что ты думаешь по поводу инт еграции такой методологии в Wolek? Есть ли что-то подобное у нас, если есть, в каком виде и как это всё можно улучшить? Здесь можешь запустить тройку для анализа между собой и грилевки, а также можете потом после своего анализа запустить SuperGrill и вместе со мной пройтись по валидации с максимальным учётом того, что уже внутри Wolek есть.
>
> Еще такой важный момент я вспомнил: у нас же есть литопис. Нужно, чтобы они максимально дружили, максимально друг друга дополняли, чтобы это не был конфликт и не была еще одна библиотека сверху существующей библиотеки.

## Decisions carried from the supergrill (owner's choices, each a recommended option he selected)

- D1 Цель: повтор записанного становится видимым и редким; витрина за минуту; агент не переспрашивает разрешённое.
- D2 Приватная память: проектные уроки → git проекта, личное остаётся приватным.
- D3 Разрешение — самостоятельная запись с областью и словами владельца; исключение из запрета только явной ссылкой + фикстура «проверка запрета на разрешённую форму не срабатывает».
- D4 Дерево: папки по областям, ветки Нельзя / Можно / Как надо — секции карточки, витрина генерируется.
- D5 «Как надо» — в карточках, доставка хуком; `.claude/rules` → один path-less файл, лимит ~40 строк.
- D6 Долг: красный для Нельзя / Как надо, счётчик для Можно.
- D7 Конфликт: разрешение побеждает только явным исключением, иначе запрет + красный.
- D8 Явная фраза «внеси в запрет / правило / разрешение» в любом канале, включая вставки; сессия пишет сразу.
- D9 Автонаходка во вставке — цитата после «да» владельца; метка программы диктовки — необязательная настройка.
- D10 Окна-вопросы: хук на ответ; дописанное — цитата, выбор варианта — решение, не цитата.
- D11 Автозахват без фразы: пишет сразу + строка-отчёт с «отмени».
- D12 litopys — история и недельная страховка, необязательный, в карточки не пишет.
- D13 Перенос приватной памяти: разовый разбор по ульям, пакетом на одобрение, без фальшивых цитат.
- D14 Поток: строка в конституции VULYK + правка глобального правила владельца (после его «да»).
- D15 Раскатка: пилот на 2 ульях ~неделю, потом все живые ульи.
- Плюс: область = пути + команды + инструменты; лимит доставки ~12 строк, узкая область первой; README генерируется, гейт красный при расхождении, команда поиска grep.

## Answers

1. litopys — Отдельно, следом (Рекомендую): litopys — отдельный репозиторий со своим релизом, а VULYK работает без него (решение D12). Эта работа фиксирует общий контракт (словарь, правила про вставки и окна), сразу после неё идёт маленькая спека в litopys.
2. Разбор — Режим /vulyk-gc (Рекомендую): новый шаг внутри уже существующей команды уборки памяти. Скрипт перечисляет приватные уроки, сессия раскладывает их на три кучи, ты одобряешь одним списком.
3. Требования — Всё верно, план на одобрение (Рекомендую).

## Asks

1. Три ветки (Нельзя / Можно / Как надо) — секции карточки в `docs/defects/`; карточки лежат в папках по областям.
2. Разрешение — самостоятельная запись с областью и словами владельца; перебивает запрет только явной ссылкой на него (с фикстурой «проверка запрета на разрешённую форму не срабатывает»); пересечение без ссылки — действует запрет, гейт красный.
3. Повтор по «Нельзя» и «Как надо» — долг, красный до проверки кодом; повтор по «Можно» — счётчик в витрине и /vulyk-status.
4. Область карточки = файлы + команды + инструменты (действия: отправка, публикация, браузер); правила, ни к чему не привязанные, — один всегда загружаемый файл в `.claude/rules/`, не длиннее ~40 строк.
5. Доставка: не больше ~12 строк на одно действие; первой — самая узкая область, затем свежая цитата; остальное одной строкой.
6. Витрина: сгенерированный индекс из трёх таблиц (запреты / разрешения / правила) по областям со счётчиками; гейт красный при расхождении с карточками; команда поиска по карточкам.
7. Фраза «внеси в запрет / правило / разрешение» (RU/UK/EN) в любом канале, включая вставки, — сессия сразу пишет карточку дословно; автонаходка без фразы — пишет сразу со строкой-отчётом и «отмени».
8. Автонаходка во вставке становится цитатой только после «да» владельца; метка программы диктовки — необязательная настройка, убирающая переспрос.
9. Ответы владельца в окнах-вопросах слышны: дописанный текст — цитата, выбранный вариант — решение, не цитата.
10. Заметки бокового агента («Here is a note offered by a side agent») никогда не считаются словами владельца.
11. Разовый разбор приватной памяти в карточки — режим `/vulyk-gc`: в карточку / личное / удалить, одобрение одним списком, без фальшивых цитат, перенесённое удаляется из приватной памяти.
12. Строка конституции: урок про код и процесс проекта — в `docs/defects/`, в авто-память — только личное.
