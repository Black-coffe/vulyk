## 2. How Hindsight actually works (from source)

Paths are under `github.com/vectorize-io/hindsight`, branch `main`, read 2026-09-29.

1. **Shape.** A server (`hindsight-api-slim/`, FastAPI + PostgreSQL/pgvector, or an embedded Postgres `pg0` started by `hindsight-embed` via `uvx`) with a background worker. The Claude Code plugin (`hindsight-integrations/claude-code/`, v0.7.5) is four hook scripts plus an MCP server; all intelligence lives in the server. The plugin marks itself deprecated in favour of `hindsight-integrations/coding-agents/` (v0.8.0, Node, `~/.claude/settings.json` hooks + `claude mcp add`), which seeds a per-repo bank from git history and maintains "knowledge pages".
2. **Hooks** (`hooks/hooks.json`): `SessionStart` → `session_start.py` (health probe, 5 s, kicks a background daemon pre-start; prints the deprecation `systemMessage`). `UserPromptSubmit` → `recall.py` (45 s timeout): query = the prompt (skipped under 5 chars), optionally the last N transcript turns, cut to 800 chars; `POST /recall` with `max_tokens=1024`, `budget=mid`, `types=["observation"]`; results wrapped in `<hindsight_memories>` under the preamble "Relevant memories from past conversations (prioritize recent when conflicting). Only use memories that are directly useful…"; emitted as `additionalContext`; the last recall is saved to state for re-injection after compaction. `Stop` → `retain.py` (async, 15 s): reads the transcript JSONL, keeps a turn counter in `~/.hindsight` state, and **every 10th turn** posts the unsent suffix of user+assistant messages (tool calls excluded) as one document tagged with the session id, with `retainMission` "Extract technical decisions, architectural choices, user preferences, project context…"; `<hindsight_memories>` blocks are stripped first (anti-feedback loop). `SessionEnd` → `session_end.py`: one forced retain, then stops the daemon it started.
3. **Retain, server side** (`engine/retain/`): one LLM call extracts facts with `fact_type` `world` (the user's preferences, rules, *corrections*, constraints) or `assistant`→`experience` (what the agent did), entities, and temporal fields (`occurred_start/end`, `mentioned_at`); dense embeddings + BM25 + entity links (`link_creation.py`); optional `memory_defense` PII/secret scan (45 regexes).
4. **Consolidation** (`engine/consolidation/consolidator.py`, 3 861 lines; `prompts.py`): a background job after every retain. Unconsolidated facts are fetched in batches per tag scope; for each batch the nearest existing observations are recalled and **one LLM call** returns `{creates, updates, deletes}`, every entry with a mandatory `reason` ("audited to catch duplicate creates"). Rules in the prompt: *prefer UPDATE over CREATE*, *one observation per facet*, *match by entity not topic*, *state changes update concisely*, *cascade*, *resolve references*, *preserve history – be very conservative with deletes*, *no computation* (never derive counts). An UPDATE (`_apply_update_action`, line 2948) rewrites the text and embedding, unions `source_memory_ids`, sets `proof_count = len(source_ids)`, widens temporal bounds (`LEAST/GREATEST`), merges tags, and appends an `_ObservationHistorySnapshot` (previous text, tags, dates, new source ids) to `observation_history`, capped by `observation_history_max_entries`. A CREATE whose embedding is ≥ 0.97 cosine to an existing observation goes through a second, focused LLM call ("merge or keep"; any differing number, entity, negation or condition → keep). Oversized/failed batches are split down to size 1.
5. **Mental models** (`engine/mental_model_refresh.py`, `engine/reflect/`): a user-defined question + tag scope. Refreshed after consolidation only when in-scope memories are newer than the model's `last_memory_seen_at` watermark, or by cron, or by hand; full or **delta** mode (structured ops applied to the existing document, each op recorded as applied/skipped; a refresh that would produce an empty candidate or whose ops all fail *refuses to write* and records the reason). Every version is kept with the facts it was built from. Reading one is a DB read, no LLM. Reflect-time observations inside a model carry `evidence[].quote` (an LLM-chosen exact quote) and a **computed `trend`** (`compute_trend`: new / strengthening / stable / weakening / stale from evidence timestamps, 30-day recent vs 90-day old window, density ratio 1.5 / 0.5) — arithmetic, no LLM.
6. **Recall** (`engine/search/`): four arms in parallel — pgvector semantic, BM25, graph link expansion, temporal window parsed from the query — each capped, merged by reciprocal rank fusion (k = 60; an interleave variant exists for dedup), cross-encoder reranked, trimmed to the token budget.
7. **Cost shape.** Per prompt: an embedding + four searches + a rerank (no LLM) and ~1 KB injected into the conversation, which is then re-sent on every later turn. Per 10 turns: one retain → one extraction LLM call + one consolidation LLM call per scope batch + dedup calls + mental-model refreshes. With `HINDSIGHT_LLM_PROVIDER=claude-code` each of those calls is a spawned `claude` CLI in an isolated `CLAUDE_CONFIG_DIR` (so the plugin's own Stop hook does not fire recursively — issue #1751), billed to the Pro/Max subscription and invisible to any transcript-based accounting in the project.

### Where VULYK is stronger

- **A lesson ends as code that fails, not as text that is recalled.** Law 6 / ADR-014: a checkable class becomes `check:` + two fixtures; a repeat without a gate is red. Hindsight never executes anything; a retained correction is prose in the next prompt — the exact carrier the YouTube_AI pilot proved loses three videos in a row. Hindsight has no equivalent of "never make the text louder" — its only escalation *is* louder recall.
- **Provenance is the owner's words, dated, blamed.** Hindsight's facts are LLM paraphrases; even the reflect-time "exact quote" is model-selected. `git blame` time on a quote line decides debt; nothing in Hindsight ties a belief to a human-signed sentence.
- **Zero runtime.** bash + python + git, works after clone on Git Bash; every hook fails open. Hindsight needs `uvx`, a daemon, an embedded Postgres, an embedding model, and a 45-second hook budget on every prompt.
- **Cost is bounded and visible.** Inject ≤ 4 000 chars once per session per card, no per-prompt search, target ≤ 1 % of session tokens; the constitution is capped by a failing test (ADR-016). Hindsight adds ~1 KB per prompt cumulatively plus LLM spend outside the project's accounting.
- **A human gate on belief change.** `revoked` only with the owner's words; always-on text grows only against owner-signed evidence; evolve changesets are merged or deleted by the owner. Hindsight's consolidator creates, rewrites and deletes beliefs autonomously.
- **Trigger by action, not by similarity.** `PreToolUse` on `paths:`/`cmd:` puts the rule in front of the agent at the moment it edits the file the rule is about — Anthropic's own "memory is context, not enforcement; use a PreToolUse hook" (grill 09-27 fact ledger). Prompt-similarity recall misses corrections whose trigger is a file, not a topic.

### Where Hindsight has something VULYK lacks

1. **The confirmation count is shown to the reader and drives ordering.** `proof_count` rides on every recalled observation. VULYK's inject line shows `id — title` + `✗` lines with no count and no ordering; under the 4 000-char budget the overflow is cut in file-name order. The grill 09-27 routine decision specified `«… · повторов 3», сортировка по повторам×свежести` — the code never got it.
2. **Staleness computed from evidence dates, deterministically.** `compute_trend` (new / strengthening / stable / weakening / stale, 30/90-day windows) costs no model call. VULYK's defect audit knows "old debt" and "new debt" but has no "stale" signal for a `text` card nobody has repeated in months — the prune signal the RRSI report deferred "until cards exist".
3. **A refresh that would collapse a document refuses to write and records why** (`refresh_failed_empty_candidate`, `delta_ops_all_skipped`, `content_preserved_no_new_facts`). `/vulyk-gc` lets the librarian rewrite `CONSOLIDATED.md` wholesale ("at most 40 entries, newest evidence wins") and the main session commits without a size check — the ACE "context collapse" case (18 282 → 122 tokens) the grill 09-27 recorded as a risk. One clean run so far (2026-09-29, 4 files → 15 entries).
4. **Duplicate-belief guard at write time** (`_duplicate_create_target`, 0.97 dedup + "merge or keep"). VULYK's intake lists "Matched classes" by `keys:` substring, but nothing audits two live cards that cover the same class.
5. **A tested rule set for merging facts into beliefs** (`prompts.py` PROCESSING RULES 1–9). litopys phase 3 (topic consolidation into a root index) has no consolidator yet; these rules are a ready spec for its prompt.
6. **Semantic + BM25 + graph + temporal recall with RRF** for "what did we decide about X". litopys does navigation + grep on demand. Grill 09-21 D5/D15: vectors only when the golden-question metric says navigation is not enough. Hindsight's benchmark (LongMemEval, synthetic long chats) is not that metric, so this is **not new evidence** — noted, not re-proposed.
7. **Recursion isolation for spawned `claude` calls** (`CLAUDE_CONFIG_DIR` scratch dir + `CLAUDE_SECURESTORAGE_CONFIG_DIR=""` so OAuth still resolves). litopys `bench` forks `claude -p --plugin-dir …` from the host cwd (ADR-002); I found no isolation there, so the bench session is itself journaled by litopys hooks and runs the host's VULYK hooks.

## 4. Proposals

Everything below borrows a *mechanism* and lands in files that exist today. No new runtime, no new dependency, no always-on bytes. Items 1 and 3 are the only ones I would build now; 2 has a date, 4–5 belong to litopys.

### P1 — Evidence count on the injected card, and ordering by it (VULYK, Tier 1)

- **Borrowed:** `proof_count` shown beside every recalled observation; the most-confirmed belief is what survives the token budget.
- **Where:** `.claude/hooks/defects-inject.sh` (the card header line becomes `id — title · N quotes, last YYYY-MM-DD`; `hits` sorted by quote count desc, then last quote date desc, *before* the 4 000-char cut so the overflow list holds the least-repeated cards); `tests/inject.test.sh` (+2 cases: the count appears; under budget a 3-quote card is shown and a 1-quote card is listed). Quote lines are already parsed by `defects-check.sh` (`^- \d{4}-\d{2}-\d{2} ·`); reuse that regex in the hook's shared parsing block (kept identical in both hooks by contract). Owner: VULYK.
- **Why it does not harm the concept:** it is the grill 09-27 routine decision ("одна строка на запрет … · повторов 3, сортировка по повторам×свежести") that the 0.19 build left out; ADR-014 D6 keeps text cards pushed before the action; a number is not "louder" text, and a card that earns `block` still leaves the injection entirely (Law 6). No always-on growth (ADR-016).
- **Cost / risk / measure:** ~30 chars per injected card, once per session; ~20 lines of python; no deps. Risk: none beyond the hook's own tests. Measure: `tests/inject.test.sh` green; inject bytes still ≤ 1 % of session tokens in the 4-week pilot number (`docs/specs/self-learning/plan.md` §1.9).

### P2 — Deterministic staleness and overlap lines in the defect audit (VULYK, Tier 1, not before 2026-12-27)

- **Borrowed:** `compute_trend` — a belief's freshness from its evidence timestamps, arithmetic only; and the write-time duplicate guard.
- **Where:** `scripts/defects-check.sh` audit mode (`I` lines only, never red): `stale <id>: text card, last quote <date>, no repeat in 90 d` for `text` cards; `overlap <a>, <b>: share keys: <k>` for two live cards; `tests/defects.test.sh` (+2 fixtures). `.claude/commands/vulyk-evolve.md` step 3 lists both as prune/merge candidates, cited in the ledger row's `--evidence`. Owner: VULYK.
- **Why it does not harm the concept:** it is information for the weekly human-gated cycle, like "old debt" lines today — not a warn-check on work (Law 6 is about checks of the owner's work). `block` cards are exempt: silence is their job (RRSI report §8, "block-проверку не удалять за молчание"). Deletion stays with the owner through the evolve changeset (`docs/self-evolution.md`, deletion-biased).
- **Cost / risk / measure:** ~25 lines of python in a script nobody loads into context; zero tokens. Risk: noise on a young library — hence the date: the library was born 2026-09-27, the 90-day window is empty before then (Law 2: do not build a signal with no data). Measure: cards revoked or merged by an evolve run that cites the line, n reported.

### P3 — A GC pass that would collapse `CONSOLIDATED.md` refuses to commit (VULYK, Tier 0)

- **Borrowed:** the mental-model refresh outcome discipline — a rewrite that would empty or gut a standing document does not persist; it records why and leaves the old version.
- **Where:** `.claude/commands/vulyk-gc.md`, the commit step: before `git commit`, the main session compares entry count and bytes of `memory/learnings/CONSOLIDATED.md` (`git diff --stat`, `grep -c '^[0-9]*\. '`); if the file lost more than half its entries or bytes, do not commit — print one line with the two numbers and show the diff to the owner. Two sentences in the command; optional one check in `tests/maintenance.test.sh` `green_of` style. Owner: VULYK.
- **Why it does not harm the concept:** ADR-017 already puts destructive steps in the main session; grill 09-27 recorded ACE's context collapse as a risk and chose "слияние скриптом, не моделью" for lesson files; `/vulyk-gc` runs unattended after the owner's task (auto-maintenance), which is exactly when a silent collapse would go unnoticed. Loaded only when the command runs (not always-on).
- **Cost / risk / measure:** ~150 bytes in a command file, no deps. Risk: a legitimate large consolidation stops for a look — that is the intended stop. Measure: never fires on a healthy pass; when it fires, the diff shows why.

### P4 — Consolidation rules and a `sources:` count for litopys's topic consolidator (litopys, roadmap phase 3; VULYK cost 0)

- **Borrowed:** `consolidation/prompts.py` PROCESSING RULES as the spec for litopys's future consolidator agent: prefer update over create; one topic note per facet; match by entity, not topic; state changes update concisely; preserve history, delete only when restated identically; **no computation**; every op carries a `reason` and verbatim source refs (session record paths, as `--links` already demands). Plus a frontmatter `sources: N` on topic notes = the number of session records behind the note (Hindsight's `proof_count`), and `last_seen: <date>` for the root index's ordering.
- **Where:** litopys `agents/consolidator.md` (does not exist yet), the root-index generator of phase 3, `docs/adr/` there. Owner: litopys; VULYK only reads the index (grill 09-21 D3/D9).
- **Why it does not harm the concept:** grill 09-21 D5 (navigation + grep first) is untouched — this is how notes are *written*, not how they are found; ADR-006 (no hook model calls) holds because consolidation stays a skill-driven agent. Sonnet, ≤ 5 % cap (D12).
- **Cost / risk / measure:** nothing now; a prompt section when phase 3 is built. Risk: rules tuned for personal-assistant facts over-merge project decisions — the "match by entity" rule and mandatory `reason` are the guard. Measure: golden-question hit rate vs. baseline (D10/D15), already the plan.

### P5 — Isolate `claude -p` spawned by litopys `bench` from the host's hooks (litopys, Tier 0)

- **Borrowed:** `claude_code_llm.py` runs the spawned CLI with a scratch `CLAUDE_CONFIG_DIR` and `CLAUDE_SECURESTORAGE_CONFIG_DIR=""` so plugin hooks do not fire inside the subprocess while `claude auth login` credentials still resolve (issue #1751 in their tracker).
- **Where:** litopys `bin/litopys` `cmd_bench`; a line in ADR-002 "Revisit when". Owner: litopys.
- **Why it does not harm the concept:** ADR-006 already forbids recursion from hooks; this closes the same hole from the CLI side. The bench must load `--plugin-dir` for `/litopys:recall`, so test whether a scratch config dir keeps that and OAuth — Hindsight's note says it needs CLI ≥ 2.1.150.
- **Cost / risk / measure:** two env vars; risk that a scratch config dir loses auth on this box — a one-run test. Measure: after a bench run, `.litopys/raw/` gains no journal for the bench session and `memory/stats/anomalies.jsonl` shows no hook rows from it.

Considered and dropped as already covered: a watermark for map slices (`/vulyk-status` step 5 does it per module from git); re-injection after compaction (`defects-inject.sh reset`); "prioritize recent when conflicting" preamble (`revoked` + the overlap line); observation history snapshots (git); secret scan (`redact.sh`); bank mission (the Profile); knowledge pages projected to disk (`memory/map`, `docs/wiki`, litopys records are already files).

## 5. Rejected — what must not be taken

1. **Installing Hindsight or its plugin in a hive.** It breaks the strongest prior: a daemon (`uvx hindsight-embed`), an embedded Postgres, an embedding model, a 45 s `UserPromptSubmit` hook on every prompt, and ~1 KB injected per prompt that is then re-sent every turn — against the ≤ 1 % injection cap and ADR-013's economy. Its LLM calls (extraction every 10 turns, consolidation, dedup, refreshes) run under a separate `CLAUDE_CONFIG_DIR`, so `scripts/token-report.py` would never see the spend. The plugin the post recommends is deprecated by its authors as of the repo's `upgrade_notice.py`, and its successor rewrites `~/.claude/settings.json` at user scope — outside any hive's git. `claude-code` provider is labelled "personal/local use only" by Hindsight; VULYK ships to 16+ hosts. Windows: an embedded Postgres per developer box is a support burden VULYK's fail-open hooks were designed to avoid.
2. **A vector server or embeddings for `docs/defects/` or the chronicle.** Grill 09-21 D5/D15 and `docs/memory-system.md` ("structure-first, embeddings-optional") stand. Hindsight's LongMemEval numbers measure conversational QA on synthetic long chats, not "did the agent stop repeating the owner's correction" — not the metric that would reopen D15. No new evidence, not re-proposed.
3. **LLM extraction of corrections from the transcript (Stop/UserPromptSubmit or a per-prompt classifier).** ADR-014 rejected the classifier (P 0.43 / R 0.58, cost); Hindsight's retain is exactly that classifier with no published precision for corrections. Its `world` fact "User corrected the project deadline" is a paraphrase; VULYK's card needs the owner's words. The intake regex stays; litopys's distiller catches the misses at the boundary.
4. **A model that rewrites, merges or deletes beliefs on its own** (the consolidator's `updates`/`deletes`, a mental model that "rewrites itself"). Grill 09-27 D13: a prohibition is lifted only with the owner's words and date; RRSI report §5.2: always-on text grows only against owner signature. A self-rewriting `CLAUDE.md` — the post's "CLAUDE.md that maintains itself" — is the banned prose carrier with the human gate removed.
5. **Prose recall as the carrier of lessons.** Hindsight has nothing that fails a build. Copying its recall shape would move VULYK back to the state the pilot measured: lesson present in context, defect shipped anyway. Law 6 and "a check that only warns is not a check" are the reason VULYK exists as a self-learning system at all.
6. **One shared bank across projects by default.** VULYK's memory is per host, in git; the personal tree (grill 09-27 D16) is deferred until hosts show the need. Cross-project leakage of one client's corrections into another's session is the failure mode Hindsight solves with `dynamicBankId`, which is off by default.
7. **Model calls inside hooks, even indirectly.** Hindsight's Stop hook does no LLM work locally but posts to a daemon that does, on a 15 s async budget. The owner's rule (no model calls in SessionEnd; model work in SessionStart, PreCompact or a command; litopys ADR-006) is not satisfied by moving the call across a socket.
8. **The reflect-time "exact quote" as evidence.** It is chosen by the model from a paraphrased fact. VULYK's quote line is the owner's sentence, typed by the owner, blamed by git. Do not let an agent write `## Owner quotes`.

## 6. Top-3

1. **P1** — show the quote count on each injected card and order cards by (count, recency) before the budget cut: the grill's own unbuilt decision, Tier 1, ~20 lines in `defects-inject.sh` + 2 tests.
2. **P3** — `/vulyk-gc` refuses to commit a `CONSOLIDATED.md` that lost more than half its entries or bytes, shows the diff instead: Tier 0, two sentences in the command, closes the ACE collapse risk in the one unattended rewrite VULYK still runs.
3. **P2** — deterministic `stale` / `overlap` info lines in `defects-check.sh` audit for `text` cards, feeding evolve's prune — Tier 1, but not before 2026-12-27; until then it is a signal with no data.

Everything else from Hindsight is either already in VULYK in a stronger, code-backed form, or belongs to litopys (P4, P5), or is rejected in §5.
