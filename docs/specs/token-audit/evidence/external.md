## Implications for VULYK

One line per principle: principle → what current guidance says (claim #) → verdict. "Outdated" means current
Anthropic guidance contradicts it for the models VULYK now runs (Opus 5.5 / Fable 5.1); "weakened" means the
premise or cost model changed; "valid" means current guidance supports it.

**Structure and delegation**

1. **Law 5 — every edit to story files goes through a worker, "including the two-line fix"** → main conversation for "a quick, targeted change" and when phases share context (1.8); "Do not delegate work you can finish yourself in a handful of tool calls" (3.5, a line VULYK's own CLAUDE.md already quotes); handoffs are state-lossy and cost several times the tokens (2.3, 2.8). Each worker re-pays ~6-7k tokens of CLAUDE.md plus its own file reads into a fresh 5-minute cache (1.1, 1.9, 1.10). → **Outdated** for small fixes; the "Queen context never refreshed" argument is real but a two-line diff costs far less in the Queen than a worker spawn.
2. **Split `worker-code` / `worker-test` / reviewers by type of work** → Anthropic names "one agent writes features, another writes tests, a third reviews code" as "often counterproductive"; decompose by context, not by work type (2.4); the builder writes its own tests (7.5). → **Outdated.**
3. **Tier table: Tier 2 = 2-4 workers, Tier 3 = 4-8 workers + full court, Tier 4 = + architect + second reviewer** → multi-agent costs 3-10x a single agent for equivalent tasks (2.2); worth it only for context pollution, true parallelism, or tool specialization (2.6); workflows/teams cost "meaningfully more" (1.12, 1.13); independent evaluation finds most MAS trail a single-agent anchor (7.8). → **Outdated as a default**; still valid for genuinely parallel, file-disjoint multi-module work.
4. **Council at every Tier 1+ ("shrinks with the tier, never to zero")** → Opus 5/5.5 self-verify; "legacy harness scaffolding that adds separate verification steps" causes over-verification (3.1, 3.2); Claude Code stopped auto-running `/verify` and `/code-review` (3.3); Anthropic's own harness found the evaluator "unnecessary overhead" inside the model's capability boundary (7.3). → **Outdated at Tier 1-2.** At Tier 3-4 one fresh-context reviewer on the diff is endorsed (3.4, 7.4, 7.7).
5. **Council seats must reach unanimity; RED on half the asks re-opens rounds** → "A reviewer prompted to find gaps will usually report some, even when the work is sound … Chasing every finding leads to over-engineering"; tell reviewers to flag only correctness/requirement gaps (3.4). → **Weakened**: matches the owner's "one or two extra circles"; three seats triple the chance of a spurious RED.
6. **`council-haiku` black-box seat (walks the client path, reads no source)** → "Blackbox verification" is one of the few boundaries Anthropic calls effective (2.4); browser-verified evaluator is in Anthropic's harness (7.4). → **Valid** where a client path exists; the seat's value is external evidence, not a second opinion.
7. **Model diversity in the court (`council-sonnet` stays Sonnet)** → guidance attributes the reviewer's value to a **fresh context**, not a different model (BP writer/reviewer, 7.7); different models also never share cache (5.6). → **Unsupported by current guidance** (neither confirmed nor refuted); not a reason on its own to keep an extra seat.
8. **Queen never reads source; always request `drone-scout` reports** → "use subagents to investigate" is endorsed for broad exploration (7.6, BP); for a targeted read it is overhead (1.8). Built-in Explore skips CLAUDE.md and git status (1.1), custom `drone-scout` does not. → **Partly valid**: keep for wide recon, drop for single-file lookups; consider `omitClaudeMd` or Explore for scouts.
9. **"Scoped context: a worker receives its story file plus the map slice — never the whole project"** → every non-fork subagent loads the full CLAUDE.md hierarchy, AGENTS.md and a git-status snapshot anyway (1.1); `omitClaudeMd: true` exists since v2.1.271 (1.2). → **Premise false today**; fixable with `omitClaudeMd` on agents that take everything from the delegation prompt.
10. **Workflow driver runs the cycle (build → council → repair)** → workflows are meant for "dozens to hundreds of agents" and cost more than conversation (1.12); workflow agents get a 5-minute cache (1.9) and share a prefix only with same model/effort/agent type/tools/schema (1.11), which VULYK's heterogeneous roster rarely satisfies; a 3M-token task is 2x the `Large workflow` warning threshold (1.5M). → **Weakened**; the orchestration pattern is legitimate but mis-sized for single-module tasks.

**Prompting and instructions**

11. **"Do not add instructions telling an agent to verify itself"** → exactly Anthropic's Opus 5 guidance (3.1, 3.2). → **Valid** (but contradicted by principle 4 at the harness level).
12. **"Working with a frontier model" section (scope line, delegation-restraint line, artifact length)** → verbatim Anthropic Opus 5 snippets (3.5, 3.7, 3.10); Opus 5.5 guide says Opus 5 patterns remain a good starting point. → **Valid.**
13. **Five Laws #1 "If requirements are ambiguous, ask before acting"** → Opus 5 / Fable 5.1 guidance: "make routine judgment calls yourself, and check in only when different readings … would lead to materially different work"; do everything that doesn't depend on the answer first (3.7). → **Weakened**; VULYK's own frontier section already carries the newer rule, so the two conflict.
14. **Laws #2 no overengineering / #3 no out-of-scope edits** → scope creep is the documented Opus 5 / Fable 5.1 failure and the stay-in-scope instruction is the fix (3.7). → **Valid.**
15. **CLAUDE.md size and tone (VULYK 211 lines + AGENTS.md import; owner's global 97 lines with four "🔴 MANDATORY" blocks)** → target <200 lines per file, imports still load, bloat makes Claude "ignore your actual instructions" (5.1, 3.12); emphasis only on the one line Claude keeps skipping (3.6); aggressive CRITICAL/MUST language over-triggers on current Opus (3.6). All of it is re-loaded by every subagent (1.1). → **Outdated**; move workflow-only sections to skills (5.3), strip maintainer notes into HTML comments (5.1), de-shout.
16. **Path-scoped rules in `.claude/rules/` with `paths:`** → load only when matching files are read (5.1, MEM). → **Valid.**

**Effort, models, caching**

17. **Effort in agent frontmatter: drones/librarian `low`, workers `medium`, planner/gate `high`** → works since v2.1.267 (1.4); `low` is documented for subagents (4.2); Opus 5.5 `medium` ≥ Opus 5 `high` (4.3). → **Valid.** `"effortLevel": "medium"` in `.claude/settings.json` does nothing on Opus 5.5 (4.5).
18. **"`max` only after a real failure"** → "Reserve `xhigh` and `max` for work where you've measured a quality gain" (4.3). → **Valid.**
19. **"Changing the level mid-session drops the cached prefix" / set `/effort` once** → on Opus 5.5 and Fable 5.1 (Anthropic API, subscription or key) changing effort keeps the cache (4.6). → **Outdated** for the current ladder; still true on other models and on Bedrock/Vertex.
20. **Route models by frontmatter and dispatch parameter, never `/model` mid-session** → a model switch re-reads the whole history uncached; a skill whose frontmatter names another model is also a switch; Anthropic's own advice is to hand off to a subagent instead (5.6, PCBLOG). → **Valid.**
21. **Command output is permanent; use quiet commands** → long context is re-read every request at the cached rate and cache reads count toward plan usage (6.2, 5.9); hook output capped at 10,000 chars (5.4). → **Valid.**
22. **`/clear` between tiers; `/rewind` rather than `/compact`** → `/clear` "costs nothing", `/rewind` hits an existing cache entry, `/compact` is a large request (5.8, 5.9). → **Valid.**
23. **Session budget "past ~10 turns of a debugging loop without progress, stop"** → Anthropic: after **two** failed corrections, `/clear` and re-prompt (5.9); unattended loops should cap auto-continuations at 2-3 (3.11). → **Valid in spirit, threshold too loose.**
24. **Long-running subagents on slow commands (e.g. `council.test.sh`, ~10 min per run on Windows per the project memory note)** → subagent cache TTL is 5 minutes by default even on Max (1.9, 5.5); a subagent idle on a >5-minute Bash call pays a full cache re-write on its next request. → **New risk** not covered by any VULYK principle; `subagentPromptCacheTtl: "1h"` or shorter test runs address it.
25. **`UserPromptSubmit` handoff hook adding `additionalContext`** → injected text is inserted and saved into history at each firing and re-read on every later request (5.4). → **Weakened** unless the hook stays silent on most prompts.
26. **Model ladder: Opus 5.5 workhorse, Fable only at the gate/hard plans/retries** → Anthropic: "start with Claude Opus 5.5 for most workloads" (ladder report row 4); Fable on Max capped at ≤50% of weekly usage (6.5). → **Valid.**
27. **Plan stops for approval; Tier 0 does it directly** → explore/plan/implement is the recommended loop, but "If you could describe the diff in one sentence, skip the plan" (7.2). → **Valid**; the Tier 1 mini-brief + worker + council is heavier than Anthropic's recommended path for a one-module change.
28. **Memory protocol (`memory/memory.md` index, librarian-only writes)** → structured note-taking and agent-maintained progress files are recommended (7.5, 7.6); Claude Code's own auto memory is not loaded into subagents (5.11). → **Valid**; keep the index short (auto-memory analogue caps at 200 lines/25 KB).

Net reading: the principles about **what to say** to the model (scope, no self-verify instructions, effort per
role, cache hygiene) match current guidance. The principles about **how many agents to run** (Law 5, per-type
workers, a council at every tier, unanimity rounds, the workflow driver for single-module work) are the ones
current Anthropic guidance contradicts, and they are where the 3-10x multi-agent overhead (2.2) comes from.
