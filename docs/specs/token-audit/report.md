- deliverable: document (study work) · дата: 2026-09-26 · автор: Queen (Opus 5.5)
- статус: **ждёт решения владельца**. Код не менялся. Превратить отчёт в код можно так: `/vulyk-plan` на
  раздел 7 своими словами.
- доказательства (по три агента, с `path:line` и скриптами):
  `evidence/forensics.md` — замер по транскриптам: 1 844 сессии, 4 998 транскриптов субагентов,
  174 прогона Workflow;
  `evidence/architecture.md` — чтение кода и конфигурации v0.17.0 (`cb3b90c`);
  `evidence/external.md` — текущие рекомендации Anthropic, по два источника на утверждение;

## 0. Коротко

1. **«3 млн» — это заниженная цифра.** Workflow печатает `totalTokens` как сумму *последних контекстов*
   агентов, а не обработанные токены. Медианная задача за 13 дней реально обработала **84.9M токенов**
   (13.5M во взвешенной оценке стоимости), то есть примерно в 29 раз больше напечатанного. Без самого
   репозитория VULYK — 96.4M / 15.8M. Claude Code сам считает стоимость сессии: медиана **$45** с VULYK
   против **$19** без него.
2. **Деньги делятся на три почти равные трети:** Queen 30.5%, workers 30.4%, контроль 30.7% (совет
   13.4%, `lead-review` 9.7%, клерки 7.6%). Работа, ради которой всё затевалось, — только треть.
3. **Каждый субагент стартует с 27–36k токенов**, и почти все они — свежая запись в кэш. Примерно 85%
   этого старта — пакет инструкций, который наследует каждый субагент: `CLAUDE.md` + `CLAUDE.vulyk.md` +
   глобальный `~/.claude/CLAUDE.md` + auto-memory `MEMORY.md`. Этот фиксированный пакет, перечитанный
   на каждом ходу, — **23% всех расходов**. У медианной задачи **67 диспатчей, из них 43 — `cycle-clerk`**,
   субагент, который запускает одну shell-команду и возвращает одну строку JSON.
4. **Круги — это нормальный путь, а не сбой.** 82% спек проходят ≥2 раундов. С первого раунда GREEN —
   только 32%, и половину из них судили повторно (8 раундов, все GREEN). Главная причина RED —
   **`lead-review` BLOCK: 39 из 64** не-GREEN раундов, в 14 из них он единственная причина. Лишние
   круги съедают **29.5%** расходов задач, где они были; медианный лишний раунд — 3.05M взвешенных.
5. **56% прогонов драйвера (96 из 172) останавливаются до вердикта**, и Queen их перезапускает. Медиана —
   3 запуска на задачу, ~21 ч календарного времени на задачу против ~2 ч у сессий без VULYK.
6. **В текущей v0.17.0 есть петли без ограничителя.** Одна — тайм-аут `close-story` → повторный worker.
   Другая — ревью без строки `VERDICT:` → повторный диспатч ревью: в katan **44 `lead-review` вместо 6**.
   Всего лишние ревью стоили 200M сырых / 31M взвешенных токенов.
7. **По Anthropic на сентябрь 2026 устарело не то, *что* VULYK говорит модели, а *сколько агентов* он
   запускает.** Правила про scope, «не проси себя перепроверять» и effort по ролям совпадают с текущими
   рекомендациями. А Law 5, разделение workers по типу работы, совет на каждом тире, единогласие и
   Workflow для одномодульной задачи Anthropic прямо называет антипаттернами или «over-verification»
   (раздел 5).
8. **Рекомендую вариант A** (раздел 6): сначала закрыть утечки, потом облегчить цикл. Моя оценка — минус
   40–55% токенов на медианную задачу, это примерно паритет с работой без VULYK. Это оценка, а не
   замер; проверить её тем же скриптом после релиза.

## 1. Что на самом деле значит «3 млн»

| Мера на задачу (44 задачи с циклом, 13–26.09) | медиана | p75 | max |
|---|---|---|---|
| напечатанный `totalTokens` Workflow (цифра владельца) | 2.56M | 3.96M | 17.2M |
| сырые токены (input + cache write + cache read + output) | **84.9M** | 188.6M | 577.1M |
| взвешенные (read ×0.1, write ×1.25/×2, output ×1) | **13.5M** | 27.6M | 87.3M |

- `tokens` у 99.6% из 2 798 агентов Workflow совпадает с их последним запросом с точностью до 2%
  (`evidence/forensics.md` §0, `item0_check.py`). Агент на 40 ходов учтён один раз.
- Сессия Queen в `totalTokens` не входит вообще.
- 95.4% сырых токенов — чтения из кэша. Они **засчитываются в лимиты Pro/Max** по сниженной ставке
  (external 6.2 ✅). Точный вес кэшированного токена в лимите Anthropic не публикует (❓).
- Парсер сверен с учётом самого Claude Code (`cost-state`): медиана — 95.5% от харнесса. Все цифры здесь
  слегка *занижены*.

## 3. Почему круги

| Причина | Цифра | Механизм |
|---|---|---|
| `lead-review` BLOCK | 39 из 64 не-GREEN раундов, единственная причина в 14 | Промпт «find reasons this change should NOT merge», «report everything», BLOCK на любой major. Каждый раунд — свежий агент на Fable, effort high, на *всей* ветке плюс ADR-001 (34.5 KB). Он каждый раз находит *новые* majors, а `no-progress` ловит только повтор того же ask (`lead-review.md:10,30,34,40`, `cycle.sh:925-936`). Anthropic: ревьюер, которого попросили искать пробелы, «will usually report some, even when the work is sound» (external 3.4 ✅) |
| GREEN → любой коммит → новый раунд | 6 из 12 GREEN-с-первого-раза судились повторно: 8 раундов, все GREEN | Устаревание бинарное по всей ветке. Релизный коммит (`VERSION`, `CHANGELOG.md`) не в белом списке (`ship-check.sh:203-204`, `lib.sh:42-52`) |
| места совета упираются в `maxTurns: 60` | p90 вызовов council-sonnet/opus = 60; 67 событий «seat returned empty» в 39 прогонах | Пустое место → переспрос или ABSENT → ESCALATE `env`. `council-sonnet` был GREEN в 80 из 101 раундов |
| ревью без `VERDICT:` → повторный диспатч | katan, Tier 4, v0.17.0: 20 ревью в одном раунде, 44 на спеку | `record-seat` возвращает не-JSON, драйвер отправляет `dispatch:review` снова, счётчика нет (forensics §5d) |
| `reopen` ведёт в `open-round`, а не в `repair` | — | перезапуск пересуживает неизменённый код и получает тот же BLOCK (`cycle.sh:2121,2133`) |

Цена раунда: медиана 7.3M сырых / 1.46M взвешенных. Внутри раунда `lead-review` берёт 34%,
`council-sonnet` 24%, `council-opus` 16%, клерки 16% (~12 штук), `council-haiku` 9%.

## 4. Сравнение с проектами без VULYK

| Изменено строк кода | VULYK ÷ без VULYK, взвешенные токены | VULYK ÷ без VULYK, активное время |
|---|---|---|
| 101–500 | **1.0×** (6 vs 7 выборок) | 1.3× |
| 501–2 000 | **2.2×** (14 vs 10) | 2.1× |
| 2 000+ | **2.3×** (18 vs 7) | 2.8× |

- На сопоставимом объёме кода VULYK дороже в **2.2–2.3 раза и медленнее в 2–3 раза**, начиная с 500 строк.
  На малых изменениях — паритет.
- Ваши «5×» видны по календарному времени (21 ч против ~2 ч) и на плохих задачах. Например, mmorpg
  `web-bridge-p1`: $153.89, 6 раундов, ESCALATE, а stories 17–19 Queen доделала вручную.
- Выборка слабая: группа без VULYK — в основном READINESS и senseti-doker. Считайте ±30%
  (forensics §6).

## 5. Что устарело по сравнению с Anthropic (сентябрь 2026)

Все пункты подтверждены двумя независимыми источниками (✅). Полные цитаты и URL — в
`evidence/external.md`.

| Принцип VULYK | Что говорит Anthropic сейчас | Вердикт |
|---|---|---|
| Law 5: любая правка story-файлов — через worker, «включая фикс в две строки» | Для быстрой точечной правки и когда планирование, реализация и тесты делят контекст, работать в основной сессии (1.8). Мультиагент — **3–10× токенов** против одного агента на ту же задачу (2.2) | **устарело** для мелких правок |
| `worker-code` / `worker-test` / ревьюер — деление по типу работы | «One agent writes features, another writes tests, a third reviews code» — «often counterproductive». Делить нужно по контексту (2.4). Раздельные агенты на plan/execute/review/iterate «spent more tokens coordinating than executing» (2.3) | **устарело** |
| Совет на каждом Tier 1+, «никогда до нуля» | Opus 5/5.5 проверяет себя сам. «Legacy harness scaffolding that adds separate verification steps» даёт over-verification (3.1). Claude Code с v2.1.215 перестал сам запускать `/verify` и `/code-review` (3.3). Evaluator внутри возможностей модели — «unnecessary overhead» (7.3) | **устарело на Tier 1–2**. На Tier 3–4 один ревьюер со свежим контекстом одобрен (3.4, 7.4) |
| Единогласие; ревьюер ищет «причины не мержить» | Ревьюеру отмечать только то, что влияет на корректность или заявленные требования, остальное — опционально (3.4) | **ослаблено** |
| «Scoped context: worker получает story + map slice» | Каждый субагент грузит всю цепочку CLAUDE.md, AGENTS.md и git status (1.1). Флаг `omitClaudeMd` появился в v2.1.271 (1.2); ни один из 13 агентов VULYK его не ставит | **посылка ложна** |
| Workflow-драйвер для любой задачи с тиром | Workflow «can use meaningfully more tokens than … in conversation»; предупреждение «Large workflow» при >25 агентах или >1.5M токенов (1.12). У медианной задачи VULYK 67 агентов | **ослаблено**: паттерн законный, но не по размеру задачи |
| `CLAUDE.md` на 211 строк; в хостах `CLAUDE.vulyk.md` ещё 15–31k символов; много MUST/NEVER; глобальный файл с четырьмя 🔴 MANDATORY | Держать <200 строк на файл, `@import` не экономит (5.1). Раздутый файл заставляет Claude игнорировать инструкции (3.12). CRITICAL/MUST даёт over-triggering на текущих Opus; выделять одну строку (3.6). И всё это грузится в каждый субагент (1.1) | **устарело** |
| «Смена effort посреди сессии роняет кэш» | На Opus 5.5 и Fable 5.1 больше не роняет (4.6) | **устарело** |
| `"effortLevel": "medium"` в `.claude/settings.json` | Верхнеуровневый `effortLevel` на Opus 5.5 не действует (4.5) | **мёртвая настройка** |
| Долгие ожидания субагента (сьют ~10 мин в `close-story`) | Кэш субагентов и агентов Workflow живёт 5 минут даже на Max (1.9). После простоя >5 мин — полная перезапись. Есть `subagentPromptCacheTtl` | **новый риск**, не покрыт |
| Law 1 «спроси, если неясно» | Рутинные решения принимать самому, спрашивать только когда прочтения ведут к разной работе (3.7). Раздел VULYK «Working with a frontier model» это уже говорит — два правила конфликтуют | **ослаблено** |
| Бюджет «~10 ходов отладки без прогресса» | `/clear` после **двух** неудачных исправлений (5.9) | верно по духу, порог мягкий |

**Что остаётся верным:**

- no-overengineering и no-out-of-scope (3.7);
- «не проси агента перепроверять себя» (3.1);
- effort во frontmatter по ролям (1.4, 4.2);
- `max` только после замеренного провала (4.3);
- не переключать `/model` посреди сессии (5.6);
- тихие команды, `/clear` и `/rewind` вместо `/compact` (5.8);
- остановка плана на утверждение;
- path-scoped rules;
- black-box место при наличии Client path (2.4).

## 6. Варианты

### A. Лёгкий VULYK: сначала закрыть утечки, затем облегчить цикл (Рекомендую)

Это единственный вариант, который бьёт по всем трём третям и по кругам сразу. Замер показывает, что
деньги уходят на обвязку: контроль 31%, фиксированный пакет 23%, лишние круги 29.5%. Anthropic
называет эту обвязку антипаттерном для задач внутри возможностей модели. При этом остаются дешёвые
вещи, которые реально окупаются: состояние на диске, остановка на утверждение, `trace-check`, журнал
совета.

**Шаг 1 — утечки** (баги и бесплатные выигрыши; сам по себе это вариант B):

1. Ограничитель на повторные диспатчи.
   - Тайм-аут `close-story` засчитывается как промах, а не как `ok`
     (`vulyk-cycle.js:110-122, 238-239`).
   - Ревью без `VERDICT:` — максимум один переспрос.
   - Пустое место совета продолжается через `SendMessage`/resume с «только переформатируй», а не
     диспатчится заново (с v2.1.246 `maxTurns` возвращает partial, его можно продолжить).
   - У каждого агента свой дедлайн по времени; сейчас бывают зависания на 10 ч и Bash на 597 мин.
2. Пакет инструкций.
   - Сократить `CLAUDE.md`/`CLAUDE.vulyk.md` до Laws + Secrets + Profile + Commands (~6 KB).
   - Маршрутизацию, лестницу, цикл и token economy перенести в `/vulyk-*` команды: они грузятся
     только в Queen.
   - Поставить `omitClaudeMd: true` клеркам, местам совета, скаутам и workers, а пять Laws вписать в
     тела агентов.
   - Убрать крик (MUST/NEVER/CRITICAL).
3. Предполётные проверки, которые сейчас останавливают 56% прогонов.
   - Чистота дерева — в `claim`, а не после трёхчасовой сборки.
   - `close-story` на уже закрытой story — идемпотентный успех.
   - Строка `## Verification`, которой нет в `## Commands`, ловится в `wave-check` на плане.
   - `reopen` → `repair`.
4. Устаревание. Релизные файлы — в белый список; ручной фикс после GREEN переоценивается по диффу от
   GREEN-головы, а не новым полным раундом.
5. Тесты. Проверка — один раз на story (worker отчитывается командой и exit-кодом, `close-story` не
   перезапускает сьют). Уже заказанное разделение fast/full. `subagentPromptCacheTtl: 1h` там, где
   ожидания >5 мин неизбежны.
6. Мёртвое: `effortLevel` из `settings.json`, хук `session-end-learnings.sh` (пустые заглушки),
   `status: in-progress`, отсылка ревьюера к ADR-001 VULYK, которого нет в хостах
   (`vulyk-cycle.js:131`).

**Шаг 2 — облегчить цикл** (структура):

1. **Tier 0–2 — один агент.** Queen (или один worker на всю спеку) делает работу сама. В конце — один
   ревьюер Opus 5.5 со свежим контекстом на диффе, который отмечает только нарушение asks или
   корректности. Без Workflow, без суда, без клерков, без ship-дронов. Law 5 сузить до Tier 3+.
2. **Драйвер без клерка на каждую команду.** Добавить глагол `cycle.sh advance`, который проходит все
   механические переходы до следующей границы агента. Workers сами делают `close-story`, места совета
   сами делают `record-seat` (Bash у них есть). Tier 3 падает с ~19–30 клерков до ~4–6.
3. **Совет с Tier 3.** Место `council-opus` (единственное, у кого бывают реальные RED). Black-box место —
   только при заполненном Client path. `council-sonnet` убрать: за 101 раунд он был GREEN в 80, а его
   работа дублирует прогон тестов worker'ом.
4. **Сходимость.** GREEN = нет *заякоренного и воспроизведённого* BLOCK/RED. Со второго раунда ревьюер
   смотрит только дифф ремонта против прошлых находок. GREEN места переносится, если его asks не
   тронуты. Ревьюер по умолчанию — Opus 5.5; Fable — на Tier 4 или по спорному BLOCK.
5. **Ремонт** ≤2 заякоренных находок — условия тому же worker'у (resume), без Fable-планировщика и
   новых story-файлов.
6. **Параллельные workers — каждый в своём worktree**, иначе чужие правки валят чужой `close-story` и
   ломают `scope.jsonl` (34–41 «out of scope» на story).
7. **Queen не ждёт многочасовой прогон с тёплым контекстом на 300k.** После запуска драйвера — хендофф
   и свежая сессия от журнала. Это снимает 58 перезаписей кэша (25M).
8. **Сделать замер штатным.** Перенести `evidence/scripts/` в `scripts/` как `token-report.sh`, чтобы
   `/vulyk-status` и `/vulyk-evolve` показывали сырые и взвешенные токены на спеку, а не
   вводящий в заблуждение `totalTokens`.

Этого хватает, чтобы на 500+ строках выйти примерно на паритет с работой без VULYK: сейчас разрыв
2.2–2.3×.

Цена варианта: шаг 1 — Tier 2–3 по матрице (hooks, driver, `cycle.sh`, агенты, installer). Шаг 2 —
Tier 4: меняются контракт цикла (ADR-001/002) и Law 5, нужен `lead-architect`. Это две спеки подряд.
Второй шаг лучше мерить на реальной задаче в одном хосте до раскатки.

### B. Только шаг 1: утечки, архитектура та же

Оценка: −25…35%. Меньше риска и изменений, ADR-001/002 не трогаются. Но остаются структурные причины:
совет на Tier 1–2, единогласие, ревьюер-«искатель причин», мультиагент на однофайловых задачах. Их
Anthropic и называет главным источником 3–10× перерасхода. Разрыв с работой без VULYK останется ~1.5×.

### C. Отказаться от VULYK, работать чистым Claude Code + 2–3 скилла

Максимальная экономия: паритет по определению. Но теряются ценные дешёвые вещи: состояние на диске
для возобновления, остановка на утверждение, `trace-check` против выдуманной работы, журнал совета
(на нём построен этот аудит) и параллельные волны для настоящих многомодульных задач. Не рекомендую:
расходы сидят в конкретных механизмах, их можно вырезать, не выбрасывая остальное.

## 7. Кандидаты в stories для следующего `/vulyk-plan` (не story-файлы)

Шаг 1 (утечки):

1. Ограничители повторов в драйвере: тайм-аут `close-story` = промах; ревью без `VERDICT:` — один
   переспрос; пустое место — resume; дедлайн на агента (H1, H8, H12, forensics §5d).

   `## Commands` в `wave-check`; `reopen` → `repair` (H10, H11, forensics §7c).

4. Пакет инструкций: `CLAUDE.md` ≤ ~6 KB, остальное в команды; `omitClaudeMd` у агентов с Laws в теле;
   снять крик; то же в шаблоне installer'а (H3, external 1.2, 3.6, 5.1).
5. Один прогон проверки на story + fast/full split + `subagentPromptCacheTtl` (H5, external 1.9).
6. Уборка: `effortLevel`, хук learnings, `in-progress`/`tracer`, ADR-001 в промпте ревьюера, чистка
   чужих строк `council.jsonl` в хостах через `vulyk-update` (H16, H20, H23, forensics §5).

Шаг 2 (цикл):

   ADR-002).

    (H14, H21).
12. Worktree на каждого параллельного worker'а; `scope-check` по своим путям (H7).

## 8. Вне VULYK, но платится в каждом субагенте

- **Ваш глобальный `~/.claude/CLAUDE.md`** (8.6 KB, четыре блока «🔴 MANDATORY», в том числе
  обязательный fact-check) грузится в каждый клерк, worker и место совета во всех проектах. Там же
  `skill_router.py` добавляет подсказки на каждый промпт. Это правила для главной сессии. Вынести их в
  скилл или output style, либо положиться на `omitClaudeMd` у агентов VULYK.
- **Auto-memory `MEMORY.md` в mmorpg — 14.3k символов** — тоже едет в каждый субагент (проверено выше).
  Индекс памяти стоит держать коротким.

## 10. Ограничения

- Сравнение с проектами без VULYK слабое: две кодовые базы, 6–18 выборок на корзину, ±30%. Сравнить
  внутри одного проекта не удалось: транскрипты на диске начинаются 2026-08-31.
- После v0.17.0 прошло 2 дня. Реально на 0.17.0 работают только katan и сам VULYK; mmorpg и fibi-next —
  на 0.16.0. Тренда по новой версии пока нет.
- Экономия в §6 — арифметика на долях, а не замер. Проверять тем же `evidence/scripts/` после релиза
  шага 1 и шага 2.
- Вес кэшированного токена в лимите подписки не опубликован. «Взвешенная» мера — приближение по
  API-ценам, а output в ней недовзвешен.
