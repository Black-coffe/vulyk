# Command reference

All commands are project slash commands in `.claude/commands/` - plain markdown, easy to read and adapt.

## /vulyk-bootstrap `[--quick]`
Interview (3 batches; `--quick` infers from the repo and asks for one confirmation) -> `## Project profile` in CLAUDE.md + the `## Commands` table filled with this project's *quiet* verification commands + path rules -> top model shown as the plan resolved it (`scripts/top-model.sh --explain`) and pinned for the Queen's session (`--apply`) -> roster pruning -> initial map via parallel Sonnet scouts -> memory index -> wiki seed -> single init commit. Ends with a usage summary; never starts feature work.

## /vulyk-plan `<goal>`
Tier classification (announced) -> verbatim `brief.md` written through `redact.sh` (Tier 2+; Tier 1: the task phrase itself) -> map-first recon, `drone-scout` (parallel, up to 4) only for territory the map does not cover - this is where the grill's implementation-variant options come from -> **the grill** (`templates/grill.md`): one round in this session via `AskUserQuestion`, one question per turn, the recommended option always first and always labelled, a free-text `Other` on every question, silence or "as you recommend" always safe; closes with a fixed last question that reads back the candidate requirement lines and writes them as `brief.md`'s `## Asks`; `claude -p` or any session without `AskUserQuestion` runs the same round in no-question mode instead (every recommended option, `(assumed)`); Tier 1 skips the grill entirely. Plan synthesis (inline for Tier 2, `queen-planner` for 3-4, `lead-architect` consult for 4 - both dispatched with `model: <TOP_MODEL>` as the session brief resolved it; `templates/plan.md` with `## Contracts` between concurrent stories) -> `docs/specs/<slug>/` plan + stories with verbatim `## Requirements` quotes and `wave:`/`blocked_by:` concurrency lines -> `scripts/wave-check.sh` (deterministic: file collisions within a wave, blocker order, dangling ids) + `scripts/trace-check.sh` (deterministic: backward - every story quote found verbatim in brief.md or plan deltas, catches invented stories; forward - brief lines no story covers, advisory) + `drone-coverage` (sonnet, `maxTurns: 5`, receives brief + plan.md and *not* the stories: the planner cannot audit what the planner did not write) - its report is evidence for the council and `lead-review` to weigh later, never a second approval stop. Closes the intake with `bash scripts/cycle.sh briefed docs/specs/<slug> --commit` (Tier 1: `--mode mini-brief`; no-question mode: `--mode assumed`) and launches the driver straight through - no summary to approve. **Two-stop opt-out:** only when the grill's last question recorded that the owner asked for it, `/vulyk-plan` stops here instead for one word of plan approval, as v0.11 did, writing `**Approved:**` in place of `**Briefed:**`. Tier 0 short-circuits to direct execution.

## /vulyk-build `[slug]`
Launches the build -> council -> repair loop for the newest spec that is `**Briefed:**`/`**Approved:**` with no branch yet (or the one named). **Mode detection:** the `Workflow` tool present in this session's own tool list selects the Workflow driver; its absence selects the fallback loop in this same session - `/vulyk-status` and the SessionStart brief say which is active. Either way it first prints and journals one line telling the human the tree is not theirs right now (`the loop holds the working tree of vulyk/<slug>; to edit, run /vulyk-pause <slug>`). **Workflow driver:** calls the `vulyk-cycle` Workflow with `{spec, top_model, stamp}`; it drives build -> round -> judge -> repair through `cycle-clerk` and the worker/council/`lead-review`/`queen-planner` agents on its own to a terminal state (`green`, `escalated`, `paused`, `shipped`), and the Queen does nothing else while it runs - on return it reads `journal.md`'s tail and the newest round's seat files rather than the transcript. **Fallback driver:** the same loop, stepped by this session's own `Bash` and `Agent` calls: `bash scripts/cycle.sh status docs/specs/<slug> --json` names the one next action (`branch`, `build:<wave>`, `open-round`, `dispatch:<seats>`, `judge`, `repair`, or a terminal state) and nothing else is read to decide it. A wave dispatches every story to its named worker in one message (cap 4); a returning `STATUS: DONE` closes with `cycle.sh close-story` (repeating `## Verification` the story's own `repeat` count); a red verification or `NEEDS_CONTEXT`/`WALL` gets one fresh worker with the failure as a condition, then a second failure marks the story `blocked` and escalates the design question to `lead-architect`. `open-round` opens the court once every story is `done`/`blocked`; `dispatch:<seats>` runs `lead-review` (main tree) ∥ the named `council-*` seats (in the court) in one message and records each report through `record-seat`, re-asking once on `MALFORMED`; `judge` computes the verdict; `repair` dispatches `queen-planner` to cut fix stories from the RED asks. One line is printed after every action - the journal's new last line, nothing more. **Stop conditions:** `green` - the round count, the newest `**Council:**` line, and each seat's `UNASKED:` line as next-circle material; recommends `/vulyk-ship`. `escalated` - prints `## Needs a human` verbatim; the owner's three exits are `human-check.sh ACCEPTED`, `cycle.sh reopen "<decision>"`, or leaving the spec open. `paused` - `/vulyk-resume` restarts it.

## /vulyk-review `[slug]`
One council round on demand, outside the driver loop - for the spec whose branch is checked out unless named. Preconditions live in `cycle.sh open-round --commit` itself (refuses on open stories, a dirty tree, no `## Asks`, or a pause; idempotent, so running this mid-round just resumes it; the ceiling reached exits like an escalation). Reads `round`, `court` and `round_dir` off `status --json` - a seat's entire input - then dispatches, **one message, in parallel**: `lead-review` at `model: <TOP_MODEL>` in the main tree (it needs the stories, so it never enters the court) alongside `council-haiku`, `council-sonnet` and `council-opus`, each working inside `court` with nothing else attached - the black-box client-path walk, the suite-then-each-ask run, and the intent/edge-case read, one seat per angle. Tier 4 adds a second reviewer on the paired model, its `PASS`/`BLOCK` folded into `lead-review`'s as the stricter of the two before anything is recorded. Each report is recorded with `bash scripts/cycle.sh record-seat docs/specs/<slug> <N> <seat> <<'EOF' ... EOF`; `MALFORMED` gets one re-ask naming the gap, then is recorded either way (a seat still malformed on attempt 2 is `ABSENT`). `bash scripts/cycle.sh judge docs/specs/<slug> --commit` then computes the verdict from the labelled, evidenced reports - `green` recommends `/vulyk-ship`; `repair` means fix stories go through `/vulyk-build`, never hand-patched here (Law 5); `escalated` prints `## Needs a human` verbatim, and the owner chooses among its exits. There is no stop inside this command beyond the round itself - the council's verdict is what it exists to produce.

## /vulyk-pause `<slug> ["why"]`
Creates the `PAUSE` semaphore (`bash scripts/cycle.sh pause docs/specs/<slug> "<why>"`) and hands the working tree of `vulyk/<slug>` back to the human. A Workflow driver already running stops at its next `cycle-clerk` call - an agent already in flight finishes, but under PAUSE the tree is the human's and a report against it is a report against a moving target, so it is discarded rather than recorded, and the seat is re-dispatched on resume; the fallback driver's next `status --json` read sees the semaphore and every mutating `cycle.sh` verb exits 3 rather than acting. Nothing in the hive touches the tree again until `/vulyk-resume`.

## /vulyk-resume `<slug>`
Clears the `PAUSE` semaphore (`bash scripts/cycle.sh resume docs/specs/<slug>`) and relaunches the driver - the exact same mode detection and launch `/vulyk-build` performs, **never** `resumeFromRunId`: a cached `status` replayed after a human touched the tree is the wrong answer, so a fresh launch costs one `cycle-clerk` call per already-closed step and never re-dispatches a seat or worker whose file already exists. If the tree moved while paused, the resume's JSON carries `stale: true` - the open round (if any) goes stale by the same rule a hand-edit stales a check, and the next `open-round` opens a fresh one; the ceiling still counts it.

## /vulyk-ship `[slug]`
Stage 06 of [the cycle](cycle.md). Runs `scripts/ship-check.sh docs/specs/<slug>` first - deterministic, free: it reads the newest `memory/stats/council.jsonl` row for stages 04+05 together (falling back to the pre-council acceptance/human ledgers only for a spec with no council row at all), plus brief, `**Briefed:**`/`**Approved:**`, `**Branch:**`, every story closed - and refuses on `NOT READY` the way `/vulyk-build` refuses without a briefed plan. The refusals worth expecting are a council `RED`/`ESCALATE` verdict (repair or `## Needs a human` is not resolved) or a `STALE` one (a repair round or a hand-edit moved the pack after judging); both are cured by going back, never by shipping around them. A `**Checked:**` line remains the owner's override in either direction, newer than the council row, and can also override a plain `NOT READY` outright - said out loud and quoted into the `--record` note. Then: one release-paperwork commit on the spec branch (version + CHANGELOG, in the project's convention - skipped when a story already wrote both at this exact version; story commits are never squashed, they are the rollback points and the review units), a **local merge** into the default branch (reversible, yours to run), and under a `to publish, run:` heading the publish step printed exactly as the *Release / deploy* Profile row names it - that is the end of the step, nothing here waits for it or polls for whether it happened; `/vulyk-status`'s `merged locally, not pushed: <n>` is how anyone finds out later. `ship-check.sh --record <spec> <version> "<where>"` then writes the `**Shipped:**` line and `memory/stats/ship.jsonl`. Closes by dispatching `drone-docs` (map + wiki) and `librarian` (ADR harvest from `## Plan deltas`) in one message, and handing over the circle's leftovers verbatim - every `UNASKED:` line, every `minor` finding, `## Descoped`, and a live `## Needs a human` - as the draft of the next brief.

## /vulyk-map `[path|.]`
Scout batches (delta-verify against existing map files to preserve gotchas), `last-verified` stamps, index update, report of unmapped territory and surprises.

## /vulyk-evolve `[--dry-run]`
The weekly cycle - see [self-evolution.md](self-evolution.md). `--dry-run` stops after diagnosis.

## /vulyk-gc
Librarian pass: consolidate learnings (cap 40), flag stale maps, prune snapshots >14 days, verify pointer index. Main session then offers concrete follow-ups.

## /vulyk-handoff
Two-phase session checkpoint before `/clear` or a restart. Phase 1 (deterministic): `handoff.py dump` writes a mechanical skeleton to `.claude/handoff/` — git state, last TodoWrite, touched files, recent prompts, measured context size. Phase 2 (model): rewrites the skeleton's `## Summary` from what actually happened — goal, current state, next step, decisions *with reasons*, dead ends, needed resources — and flips `enriched: true`. The next session in the project restores the handoff automatically via the SessionStart hook. Unenriched dumps also happen automatically on `/clear`/exit/compaction; see [hooks-reference.md](hooks-reference.md).

## /vulyk-update
Upgrade the installed framework, with the owner holding the decision throughout. Reports the installed version against the newest published tag, runs `scripts/vulyk-update.sh . --check` so the change has a visible shape before anyone approves it, summarises the CHANGELOG between the two versions, and only then asks. On yes it delegates to that release's own `install.sh --upgrade` — so an upgrade can never mean more than the release documented: framework-owned trees (agents, commands, hooks, `_meta` skills, bootstrap, templates, scripts) are replaced where they changed, and `CLAUDE.md`, `memory/`, `docs/specs|adr|wiki` and `.claude/rules` are never touched. Constitution changes therefore remain a manual merge, and the command names them explicitly rather than performing them. Pin a version with `/vulyk-update 0.7.0`. The counterpart hook that notices a release in the first place is `vulyk-update-check.sh`.

## /vulyk-status
Reads only metadata. `driver:` first - `workflow` when the `Workflow` tool is in this session's own tool list, else `fallback (CLI <version>)` with a note that the fallback runs the whole loop inside this pinned top-model session, the most expensive path in the token economy - then `merged locally, not pushed: <n>` against the default branch. `council:` next, one `awk` pass over `memory/stats/council.jsonl`: `<specs>` specs judged, the `<median>` round of each spec's first `GREEN`, `<escalations>`, and `<escaped defects>` (a `**Escaped from:**` brief whose origin spec already went GREEN). Then `scripts/state.sh`, which writes `.claude/state.json` - a **derived** view of every spec's story frontmatter: counts per status, per-story rows, a `stage` column (which of the six cycle confirmations the spec has reached - a spec with a council round shows `04-council:<verdict>` here, and any spec with a `PAUSE` file shows `paused` regardless of how far it got), and a `stale` flag set when a story file is newer than the snapshot. It is gitignored on purpose. A derived artifact committed beside its source becomes a second account of the same fact, and the two diverge the first time someone edits one; regenerating costs nothing, so there is never a reason to trust an old copy. If a number disagrees with a story file, the story file wins. Statuses outside `todo|in-progress|done|blocked` are counted as `unrecognised` and reported as such - never folded into `todo`, because a spec written before the convention is not a spec with nothing done.
Cheap metadata-only dashboard: story table, map freshness vs git churn, learnings buffer depth, skill counters, budget posture (`scripts/top-model.sh --explain`: resolved top model, the plan behind it, whether the session is pinned). On a fresh session it also nudges the context-hygiene pass — `/context` to see what the session starts with, `/mcp` to drop servers this project never calls. Ends with the single most useful next action.
