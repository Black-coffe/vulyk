# Command reference

All commands are project slash commands in `.claude/commands/` - plain markdown, easy to read and adapt. Changed in 0.18.0 (ADR-013): below Tier 3 the Queen builds herself, and every loop steps through `cycle.sh advance`.

## /vulyk-bootstrap `[--quick]`
Interview (3 batches; `--quick` infers from the repo and asks for one confirmation) -> the constitution tailored (`CLAUDE.vulyk.md` if it exists, else `CLAUDE.md`): the Profile rows between the `VULYK:PROFILE` markers, verified rather than copied from a README (a filled *Client path* adds the black-box seat at Tier 3-4); the `## Commands` table replaced with this project's *quiet* verification commands, the full suite in its own row -> path rules into `.claude/rules/` -> the gate model shown as the plan resolved it (`scripts/top-model.sh --explain`) and the Queen's session pinned to `opus` (`--apply`) -> roster pruning -> initial map via `drone-scout`, up to four in parallel -> memory index -> wiki seed -> single init commit. Ends with a summary; never starts feature work.

## /vulyk-plan `<goal> [--go] [--study]`
Deliverable first (ADR-008): a request whose answer is a document - validate, audit, monitor, research, "make me a spec" - or `--study` writes `brief.md` and `report.md` and stops; no story, no worker, no council. Otherwise: tier classification (announced; Tier 0 is done at once, no paperwork) -> verbatim `brief.md` written through `redact.sh` -> recon from `memory/` and the map first; `drone-scout` only for broad or unmapped territory (Tier 1 none, one if the location is unknown; Tier 2 at most one; Tier 3 two; Tier 4 four) -> **the grill** at Tier 2-4 (`templates/grill.md`: one round, recommended option first, closing into `brief.md`'s `## Asks`); Tier 1's `## Asks` is the task phrase. Plan: Tier 1-2 written by the Queen from `templates/plan.md`; Tier 3-4 by `queen-planner`, with a `lead-architect` consult at Tier 4 - both Tier 4 dispatches carry `model: <top_model>`, Tier 3 passes none. Stories from `templates/story.md`, each `model: opus`, cut by review unit at Tier 1-2 (one story at Tier 1, one to three at Tier 2) and by parallel worker at Tier 3-4 -> `scripts/wave-check.sh` (file collisions within a wave, blocker order, dangling ids, `## Verification` segments that are not `## Commands` cells) + `scripts/trace-check.sh` (every story quote found verbatim in the brief, its `## Asks` or plan deltas; brief lines no story carries) -> `drone-coverage` at Tier 3-4 (brief + plan only, never the stories). **Tier 1 runs straight through** (`cycle.sh briefed --mode mini-brief`, then `/vulyk-build`). **Tier 2-4 stop for approval**: the plan is shown with what the build will spend, and one word writes `**Approved:**` (ADR-008). `--go`, or the owner asking for it on the grill's last question, closes the intake with `cycle.sh briefed` instead. After approval a Tier 2 build starts in a fresh session (`/clear`, then `/vulyk-build <slug>`); Tier 3-4 launch at once.

## /vulyk-build `[slug]`
Builds the newest spec that is `**Briefed:**`/`**Approved:**` with no branch yet (or the one named) to a council verdict. plan.md's `**Tier:**` picks the path. Every call reads the last JSON line of `cycle.sh`: `ok`, `next`, `status` - never prose.

**Solo, Tier 1-2** - no driver, no clerk, no court. `bash scripts/cycle.sh advance docs/specs/<slug>` runs every mechanical step (branch, open-round, judge, the repair story) up to the next thing only an agent can do. On `build:<W>` the Queen implements each of `status.wave_stories` herself (its `## Files` only), sets `returned: DONE` and runs `cycle.sh close-story <file> --commit`, which runs the story's verification once and commits; on exit 4 she fixes and reruns, and after three failed reruns writes `## Findings` and stops for the owner. On `dispatch:review` she dispatches one `lead-review` (no model parameter) with the report path `.vulyk/reports/<slug>/round-<n>/review.attempt-<k>.md` - from round 2 also `since` and the previous round's directory - then runs `advance --ingest`; a rejected report is re-dispatched once with its error.

**Hive, Tier 3-4** - resolves `top_model` (`scripts/top-model.sh`), `second_model` (the Tier 4 pairing) and a random 16-hex `stamp`, journals the "tree is not yours" line (`the loop holds the working tree of vulyk/<slug>; to edit, run /vulyk-pause <slug>`), and calls the Workflow tool with `scriptPath: ".claude/workflows/vulyk-cycle.js"` and `{spec, stamp, top_model, second_model}`. The driver claims the spec itself (`advance --claim`), dispatches each wave's workers in parallel (each closes its own story with `close-story --commit --stamp`), then `advance`; dispatches the seats `next` names, then `advance --ingest`; and releases in `finally`. A story still todo after its wave is retried once on the gate model; a second miss stops the run and names the file, and the Queen blocks the story and consults `lead-architect`. A seat still missing after `--ingest` is re-dispatched once with its rejection; a third dispatch in one round stops the run. On return the Queen reads the returned object, the journal tail and the newest round's files - never the transcript; spend comes from `python scripts/token-report.py . --spec <slug>`, not the run's printed `totalTokens`. A Workflow call that throws records `telemetry.sh record driver_refused`. Without the Workflow tool the Queen runs the same `advance` loop with the stamp and dispatches workers and seats with the Agent tool.

**Terminal:** `green` - the round count and the newest `**Council:**` line; recommends `/vulyk-ship`. `escalated` - prints `## Needs a human` verbatim; the owner chooses `human-check.sh ACCEPTED`, `cycle.sh reopen "<decision>"` (it resumes with a repair story) or leaving the spec open. `paused` - `/vulyk-resume` restarts it. Any `ok:false` - the failing verb and its error are journaled, and the loop stops for a human.

## /vulyk-review `[slug]`
One council round on demand, for the spec whose branch is checked out unless named. Claims with a fresh stamp and runs `cycle.sh advance --stamp <s> --claim`, which opens the round when one is due (its preconditions - every story closed, a clean tree, `## Asks` present, no pause - live in `open-round` itself). On `dispatch:<seats>` it dispatches exactly those seats in one message, as `/vulyk-build` does: `lead-review` in the main tree with no model parameter at Tier 1-3 and two reviewers (`review-top`, `review-second`) at Tier 4; at Tier 3-4 `council-opus`, and `council-haiku` when the Client path is filled, inside the court with slug, round, `court` and the report path only. Then `advance --ingest` records the reports and judges; a rejected seat is re-dispatched once. Always releases. `green` recommends `/vulyk-ship`; `build:<W>` means the round was RED and `cycle.sh repair` has written the repair story, which goes through `/vulyk-build`, never hand-patched here; `escalated` prints `## Needs a human` verbatim. There is no stop for the owner inside this command.

## /vulyk-pause `<slug> ["why"]`
Creates the `PAUSE` semaphore (`bash scripts/cycle.sh pause docs/specs/<slug> "<why>"`) and hands the working tree of `vulyk/<slug>` back to the owner. Every mutating `cycle.sh` verb checks `PAUSE` first and exits 3 without acting, so the Workflow driver stops at its next `advance` (the agent in flight finishes first), a solo loop stops at its next `cycle.sh` call, a worker's edits stay on disk with only its `close-story` waiting, and a seat report in flight is not recorded - the seat is dispatched again after `/vulyk-resume`. Nothing in the hive touches the tree again until then.

## /vulyk-resume `<slug>`
Clears the `PAUSE` semaphore (`bash scripts/cycle.sh resume docs/specs/<slug>`) and relaunches with `/vulyk-build <slug>` - a fresh run, solo at Tier 1-2, hive at Tier 3-4 (recording `telemetry.sh record driver_relaunched` first), **never** `resumeFromRunId`: a cached status replayed after the owner touched the tree is the wrong answer. `advance` re-derives everything from disk, so a story already done or a seat already recorded is never dispatched again. If the tree moved while paused, the resume's JSON carries `stale: true`; the next round re-reviews the new diff, and the tier's ceiling still counts it.

## /vulyk-ship `[slug]`
Stage 06 of [the cycle](cycle.md). Runs `scripts/ship-check.sh docs/specs/<slug>` first - deterministic, free: it reads the newest `memory/stats/council.jsonl` row (falling back to the pre-council acceptance/human ledgers only for a spec with no council row), plus brief, `**Briefed:**`/`**Approved:**`, `**Branch:**`, every story closed - and refuses on `NOT READY`. The refusals worth expecting are a council `RED`/`ESCALATE` verdict and a `STALE` one (a repair round or a hand edit moved the code after judging; a hand fix reopens a round that re-reviews only the new diff); both are cured by going back. A newer `**Checked:**` line is the owner's override in either direction, and the owner may also override a plain `NOT READY` out loud. Then: one release-paperwork commit on the spec branch (version + CHANGELOG; `VERSION` and `CHANGELOG.md` are paperwork, so it does not stale a GREEN round; story commits are never squashed), a **local merge** into the default branch, and under a `to publish, run:` heading the publish step printed exactly as the *Release / deploy* Profile row names it - never run, never polled. `ship-check.sh --record <spec> <version> "<where>"` writes the `**Shipped:**` line and `memory/stats/ship.jsonl`. Closes by dispatching only what has work to do - `drone-docs` when the merge touches a mapped module, `librarian` when `## Plan deltas` or `## Descoped` has entries - and hands over the next brief's draft verbatim: every `UNASKED:` line, the review's minors, every `[unanchored]` finding, `## Descoped`, and a live `## Needs a human`.

## /vulyk-map `[path|.]`
Scout batches (delta-verify against existing map files to preserve gotchas), `last-verified` stamps, index update, report of unmapped territory and surprises.

## /vulyk-evolve `[--dry-run]`
The weekly cycle - see [self-evolution.md](self-evolution.md): learnings, skill counters and the week's spend from `scripts/token-report.py`, the council and anomaly check-in, a diagnosis, and a changeset on `vulyk/evolve-<date>` for a human to review. `--dry-run` stops after diagnosis.

## /vulyk-gc
Librarian pass: consolidate learnings (cap 40), flag stale maps, prune snapshots >14 days, verify pointer index. Main session then offers concrete follow-ups.

## /vulyk-handoff
Two-phase session checkpoint before `/clear` or a restart. Phase 1 (deterministic): `handoff.py dump` writes a mechanical skeleton to `.claude/handoff/` — git state, last TodoWrite, touched files, recent prompts, measured context size. Phase 2 (model): rewrites the skeleton's `## Summary` from what actually happened — goal, current state, next step, decisions *with reasons*, dead ends, needed resources — and flips `enriched: true`. The session that starts after `/clear` or a compaction restores it through the SessionStart hook (capped at 4 000 characters). Unenriched dumps also happen automatically on `/clear`/exit/compaction; see [hooks-reference.md](hooks-reference.md).

## /vulyk-update `[version]`
Upgrade the installed framework, with the owner holding the decision throughout. Reports the installed version against the newest published tag, runs `scripts/vulyk-update.sh . --check` so the change has a visible shape before anyone approves it (what would be replaced, what would be removed as retired, what is skipped as the owner's), summarises the CHANGELOG between the two versions, and only then asks. On yes it delegates to that release's own `install.sh --upgrade`: framework-owned trees are replaced where they changed, retired framework files are removed unless the owner edited them, and `memory/`, `docs/specs|adr|wiki` and `.claude/rules` are never touched. The constitution is never overwritten on a plain upgrade; the command prints the size difference and offers `scripts/vulyk-update.sh . --constitution replace` as a separate choice, which writes the new constitution with the hive's `VULYK:PROFILE` and `VULYK:COMMANDS` blocks and telemetry row carried over and keeps the old file as `<name>.pre-0.18.md`. Pin a version with `/vulyk-update 0.17.0`. The counterpart hook that notices a release in the first place is `vulyk-update-check.sh`.

## /vulyk-status
Reads only metadata. `driver:` first - `workflow` when the `Workflow` tool is in this session's own tool list, else `agent loop` (Tier 3-4 run their agents from the Queen's session; Tier 1-2 build solo either way) - then `merged locally, not pushed: <n>` against the default branch. `council:` next, one `awk` pass over `memory/stats/council.jsonl`: specs judged, the median round of each spec's first `GREEN`, escalations, and escaped defects (a `**Escaped from:**` brief whose origin spec already went GREEN). Then the last 14 days of spend per spec from `python scripts/token-report.py`: raw and weighted tokens, dispatches, rounds. Then `scripts/state.sh`, which writes `.claude/state.json` - a **derived**, gitignored view of every spec's story frontmatter with a `stage` column (a spec with a council round shows `04-council:<verdict>`, a `PAUSE` file shows `paused`); if a number disagrees with a story file, the story file wins, and statuses outside `todo|done|blocked` (older specs may still carry `in-progress`) are reported as `unrecognised`. Then map freshness against git churn, the learnings buffer, skill counters, and budget posture (`scripts/top-model.sh --explain`: the gate model, the plan behind it, the Tier 4 pairing, whether the session is pinned to `opus`). On a fresh session it also suggests `/context` and `/mcp`. Ends with the single most useful next action.
