# Hooks reference

Wired in `.claude/settings.json`; scripts in `.claude/hooks/`. Every entry has one form, with the project dir quoted so a path with a space still runs: `"command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/<name>.sh [arg]"`, and a SessionEnd entry carries `"timeout": 30`. `install.sh` writes that form into an existing `settings.json` too, one line per hook (`wire <event> <name>` or `kept <event> <name>`), and `--upgrade` rewrites an old unquoted entry in place (`rewire <name>`). Every script fails open (`exit 0` on any missing dependency) - VULYK never blocks your session because `jq` is absent - except the three PreToolUse guards (`git-guard.sh`, `owner-guard.sh`, `court-guard.sh`): they are wired with `"onFailure": "block"` and fail closed, as their rows below say.

| `git-guard.sh` | PreToolUse, matcher `Bash\|PowerShell`, `"onFailure": "block"` | Denies the git verbs that throw away uncommitted work or commits: `stash` (push, `-u`, `drop`, `clear`), `checkout .` / `-f` / `[<ref>] -- <path>` / `-B`, `restore` (worktree), `reset --hard` / `--merge`, `merge --abort`, `clean -f`, `switch -f` / `--discard-changes` / `-C` / `--force-create`, `branch -D` / `-f` / `-M` / `-C` / `-d --force`, `worktree remove --force`, `rm -f` / `--force`, `checkout-index -f`, `read-tree -u` with `--reset` or `-m`, `update-ref`; read-only and unforced forms pass. The same verbs are read where a shell is handed them (`bash -c`, `pwsh -Command`, a heredoc fed to a shell) and in a `git -c alias.<name>=` definition on the command line. A line continuation is joined before reading; git is found after the shell keywords (`then`, `do`, `else`, `!`, ...), behind `eval` and behind the wrappers `env`, `timeout`, `nohup`, `nice`, `sudo` and `xargs` (by basename, `/usr/bin/env git`). Every caller, the main session too, is denied a forced tag and a forced push: no agent needs them, and the owner runs them in his own terminal. A subagent (input with `agent_id`) is read on every shell call and is denied every listed verb, any git call whose arguments cannot be read, a shell call on the cycle's run state (`.vulyk/state/`; the Read tool reads a record), a script or program whose name it cannot read, every git verb that stages, makes a commit or moves a branch or HEAD while a `docs/specs/*/DRIVER` exists in the repository the command acts on (git reads and `git update-index --chmod` pass), and every `cycle.sh` verb but `advance`, `status`, `release`, `suite`, `stamp-red` (never with `--baseline`) and `close-story`. The main session is denied a tree-file verb only when `git status --porcelain` shows those paths dirty or untracked; the reason names them (10, then `+N more`) and says: commit them, leave them, or run the command in your own terminal. A `git status` that times out denies: it cannot prove the tree is clean. Without Python, a bash fallback reads the same verb list and denies each listed verb after a `git` word, for any caller, in Bash and PowerShell; other git passes. A Python that starts and ends with a status other than 0 on a command naming git denies (1 included, outside `--check`; an error inside the Python half exits 3), saying the guard failed and that the owner can run the command. Passes silently on bad JSON and a command naming neither git nor `cycle.sh`. The forms left open on purpose are named in the script's header. No env switch for agents: the owner unwires it by removing its entry from `.claude/settings.json`, and an upgrade leaves it removed (`unwired PreToolUse: git-guard.sh` names it, with the `--wire` command that puts it back). `--check <file>` is card `work-discarded-by-git-verb`'s check. Law 5 (0.48.1): the main session is also denied `cycle.sh close-story <story>` when the story's plan.md says Tier 3 or 4 (its worker closes it; a returned story is re-dispatched); a subagent, Tier 1-2 and `stamp-red` pass; a story token holding `$`, a backtick or `%`, or whose plan.md cannot be read, is of unknown tier and denied. Python: `$VULYK_PY`, `python3`, `python`, `py`, as `lib.sh`; hook stdin is decoded as UTF-8 (a BOM tolerated). |

## Session handoff (`handoff.py`)

Claude Code hooks receive **no token counter** — but every hook gets `transcript_path`, and each assistant entry in that JSONL carries `message.usage`. The true context size is `input + cache_read + cache_creation + output` of the last **non-sidechain** assistant entry (sidechain = subagent; counting those skews the number). That measurement drives everything:

- **Escalating warnings** (Stop → banner to the user; UserPromptSubmit → context injected to the model) at **70% / 80% / 90% of the context window** by default (a 1M window: 700k / 800k / 900k), each offering `/vulyk-handoff`, never earlier. A session with no statusLine copy of its own takes the window Claude Code last reported on this machine for the same model (any copy claude-statusbar left in the last 30 days), so a 1M session is not measured against the stock 200k. Each level fires **once per session** — a noisy hook is worse than no hook.
- **Cache warmth.** From level 1 the warning also carries how long the prompt cache has left. The same transcript entry that yields the token count carries its `timestamp`, so the age of the last turn is free to compute — and it decides the *price* of acting on the warning: compacting or checkpointing re-reads the conversation, which is a cache hit inside the TTL and a full-price re-prefill after it. The banner therefore says "warm for ~55 more min", "expires in ~5 min", or "expired anyway — no reason to delay". Default TTL is 60 min (subscription plans); set `cache_ttl_minutes: 5` in the config if you run on an API key without `ENABLE_PROMPT_CACHING_1H=1`. Transcripts without a parseable timestamp simply drop the clause. See [token-economy.md](token-economy.md).
- **Auto-dump** of a mechanical handoff (`git` state, last task list (TodoWrite or TaskCreate/TaskUpdate), touched files, recent prompts, last reply) on SessionEnd (`/clear`, exit) and PreCompact. Sessions under 25k tokens are not worth dumping and are skipped (PreCompact always dumps). The dump passes through `scripts/redact.sh` before it is written — handoffs are gitignored but re-injected into future sessions and routinely shared.
- **`/vulyk-handoff`** writes the same skeleton on demand, then the model enriches its `## Summary` section — decisions, dead ends, next step. See the command reference.
- **Restore** on SessionStart: after `/clear` or compaction only, once per handoff and only while it is under 12 h old; after a compaction only the same session's handoff. Cut to 4 000 characters (`restore_max_chars`), keeping the last `## Summary` whole. A plain startup or a `fork` starts on its own topic, and a `resume` still carries its own context, so none of them restores (changed in 0.18.0: a plain startup used to restore any handoff younger than 12 h, whatever it was about).

**The window is detected, never assumed.** A percentage needs a denominator, and the hook payload does not carry one: `context_window_size` exists only in statusLine input, and the transcript records the model without its `[1m]` suffix. So `handoff.py` asks, strictest source first — a `context_limit` pin in the config; Claude Code's own `CLAUDE_CODE_AUTO_COMPACT_WINDOW` / `CLAUDE_CODE_DISABLE_1M_CONTEXT`; the statusLine JSON [claude-statusbar](https://pypi.org/project/claude-statusbar/) caches on disk (its per-session copy, then the global one, and only when this session rendered it — every Claude Code window overwrites that file); the window this session was already seen to have; and finally the measurement itself, since a session past 200k tokens proves the window is the large one. Failing all of that it assumes the stock 200k.

Where the statusbar could answer but this tick could not tell (another window rendered last), the hook **says nothing** instead of dividing by a guess: a wrong denominator is what makes a guard untrustworthy. Machines without the statusbar keep the plain 200k behaviour.

Storage is project-local and gitignored: documents in `.claude/handoff/`, pointer in `.claude/handoff/index.json`, per-session anti-spam state in `.claude/handoff/state/` (self-pruned after 7 days, and where the detected window is remembered). Override defaults (`thresholds_pct`, absolute `thresholds`, `context_limit` to pin the window, `cache_ttl_minutes`, `restore_max_chars`, `enabled`) in `.claude/handoff.config.json`.

Requires Python 3 on PATH (`python3`, `python` or `py`); the `handoff.sh` wrapper fails open without it, per the VULYK contract. Diagnose with `bash .claude/hooks/handoff.sh status`.

## Accepted costs

Three costs the private audit of 2026-11-08 measured are kept as they are, each for a reason its own verifier gave
(spec `mass-audit-fixes`, plan `## Assumptions`). The owner may send any of them back as a story.

- **The suite's step barrier (O2).** `cycle.sh suite` runs the full suite as fixed steps of at most `--jobs` parts,
  and a step waits for its slowest part. One measured round: 77 parts, about 4 570 part-seconds on 12 jobs, nine
  steps adding up to 773 s of wall time, against about 381 s for a perfect 12-slot packing (an ideal that ignores
  contention, so the real gap is smaller). Kept because each `--step K` is one capped call under the 600 s tool
  limit (ADR-029); a single global queue would break that. Only ordering parts within a step is compatible, and it
  changes no wall time.
- **The constitution every builder loads (O7).** `CLAUDE.md` is about 7.1 KB (cap 7 168 B), and five agents load it
  (`worker-code`, `worker-test`, `lead-review`, `queen-planner`, `lead-architect`). About 2.6 KB of it (Routing,
  Models and effort, Compact instructions, Where things live; about 650 tokens) is mostly the Queen's, and it is
  read from cache after an agent's first turn. Kept because ADR-013 D7 gives every builder the host's conventions,
  the Laws cite the tiers, and in a hive `CLAUDE.md` is the host's merged constitution: moving sections out is an
  architecture change, not a fix.
- **Two Python starts per turn in `handoff.sh` (O8).** `handoff.sh prompt` (UserPromptSubmit) and `handoff.sh stop`
  (Stop) each start Python even when they print nothing: measured 139-146 ms and 127-141 ms, about 280 ms per turn.
  Kept because both modes record the session's context window on every turn, below the warning threshold too; a
  bash gate in front of them would skip that record, and transcript bytes are not tokens.

Plus two **git** hook samples (not Claude Code hooks): `scripts/git-hooks/post-merge` touches `memory/map/.stale` after merges; `/vulyk-status` and the session brief surface it. `scripts/git-hooks/pre-push` refuses a push carrying a `-dev.N` tag or more than one version tag; `/vulyk-ship` step 2a copies it into place, and `--no-verify` turns it off. Install each per the comment in its file.

Customizing: hooks receive JSON on stdin (see Anthropic's hooks docs for the schema per event); keep scripts fast and fail-open (the three guards above are the exception: they fail closed), and prefer writing signals to `memory/` over doing heavy work inline.
