# Grill: автономный цикл VULYK — наблюдательный совет вместо человека

Дата: 2026-09-12 · Линза: product · Режим: hard · Статус: **синтез готов, реализация не начата**
Вопросов: 13 · Все ветки закрыты · Следующий шаг — проверить два платформенных допущения, затем `/vulyk-plan` на самом VULYK (v0.12.0)

## Вердикт

VULYK переходит от «человек — обязательный гейт» (v0.11.0, stage 05) к «человек — один раз, в начале».
Единственный стоп — мини-гриль внутри `/vulyk-plan`, после дешёвой разведки. Дальше цикл идёт сам: план →
ветка → стори-коммиты → `lead-review` ∥ **наблюдательный совет** (Haiku/Sonnet/Opus, три угла, слепые к
внутренностям хайва) → фикс-стори → повтор, потолок 3 раунда → мерж в default. Publish/deploy печатается,
но не нажимается. Человек может вмешаться на любом этапе; система зовёт его сама только в аварийном
случае — три красных раунда без единогласия. Королева — top-model по `auto` (на Max = Fable), с
обязательным пином сессии, и делает минимум: гриль, план, чтение итогового отчёта. Петля build → гейты →
совет → починка уезжает в Workflow-скрипт с fallback в сессию. Ход цикла пишется в журнал на диске;
терминал — витрина. Гипотеза «модели доросли» проверяется числом: сбежавшие дефекты в `council.jsonl`.

## Контекст (установлено до вопросов)

- v0.11.0 (`2a35d15`, 2026-09-05) ввёл 4 ручные остановки на спеку: stage 01 (подтверждение brief, Tier 3-4),
  stage 02 (approval плана — было и раньше), stage 05 (owner looks, `human-check.sh`), stage 06 (publish — human presses).
- Stage 05 «не сжимается по тирам» (`CLAUDE.md`, `docs/cycle.md`) и протухает при любом коммите кода после взгляда → цикл.
- Существующие гейты: `lead-review` (opus, видит всё), `drone-acceptance` (sonnet, слепой: brief + repo + run cmd),
  Tier 4 — второй ревьюер на другой модели. Принцип v0.8.0: «две копии одной модели слепы в одних и тех же местах».
- Политика top-model: `TOP_MODEL = auto` → fable на Max/premium, opus на Pro/API («граница — деньги, не способность»).
  `scripts/top-model.sh --apply` пинит сессию в `.claude/settings.local.json`; по умолчанию сессия не запинена.
- Репозиторий публичный, есть CI, CITATION.cff, внешний контрибьютор (PR #1). Хуки (`handoff.py`, `context-guard.sh`)
  человека не спрашивают — только баннеры.

## Видение владельца (2026-09-12, суть verbatim)

Человек участвует максимально один раз — мини-гриль сразу после постановки задачи в `/vulyk-plan`. Дальше система
автономна: сама пишет план, тесты, критерии приёмки. Перед коммитом — «наблюдательный совет»: агенты последних
моделей с чистым контекстом получают ТЗ и результат, независимо дают развёрнутый фидбэк, могут гонять
браузер/MCP/скрипты. Оркестратор оценивает ответы; много проблем → чинить → тесты → совет, до зелёного. Затем коммит.
Человек может включиться на любом этапе по желанию. В терминале — понятные периодические логи о смене состояния.
Королева — всегда Fable последней версии, делает минимум; всё остальное — сабагенты Opus/Sonnet/Haiku.
Уточнение владельца в ходе гриля: «после третьего раунда, если нет единогласного решения или процент проблем
критический (красная зона) — стоп и на человека, чтобы он принял решение».

### Производные решения (следствия, не отдельные вопросы)

- Таблица цикла: stage 05 → **Council** (обязательный, агентный); *Human* — необязательный override на любой стадии.
  `human-check.sh` остаётся: если человек записал ACCEPTED/REJECTED — это перевешивает совет.
- `**Checked:**` → `**Council:**` — пишет `scripts/council-log.sh` (по образцу `acceptance-log.sh`), пришпилено к коммиту и
  отпечатку пака; `ship-check.sh` читает эту строку вместо `**Checked:**`. Правило устаревания сохраняется:
  коммит кода после вердикта → `STALE` → совет заново (это и есть «повтор раунда»).
- Stage 01 «подтверждение brief» на Tier 3-4 сливается с грилем (показ brief — часть первого вопроса).
- `drone-acceptance.md` → переписать в три агента совета; `drone-coverage` остаётся на этапе плана
  (его вывод питает вопрос гриля про «требование vs контекст»).
- Раскатка: чинить в исходнике `E:/Projects/vulyk` (v0.12.0), затем `install.sh --upgrade` / `/vulyk-update` по хайвам.

## Anti-scope

- Не трогаем: token economy, memory protocol, `/vulyk-evolve`, `/vulyk-gc`, хуки хендоффа.
- Не делаем: авто-publish; MCP-браузер всем местам; совет на Tier 0; второй Haiku; зависимость от личных скиллов/статусбара.
- Не меняем: политику `auto`, алиасы моделей, «одна сторя — один коммит».

## Act 2 — адверсариальное ревью и поправки (2026-09-12, вечер)

Свежий ревьюер (Opus, видел только этот бриф) — полный текст: `2026-09-12-autonomous-cycle-council-adversarial.md`.
Владелец выбрал путь: **совет остаётся, переформулирован, все технические находки приняты.**

### Данные, поднятые по требованию ревьюера («нулевой шаг»)

`memory/stats/human.jsonl` в хайвах AI, Recall, fibi-next — 10 записей за 2026-09-06…09-12:
**0 REJECTED**; 3 записи — перезаписи после коммитов «только бумаги» (STALE-цикл); 2 — штампы с одинаковым
текстом в одну секунду на две спеки; единственная содержательная находка человека (fibi-next, экран приёмки)
была вне скоупа и мерж не остановила. `acceptance.jsonl` (42 записи, 5 хайвов): **5 REJECTED, все по делу** —
интерактив умирает после первого поиска (AI); требование brief не выполнено ни в каком виде (kiln, ×2 хайва);
центральная просьба не исполняется, `BANK_TARGETS` пуст — дважды, включая ремонтный раунд (fibi-next).
**Вывод:** блокирующий человеческий гейт за неделю не остановил ничего; слепой гейт по brief ловит реальный
дрейф от намерения. Случай `BANK_TARGETS` — класс «без человека не сходится», ради которого нужен потолок.

### Поправки к решениям

| Реш. | Было | Стало (поправка) | Источник |
|---|---|---|---|

- **Дедлайн на `human-check.sh` вместо совета (3.1)** — отклонено как решение цели: дедлайн снимает вечное
